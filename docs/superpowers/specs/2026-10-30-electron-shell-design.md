# หน้าต่างร้านแบบ Electron (Electron shell)

เจ้าของร้านต้องการให้ผู้ใช้ทั่วไป "ติดตั้งครั้งเดียวแล้วใช้ได้เลย" และสั่งให้ทำเป็น Electron ตอนนี้ไอคอน "เปิดหน้าร้าน" เปิด Chrome หรือ Edge แบบ `--kiosk` ไปที่ `http://localhost:<พอร์ต>` ของ service ที่ตัวติดตั้งวางไว้ ผู้ใช้จึงเห็นเบราว์เซอร์ที่ลูกค้าหรือพนักงานปิด ย่อ หรือเปิดแท็บอื่นได้ และพิมพ์ใบเสร็จต้องผ่านหน้าต่างเลือกเครื่องพิมพ์ของเบราว์เซอร์

ข้อสมมติที่เป็นของผม (ให้ตรวจตอนอ่าน): Electron เป็น **เปลือกหน้าต่าง** ที่เปิดหน้าขายเดิม ไม่ได้ย้าย API หรือฐานข้อมูลเข้าไปในแอป เพราะ API ต้องทำงานตอนไม่มีใครล็อกอินและต้องให้ iPad หรือเครื่องที่สองในร้านเข้าถึงได้ (AGENTS.md: API มี instance เดียว, Windows service)

## เป้าหมาย

- ติดตั้งผ่านไฟล์เดียวเหมือนเดิม และได้ไอคอน "เปิดหน้าร้าน" ที่เปิดเป็นหน้าต่างของแอปเอง ไม่ใช่เบราว์เซอร์
- โหมดเต็มจอ (kiosk) ที่ปิดโดยไม่ตั้งใจยาก: ไม่มีแถบที่อยู่ ไม่มีแท็บ ไม่เปิดเว็บภายนอกในหน้าต่างนี้ ปิดแอปได้เฉพาะจากเมนูที่เจ้าของเข้าถึง
- พิมพ์ใบเสร็จแบบเงียบ (ไม่ขึ้นหน้าต่างเลือกเครื่องพิมพ์) ไปที่เครื่องพิมพ์ที่เลือกไว้
- ถ้า service ยังไม่พร้อม (เพิ่งเปิดเครื่อง) แอปแสดงหน้ารอที่อ่านง่ายแล้วเข้าหน้าขายเมื่อพร้อม ไม่ใช่หน้าผิดพลาดของเบราว์เซอร์
- ตัวติดตั้งเดิม ฐานข้อมูล การสำรองข้อมูล และวิธีอัปเดต (`apply-update.ps1`) ใช้ต่อได้ ไม่ต้องย้ายข้อมูลลูกค้า
- ทำงานคู่กับเบราว์เซอร์ได้: iPad และเครื่องอื่นในร้านยังเปิดผ่านเบราว์เซอร์ได้เหมือนเดิม

## ไม่ทำ

- ไม่ย้าย API (Bun) หรือ PostgreSQL เข้าไปในกระบวนการของ Electron
- ไม่ทำเวอร์ชัน macOS หรือ Linux ในงานนี้ (เป้าหมายคือ Windows x64 ตามตัวติดตั้งปัจจุบัน)
- ไม่ทำตัวอัปเดตของ Electron ในงานนี้ (electron-updater): การอัปเดตยังเป็นเส้นทางเดิมของตัวติดตั้ง จะแยกเป็นงานต่อไป "อัปเดตกดปุ่มเดียว"
- ไม่ซื้อ/ตั้งค่าใบรับรองลายเซ็นดิจิทัลในงานนี้ แต่ต้องออกแบบ build ให้เซ็นได้ภายหลังโดยไม่ต้องแก้โค้ด

## ห้ามเด็ดขาด

- หน้าต่างแอปโหลดได้เฉพาะ origin ของร้านเอง (`http://localhost:<พอร์ต>` หรือที่ตั้งไว้) ลิงก์ภายนอกเปิดในเบราว์เซอร์ระบบ ไม่ใช่ในหน้าต่างที่มีสิทธิ์ของแอป
- renderer ไม่มี Node: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, ไม่เปิด `webSecurity` ปิด; ช่องทางเดียวที่หน้าเว็บคุยกับแอปคือ preload ที่เปิด API เล็กๆ ตรวจ origin ทุกครั้ง (เช่น `printReceipt`, `openCashDrawer` ถ้ามี)
- ห้ามใส่รหัส ความลับ หรือรหัสตั้งค่าร้านในแอป ไฟล์ตั้งค่า หรือ argv ของคำสั่งเปิดแอป ไม่แตะกฎของรหัสตั้งค่าใน AGENTS.md
- ห้ามแก้พฤติกรรมของ API หรือสัญญา OpenAPI

## ข้อกำหนด

- Electron เวอร์ชันที่รองรับอยู่ ณ ตอนทำ (ตรึงเวอร์ชันเต็ม) บนเครื่อง Windows 10/11 x64
- แอปอยู่ในโฟลเดอร์ `apps/desktop/` ที่รากของ repo: โค้ด main/preload เป็น TypeScript (typecheck อยู่ใน `bun run typecheck`) เพิ่มเป็น dependency เฉพาะของ workspace นี้ ไม่แตะ `package.json` ของเว็บและ API มากกว่าเพิ่ม script
- เว็บหน้าขายไม่ต้องรู้ว่ารันใน Electron ยกเว้นที่จำเป็นต้องใช้ preload: ตรวจ `window.tillumiDesktop?.…` และถอยกลับไปใช้ `window.print()` เมื่อไม่มี (ผู้ใช้เบราว์เซอร์ต้องใช้งานได้เหมือนเดิม)
- ตัวติดตั้ง Inno Setup (`installer/tillumi.iss`) แพ็กแอปไปด้วยและให้ทางลัด "เปิดหน้าร้าน" ชี้ไปที่แอปแทน Chrome/Edge kiosk ถ้าแอปไม่อยู่หรือเปิดไม่ได้ ให้ทางลัดถอยกลับไปใช้เบราว์เซอร์ตามลำดับเดิม
- สร้างไฟล์ด้วย workflow `windows-installer` เดิม (เพิ่มขั้น build แอป) และต้องไม่ทำให้เวลาของ job นานเกินสมเหตุสมผล

## ส่วนประกอบ

1. **main process**: สร้างหน้าต่างเต็มจอ, หน้ารอเมื่อ service ไม่พร้อม (โพล `/api/v1/health` พร้อมหน่วงเวลาเพิ่มขึ้นทีละน้อย), จำกัดการนำทางและหน้าต่างใหม่, เมนูที่ซ่อนไว้สำหรับเจ้าของ (ออกจากโหมดเต็มจอ, ตั้งค่าเครื่องพิมพ์, ปิดแอป) ด้วยแป้นลัดที่ต้องกดหลายปุ่ม, อินสแตนซ์เดียว (กดไอคอนซ้ำให้โฟกัสหน้าต่างเดิม)
2. **preload**: เปิด `window.tillumiDesktop` ที่มี `printReceipt(html)` และ `listPrinters()` เท่านั้น ตรวจ origin ของผู้เรียกก่อนทุกครั้ง
3. **การพิมพ์เงียบ**: ใช้ `webContents.print({ silent: true, deviceName })` กับเครื่องพิมพ์ที่เจ้าของเลือกไว้ (เก็บเฉพาะชื่อเครื่องพิมพ์ในไฟล์ตั้งค่าของผู้ใช้ Windows)
4. **การแพ็ก**: electron-builder แบบ `dir` (ไม่สร้างตัวติดตั้งซ้อน) แล้วให้ Inno Setup คัดลอกโฟลเดอร์ผลลัพธ์; `asar` เปิดไว้; รองรับการเซ็นภายหลังผ่านตัวแปร environment ใน CI
5. **หน้าตั้งค่าเครื่องพิมพ์** อยู่ในเมนูของแอป (หน้าต่างเล็กของแอปเอง ไม่ใช่หน้าเว็บของร้าน)

## ทดสอบ

- ส่วนตรรกะ (ตรวจ origin, ตัดสินใจนำทางภายใน/ภายนอก, ลำดับ backoff ของหน้ารอ, เลือกเครื่องพิมพ์) เป็นฟังก์ชันล้วนพร้อม `bun test` ข้างไฟล์
- เทสต์ผสานที่เปิดแอปจริงแบบ headless ไม่ทำในงานนี้ (ต้นทุนสูง) ใช้รายการตรวจด้วยมือในเอกสารแทน และ smoke ที่รัน `electron` กับ `--version`/เปิดแล้วปิดทันทีใน CI ถ้าทำได้
- ตัวติดตั้ง: รันขั้นตอน `windows-installer` เดิมให้ผ่าน และตรวจว่ามีโฟลเดอร์แอปในผลลัพธ์

## ความเสี่ยงที่รู้อยู่แล้ว

- ไฟล์ติดตั้งใหญ่ขึ้นราว 100 MB และต้องตามอัปเดตความปลอดภัยของ Electron เอง
- SmartScreen จะเตือนต่อไปจนกว่าจะมีใบรับรองลายเซ็น (ไม่ใช่ขอบเขตนี้)
- พิมพ์เงียบเขียนให้เครื่องพิมพ์ใบเสร็จที่ติดตั้งไดรเวอร์ Windows เท่านั้น เครื่องพิมพ์แบบส่ง ESC/POS ผ่านแลนที่ระบบมีอยู่แล้ว (`receipt-printer` module) ยังใช้เส้นทางเดิม
- ผมยังไม่ได้ทดสอบกับเครื่องพิมพ์จริง ต้องให้เจ้าของลองก่อนถือว่าใช้ได้

## ที่ปล่อยให้ผู้สร้างตัดสินใจ

โครงสร้างไฟล์ใน `apps/desktop/`, ชื่อช่องทาง IPC, ข้อความในหน้ารอ, ไอคอนของแอป (ใช้ไอคอนของร้านที่มีอยู่)
