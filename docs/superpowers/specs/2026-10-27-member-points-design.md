# แต้มสมาชิก

ต่อยอดจาก [แบบสมาชิก](2026-10-15-members-design.md) ซึ่งตอนนี้มีสมาชิก (ชื่อ เบอร์ ประวัติซื้อ) แต่ยังไม่มีแต้ม งานนี้อยู่บน branch `ohmattpon/member-points`

## เป้าหมาย

- **สะสมแต้ม:** สมาชิกได้แต้มจากยอดที่จ่ายจริง ตามอัตราที่ร้านตั้ง เช่น ทุก 25 บาทได้ 1 แต้ม
- **แลกแต้ม:** แลกเป็นส่วนลดในบิลถัดไปได้ ตามมูลค่าที่ร้านตั้ง เช่น 1 แต้ม = 1 บาท
- **ดูแต้ม:** แคชเชียร์เห็นแต้มคงเหลือเมื่อเลือกสมาชิก และหน้าสมาชิกมีประวัติแต้มทุกรายการ
- **ปรับแต้มเอง:** เจ้าของปรับแต้มได้ (เพิ่ม/ลด) พร้อมเหตุผล

## ไม่ทำ

- แต้มหมดอายุ
- ระดับสมาชิก (เงิน/ทอง)
- ตัวคูณแต้มตามโปรหรือตามสินค้า
- แลกแต้มเป็นสินค้า
- แอปหรือหน้าที่ลูกค้าดูแต้มเอง
- โอนแต้มระหว่างสมาชิก

## ห้ามเกิด

- **แต้มติดลบ หรือแลกแต้มเดียวกันซ้ำสองบิล:** อาจเกิดเมื่อสองเครื่องขายพร้อมกัน
- **แต้มค้างหลัง void:** void บิลแล้วแต้มที่ได้จากบิลนั้นต้องหายไป และแต้มที่แลกไปต้องกลับมาครบ
- **ยอดบนจอไม่ตรงใบเสร็จ หรือเงิน QR ที่จ่ายแล้วออกบิลไม่ได้:** อาจเกิดเพราะแต้มเปลี่ยนระหว่างรอเงิน
- **แก้ประวัติแต้มทับ:** ทุกการเปลี่ยนเป็นแถวใหม่เสมอ (append-only)

## การตั้งค่า (ร้าน)

`shop_settings` เพิ่ม 4 คอลัมน์ ทุกค่ามีค่าเริ่มต้นที่ปิดระบบไว้ ร้านเดิมจึงไม่เห็นอะไรเปลี่ยน:

| คอลัมน์ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `points_enabled boolean` | false | เปิด/ปิดทั้งระบบ |
| `points_earn_satang integer` | 2500 | จ่ายครบเท่านี้ได้ 1 แต้ม (≥ 100) |
| `points_redeem_satang integer` | 100 | 1 แต้มแลกได้เท่านี้ (≥ 1) |
| `points_min_redeem integer` | 1 | แลกขั้นต่ำต่อบิล (≥ 1) |

- **เวลาเปลี่ยนค่า:** มีผลกับบิลถัดไปเท่านั้น บิลเก่าเก็บตัวเลขที่ใช้ไว้ใน snapshot
- **audit:** ต้องบันทึก audit เหมือนการตั้งค่าอื่น

## โมเดลข้อมูล (migration เพิ่มอย่างเดียว)

**ตารางใหม่ `member_point_movements` (append-only):**

| คอลัมน์ | หมายเหตุ |
|---|---|
| `id` | |
| `member_id` | FK |
| `kind` | `earn`, `redeem`, `void_earn`, `void_redeem`, `adjust` |
| `points integer` | บวกหรือลบ ห้ามเป็น 0 |
| `sale_id` | null ได้ (ใช้กับ `adjust`) |
| `reason text` | บังคับเมื่อ `adjust` |
| `created_by_id` | |
| `created_at` | |

- **index:** `(member_id, created_at)`
- **unique:** `(sale_id, kind)` เมื่อ `sale_id` ไม่เป็น null เพื่อให้หนึ่งบิลมี earn ได้ครั้งเดียว และ void ได้ครั้งเดียว
- **ห้ามแก้หรือลบ:** port และ adapter ต้องไม่มี update/delete เหมือน `audit_logs`

**ยอดคงเหลือ (`members.points_balance integer not null default 0`):**
- เป็นค่าที่ระบบเก็บไว้เพื่ออ่านเร็ว ต้องเปลี่ยนใน unit of work เดียวกับที่เพิ่มแถว movement เสมอ
- ห้ามติดลบ ใส่ check constraint `>= 0`
- ความจริงคือผลรวมของ movement และต้องมีเทสต์ integration ตรวจว่าทั้งสองค่าตรงกัน

**บิล (`sales`) เพิ่ม:**
- `points_earned integer not null default 0`
- `points_redeemed integer not null default 0`
- `points_discount_satang integer not null default 0`
- อัตราที่ใช้ เก็บใน jsonb snapshot `points_rule` (null ได้สำหรับบิลเก่า)

**quote (`price_quotes`) เพิ่ม:** `points_redeemed`, `points_discount_satang` และ `points_rule` เพื่อตรึงไว้เหมือนส่วนอื่นของราคา

## สูตร (ที่เดียว: `domains/member-points.ts` ฟังก์ชันบริสุทธิ์ ใช้ร่วมกับเว็บผ่าน `@pos/api/points`)

- **ส่วนลดจากแต้ม:** `pointsDiscount(points, rule) = points × redeemSatang`
  - ต้องไม่เกิน "ยอดหลังส่วนลดโปร/ส่วนลดที่พิมพ์" ของบิล
  - จำนวนแต้มที่แลกได้สูงสุด = `floor(ยอดนั้น / redeemSatang)`
- **ส่วนลดรวมที่ส่งให้ `calculateTotals`:** `discountSatang = ส่วนลดโปรหรือส่วนลดที่พิมพ์ + ส่วนลดจากแต้ม`
  - สูตร `calculateTotals` ไม่เปลี่ยน
  - **กฎใหม่:** แต้มซ้อนกับโปรได้ แต่โปรกับส่วนลดที่พิมพ์ยังไม่ซ้อนกันเหมือนเดิม ต้องแก้ข้อความใน AGENTS.md ให้ตรง
- **แต้มที่ได้:** `pointsEarned(totalSatang, rule) = floor(totalSatang / earnSatang)`
  - คิดจากยอดสุทธิที่ลูกค้าจ่ายจริง (หลังส่วนลดทุกอย่าง รวม VAT)
  - บิลที่แลกแต้มก็ยังได้แต้มจากส่วนที่จ่ายจริง

## ขั้นตอน

**ขอ quote:** `POST /quotes` รับ `redeemPoints` (optional, จำนวนเต็ม ≥ 0) เมื่อมีสมาชิกและระบบเปิดอยู่
- อ่านยอดคงเหลือ (ไม่ล็อก)
- เกินยอดคงเหลือ, ต่ำกว่าขั้นต่ำ หรือเกินจำนวนที่แลกได้ → `POINTS_NOT_ENOUGH` หรือ `POINTS_REDEEM_INVALID` (400) พร้อม `params`
- quote ตรึงแต้มที่แลกและส่วนลดไว้

**การแลกแต้ม:** ต้องผ่าน quote เสมอ
- checkout ที่ไม่มี quote แต่ขอแลกแต้ม → `QUOTE_REQUIRED`
- ส่วนลดที่พิมพ์เองยังไปทางเดิม (ไม่มี quote) แต่ในทางนั้นแลกแต้มไม่ได้

**ตอนชำระ (`SaleCheckout`):** ทำใน unit of work เดียวกับการสร้างบิล ล็อกสมาชิกตามลำดับเดิม (order → QR → quote → member → product) แล้ว:
1. ถ้ามีแต้มที่แลก ให้ตรวจยอดคงเหลือใต้ล็อก
   - **quote `open` (จ่ายเงินสด/บัตร):** ถ้าไม่พอ → `POINTS_NOT_ENOUGH` (409) แล้วเว็บขอราคาใหม่
   - **quote `reserved` (เงิน QR มาแล้ว):** แต้มถูกกันไว้ตั้งแต่ตอน reserve แล้ว ไม่ตรวจซ้ำ
2. เพิ่ม movement `redeem` (ค่าติดลบ) และ `earn` (ค่าบวก ถ้า > 0) แล้วปรับ `points_balance`
3. ใช้ `points_rule` จาก quote ไม่ใช่ค่าที่ตั้งตอนนี้

**กันแต้มให้ QR:** เมื่อ reserve quote ให้ QR ระบบล็อกสมาชิก ตรวจยอด แล้วเขียน movement `redeem` ทันที โดยมี `quote_id` และไม่มี `sale_id`
- ตอนออกบิลจาก quote นั้น ไม่ต้องเขียน `redeem` ซ้ำ และไม่แก้แถวเดิม (append-only)
  - ความเชื่อมโยงกับบิลมาจาก `price_quotes.sale_id` ที่มีอยู่แล้ว
- ถ้ายกเลิกหรือ dismiss QR ให้เขียน movement `void_redeem` คืนแต้ม โดยมี `quote_id`
- **ผล:** เงินที่จ่ายแล้วได้บิลเสมอ และแต้มไม่ถูกใช้ซ้ำ
- **ที่ต้องปรับตาราง:** movement มีคอลัมน์ `quote_id` เพิ่ม (null ได้)
  - unique `(quote_id, kind)` เมื่อ `quote_id` ไม่เป็น null
  - check ว่ามี `sale_id` หรือ `quote_id` อย่างน้อยหนึ่งอย่าง ยกเว้นเมื่อเป็น `adjust`
- **void บิลที่แลกแต้มผ่าน QR:** หา movement `redeem` จาก quote ของบิล แล้วเขียน `void_redeem` โดยมี `sale_id`

**void บิล:** ใน unit of work ของ void ให้เขียน `void_earn` (ลบแต้มที่ได้) และ `void_redeem` (คืนแต้มที่แลก)
- ถ้าลบแต้มที่ได้แล้วยอดคงเหลือจะติดลบ (สมาชิกใช้แต้มนั้นไปแล้ว) ให้ลดยอดลงเหลือ 0 ไม่ใช่ติดลบ
- บันทึกส่วนที่ขาดไว้ใน `reason` ของ movement และ audit
- **เหตุผลที่ไม่ปฏิเสธการ void:** void คือการแก้ความผิดพลาดที่ต้องทำได้เสมอ

**ปรับแต้มเอง:** `POST /members/{id}/points/adjustments` `{ points, reason }`
- เป็น command ใหม่ ต้องใช้สิทธิ์ใหม่ `members.points_adjust`
- ต้องเพิ่มคำแปลสิทธิ์ในเว็บ
- ผลลัพธ์ห้ามติดลบ → `POINTS_NOT_ENOUGH`
- เขียน audit ใน unit of work เดียวกัน

## API (v1 เพิ่มอย่างเดียว)

- **สมาชิก:** `GET /members/{id}` และรายการสมาชิกเพิ่ม `pointsBalance`
- **ประวัติแต้ม:** `GET /members/{id}/points?limit&offset` (query) ตอบ `{ items, total }` เรียงใหม่สุดก่อน
- **การขาย:** response ของบิล (v1 และ v2) เพิ่ม `pointsEarned`, `pointsRedeemed`, `pointsDiscountSatang`
- **quote:** `POST /quotes` รับ `redeemPoints` และ response ของ quote เพิ่มฟิลด์แต้ม
- **ตั้งค่าร้าน:** response ของการตั้งค่าร้านเพิ่ม 4 ค่า
- **error code ใหม่:** `POINTS_NOT_ENOUGH`, `POINTS_REDEEM_INVALID`, `POINTS_DISABLED` พร้อมคำแปลใน `src/locales/errors.ts`
- **OpenAPI:** baseline ต้องบันทึกใหม่ (เปลี่ยนแบบเพิ่มอย่างเดียว) และแจ้งเจ้าของก่อน

## หน้าเว็บ

- **ตั้งค่าร้าน:** ส่วน "แต้มสมาชิก" มีสวิตช์และ 3 ช่อง พร้อมตัวอย่างที่คำนวณจากสูตรเดียวกัน (เช่น "จ่าย 100 บาท ได้ 4 แต้ม")
- **ตะกร้า (เมื่อเลือกสมาชิก):**
  - แสดงแต้มคงเหลือ
  - ปุ่ม "แลกแต้ม" เปิดช่องจำนวนแต้ม มีปุ่ม "สูงสุด" และแสดงส่วนลดที่จะได้
  - จำนวนที่พิมพ์เก็บใน zustand ล้างพร้อมตะกร้าและเมื่อเปลี่ยนสมาชิก
- **ใบเสร็จ:** แสดงบรรทัด "ส่วนลดจากแต้ม" แต้มที่ได้ และแต้มคงเหลือหลังบิล
  - แต้มคงเหลืออ่านจาก response ของบิล โดยเก็บ `pointsBalanceAfter` ใน snapshot ของบิล
- **หน้าสมาชิก:** แท็บประวัติแต้ม และปุ่มปรับแต้ม (เห็นเฉพาะผู้มีสิทธิ์)
- **ขนาดจอ:** ทุกหน้าต้องใช้ได้ที่ 390/768/1366px และตารางใช้ `DataTable`

## เทสต์ที่ต้องมี

- **เทสต์ของสูตร:** แต้มที่ได้ปัดลง, ส่วนลดจากแต้มไม่เกินยอด, แลกพอดียอด, แต้มกับโปรซ้อนกัน
- **use case:**
  - แลกเกินยอด
  - ต่ำกว่าขั้นต่ำ
  - ปิดระบบอยู่
  - ไม่มี quote
  - quote open แต่แต้มถูกใช้ไปแล้ว (409)
  - QR reserved แล้วผ่าน
  - void คืนครบ
  - void แล้วยอดคงเหลือจะติดลบ
  - ปรับแต้มโดยไม่มีสิทธิ์
- **integration:**
  - สองบิลพร้อมกันแลกแต้มชุดเดียวกัน ต้องผ่านบิลเดียว
  - ยอดคงเหลือเท่ากับผลรวมของ movement หลังขาย void และปรับแต้ม

## ข้อที่ผมตัดสินใจเอง (เจ้าของโครงการอนุมัติแล้ว 2026-10-27)

- แต้มคิดจากยอดสุทธิรวม VAT และปัดลง
- แลกแต้มซ้อนกับโปรได้
- void ที่ทำให้ยอดติดลบ จะลดยอดเหลือ 0 แทนการปฏิเสธ
- ไม่มีแต้มหมดอายุในรอบแรก
- ระบบปิดไว้เป็นค่าเริ่มต้น
