# การตั้งค่าร้านและรองรับหลายภาษา: เอกสารออกแบบ

- วันที่: 2026-10-13
- ชิ้นงานที่ 4 ใน `docs/superpowers/roadmap.md`
- branch: `ohmattpon/shop-settings` (ซ้อนบน `ohmattpon/web-feature-structure`)

## เป้าหมาย

ค่าที่ร้านต้องปรับเองได้ ต้องไม่ฝังในโค้ดหรือไฟล์ env และข้อความทั้งหมดที่ผู้ใช้เห็นต้องอยู่ในไฟล์ภาษา เพื่อให้ร้านอื่นนำไปใช้และเพิ่มภาษาได้โดยไม่แก้คอมโพเนนต์

## สิ่งที่ตัดสินใจ

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| ที่เก็บการตั้งค่า | ตาราง `shop_settings` แถวเดียว (`id = 1`) ถ้ายังไม่มีแถวใช้ค่าเริ่มต้นจากโค้ด | แก้ได้จากหน้าเว็บ ไม่ต้องรีสตาร์ต และไม่ต้องมีขั้นตอนใส่ข้อมูลตั้งต้น |
| วิธีคิดภาษี | `inclusive` (ราคารวม VAT, เป็นค่าเริ่มต้น), `exclusive` (บวก VAT เพิ่ม), `none` (ไม่คิด) | ร้านไทยส่วนใหญ่ใช้ราคารวม VAT แต่ร้านที่ขายให้นิติบุคคลมักแยก |
| การเปลี่ยนค่าภาษี | มีผลกับบิลใหม่เท่านั้น บิลเก็บ `vatMode` และ `vatRateBp` ของตัวเองเมื่อขาย | ใบเสร็จเก่าห้ามเปลี่ยน เหมือนที่เก็บชื่อและราคาสินค้า |
| การคำนวณยอดฝั่งเว็บ | ใช้ฟังก์ชันล้วนตัวเดียวกับเซิร์ฟเวอร์ (`@pos/api/pricing`) | ถ้าเขียนสองที่ ยอดที่เห็นหน้าจอกับยอดที่เซิร์ฟเวอร์คิดจะเพี้ยนกันที่การปัดเศษ |
| สกุลเงิน | ตั้งได้ (รหัส ISO 4217) กระทบการแสดงผลและจำนวนทศนิยม ข้อมูลยังเก็บเป็นหน่วยย่อยจำนวนเต็ม | ไม่เปลี่ยนชื่อฟิลด์ `*Satang` ของ API ซึ่งเป็นการทำให้สัญญา v1 พัง |
| ภาษา | ไทย (`th`) และอังกฤษ (`en`) ตั้งเป็นภาษาของทั้งร้าน | พิสูจน์ว่ากลไกเพิ่มภาษาได้จริง ภาษาต่อผู้ใช้ทำทีหลังได้ |
| ไลบรารีแปลภาษา | `i18next` + `react-i18next` | มาตรฐาน รองรับ interpolation, plural และ namespace ซึ่งเข้ากับโครง feature |
| ข้อความจาก API | เซิร์ฟเวอร์ตอบ `detail` ภาษาไทยเสมอ และส่ง `params` เมื่อมีข้อมูลแทรก เว็บแปลตาม `code` เมื่อภาษาไม่ใช่ไทย | ไคลเอนต์อื่นยังได้ข้อความอ่านออก และเซิร์ฟเวอร์ไม่ต้องรู้ภาษาของผู้ใช้ |

## การตั้งค่า

| ช่อง | กฎ | ค่าเริ่มต้น |
|---|---|---|
| `shopName` | 1–100 ตัวอักษร | `EasyPOS` |
| `taxId` | ไม่บังคับ ไม่เกิน 20 ตัวอักษร | ว่าง |
| `address` | ไม่บังคับ ไม่เกิน 300 ตัวอักษร | ว่าง |
| `phone` | ไม่บังคับ ไม่เกิน 30 ตัวอักษร | ว่าง |
| `currency` | รหัส ISO 4217 สามตัวอักษรใหญ่ | `THB` |
| `vatMode` | `inclusive`, `exclusive`, `none` | `inclusive` |
| `vatRateBp` | จำนวนเต็ม 0–10000 (700 = 7%) | `700` |
| `timeZone` | IANA time zone ที่ถูกต้อง กำหนดเส้นแบ่งวันของเลขใบเสร็จ | `Asia/Bangkok` |
| `locale` | `th` หรือ `en` | `th` |

## API

- `GET /api/v1/settings`: ผู้ใช้ที่ล็อกอินทุกคน (แคชเชียร์ต้องรู้สกุลเงิน VAT และชื่อร้านเพื่อแสดงผล)
- `PATCH /api/v1/settings`: เจ้าของร้านเท่านั้น ส่งเฉพาะช่องที่เปลี่ยน
- ทุกบิล (`/sales`, `/sales/:id`) เพิ่มช่อง `vatMode` และ `vatRateBp`: เป็นการเพิ่มช่อง ไม่ทำให้ไคลเอนต์เดิมพัง
- problem details เพิ่มช่อง `params` (ไม่บังคับ) สำหรับข้อความที่มีข้อมูลแทรก: `INSUFFICIENT_STOCK` (`name`, `available`), `PRODUCT_INACTIVE` (`name`), `PRODUCT_NOT_FOUND` (`productId`)

### การคิดยอด

| โหมด | ยอดสุทธิ | VAT |
|---|---|---|
| `inclusive` | รวมสินค้า − ส่วนลด | ปัด(ยอดสุทธิ × อัตรา ÷ (10000 + อัตรา)) |
| `exclusive` | (รวมสินค้า − ส่วนลด) + VAT | ปัด((รวมสินค้า − ส่วนลด) × อัตรา ÷ 10000) |
| `none` | รวมสินค้า − ส่วนลด | 0 |

ยอดสุทธิที่เกิน 2,147,483,647 หน่วยย่อยตอบ 400 `AMOUNT_TOO_LARGE` เหมือนเดิม

## เว็บ

- feature ใหม่ `settings`: หน้าตั้งค่า (เจ้าของร้านเท่านั้น), `useSettings()`, `useFormat()` (จำนวนเงิน วันที่ ตามสกุลเงินและภาษา)
- รายการเมนู "ตั้งค่าร้าน" ใน sidebar สำหรับเจ้าของร้าน
- ตะกร้าคิดยอดตามโหมดภาษี และแสดงบรรทัด VAT เมื่อเป็น `exclusive`
- ใบเสร็จแสดงชื่อร้านและเลขผู้เสียภาษีจากการตั้งค่าปัจจุบัน และข้อความ VAT ตามโหมดของบิลนั้น
- ข้อความทุกข้อความอยู่ใน `features/<feature>/locales/{th,en}.ts` และ `src/locales/{th,en}.ts` (ส่วนกลาง) คีย์เป็น type-safe
- ภาษาเปลี่ยนตามการตั้งค่าของร้านทันทีที่โหลด และจำค่าล่าสุดใน `localStorage` เพื่อไม่ให้หน้าล็อกอินกระพริบ

## สิ่งที่อยู่นอกขอบเขต

- ภาษาต่อผู้ใช้ และภาษาอื่นนอกจาก `th`/`en`
- เปลี่ยนชื่อฟิลด์ `*Satang` ใน API (ควรทำพร้อมการขึ้น `v2` ถ้ามีผู้ใช้สกุลเงินที่ไม่ใช่หน่วยย่อย 1/100)
- เก็บภาพถ่ายข้อมูลร้าน (ชื่อ เลขผู้เสียภาษี ที่อยู่) ไว้ในบิล ซึ่งใบกำกับภาษีต้องการ อยู่ในชิ้นที่ 11
- หน้าจัดการผู้ใช้และหมวดหมู่ (ชิ้นที่ 11)
- แปลข้อความที่เซิร์ฟเวอร์ตอบกรณีผิดปกติที่หน้าเว็บตรวจดักไว้แล้ว (`INVALID_*`) ถ้าภาษาไม่ใช่ไทยจะเห็นข้อความไทยของเซิร์ฟเวอร์

## เกณฑ์ว่าเสร็จ

- การทดสอบทั้งหมดผ่าน: การคิดยอดทั้งสามโหมด การตั้งค่า (สิทธิ์ ตรวจข้อมูล) บิลเก่าคงค่าเมื่อเปลี่ยนการตั้งค่า
- ตัวแปร `VAT_RATE_BP` และ `SHOP_TIME_ZONE` ไม่ถูกใช้ในโค้ดอีก
- ไม่เหลือข้อความไทยฝังในคอมโพเนนต์ (ตรวจด้วย `grep` หาอักษรไทยในไฟล์ `.tsx` นอก `locales/`)
- เปลี่ยนภาษาและสกุลเงินในหน้าตั้งค่าแล้วหน้าขาย ใบเสร็จ และหน้าวันนี้เปลี่ยนตามในเบราว์เซอร์จริง
