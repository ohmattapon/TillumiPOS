# โครงสร้างสาขา

สถานะ: ร่างสำหรับลงมือทำ · roadmap ข้อ 5 · branch `ohmattpon/branches`

## เป้าหมาย

ร้านเดียวมีได้หลายสาขา โดยสต็อก บิล เลขใบเสร็จ และผู้ใช้ผูกกับสาขา และแก้ตอนที่ยังไม่มีข้อมูลจริงมากที่สุด ร้านที่มีสาขาเดียวต้องใช้งานได้เหมือนเดิมโดยไม่ต้องรู้ว่ามีสาขา

## การตัดสินใจ

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| รายการสินค้า หมวดหมู่ ราคา ต้นทุน | ใช้ร่วมกันทุกสาขา | ร้านเดียวกันขายของชุดเดียวกัน แยกราคาตามสาขาเป็นของหลังรุ่นแรก |
| จำนวนสต็อก | แยกตามสาขา ตาราง `branch_stock` แทนคอลัมน์ `products.stock_qty` | สต็อกคือสิ่งที่ต่างกันจริงในแต่ละสาขา |
| ผู้ใช้ | ผูกกับ 1 สาขาหลัก (`users.branch_id`) | พนักงานประจำที่เดียว กรณีอื่นหลังรุ่นแรก |
| การเลือกสาขาที่ทำงาน | header `X-Branch-Id` ทุกคำขอ ถ้าไม่ส่งใช้สาขาหลักของผู้ใช้ | ไม่ต้องเปลี่ยนรูปแบบ session และเจ้าของร้านสลับสาขาได้ทันที |
| สิทธิ์ข้ามสาขา | เจ้าของร้าน (`owner`) ทำงานได้ทุกสาขา แคชเชียร์ได้เฉพาะสาขาหลักของตน ถ้าขอสาขาอื่นได้ 403 | ตรงกับแนวคิดเจ้าของ/พนักงานที่มีอยู่ |
| เลขใบเสร็จ | `<รหัสสาขา>-yyyymmdd-nnnnn` นับแยกตามสาขาและวัน ไม่มีช่องว่าง | เลขซ้ำข้ามสาขาไม่ได้ และอ่านออกว่าบิลมาจากไหน บิลเก่าคงรูปแบบเดิม |
| การตั้งค่า (สกุลเงิน VAT ภาษา เขตเวลา ชื่อร้าน) | ยังเป็นระดับร้าน มีชุดเดียว | ภาษี สกุลเงิน เป็นเรื่องของนิติบุคคล ไม่ใช่สาขา |
| ที่อยู่และเบอร์โทร | อยู่ที่สาขา (ว่างได้) ใบเสร็จพิมพ์ของสาขาถ้ามี ไม่มีใช้ของร้าน | สาขาต่างที่อยู่กัน |
| ปิดสาขา | ปิดการใช้งานได้ ลบไม่ได้ ปิดสาขาสุดท้ายหรือสาขาที่ยังมีผู้ใช้ที่ใช้งานอยู่ไม่ได้ | ประวัติบิลและสต็อกต้องอ้างถึงสาขาได้เสมอ |
| ย้ายสต็อกระหว่างสาขา | ไม่ทำ สต็อกเข้าสาขาใหม่ด้วยการรับเข้า | การโอนเป็นของหลังรุ่นแรกใน roadmap |
| ข้อมูลเดิม | สร้างสาขา `MAIN` (ชื่อจากชื่อร้านที่ตั้งไว้) ให้ผู้ใช้ บิล รายการเคลื่อนไหว และยอดสต็อกเดิมทั้งหมด | ร้านเดิมใช้ต่อได้ทันที |

## ข้อมูล

- `branches`: `id`, `code` (unique, ตัวพิมพ์ใหญ่ a-z0-9 ยาว 2-10), `name`, `address`, `phone`, `is_active`, `created_at`, `updated_at`
- `branch_stock`: คีย์หลัก (`branch_id`, `product_id`), `qty`; สร้างแถวเมื่อมีการเคลื่อนไหวครั้งแรก สินค้าที่ไม่มีแถวถือว่าคงเหลือ 0
- `users.branch_id` (not null, อ้าง `branches`)
- `sales.branch_id`, `stock_movements.branch_id` (not null)
- `receipt_counters`: คีย์หลักเป็น (`branch_id`, `day`)
- ลบ `products.stock_qty` ยอดคงเหลือของสินค้าที่ API ตอบคือยอดของสาขาที่ทำงานอยู่

## API (ยังอยู่ใต้ `/api/v1`)

- `GET /branches`: ผู้ใช้ที่ล็อกอินทุกคน เจ้าของเห็นทุกสาขา แคชเชียร์เห็นเฉพาะสาขาของตน
- `POST /branches`, `PATCH /branches/:id`: เจ้าของเท่านั้น
- ทุกเส้นทางที่เกี่ยวกับสต็อกและการขาย (`/products`, `/inventory`, `/sales`) ทำงานในสาขาที่ได้จาก `X-Branch-Id`
- ผู้ใช้ (`/users`) มี `branchId` ตอนสร้างและแก้
- บิลที่คืนมามี `branchId`
- ข้อผิดพลาดใหม่: `BRANCH_NOT_FOUND` (404), `BRANCH_FORBIDDEN` (403, แคชเชียร์ขอสาขาอื่น), `BRANCH_INACTIVE` (409), `BRANCH_CODE_TAKEN` (409), `BRANCH_IN_USE` (409, ปิดสาขาที่ยังมีผู้ใช้หรือเป็นสาขาสุดท้าย)

## เว็บ

- ตัวสลับสาขาใน sidebar สำหรับเจ้าของที่มีมากกว่า 1 สาขา ค่าเก็บใน zustand และ localStorage และส่งเป็น `X-Branch-Id` ทุกคำขอ
- เปลี่ยนสาขาแล้ว invalidate ข้อมูลที่ขึ้นกับสาขาทั้งหมด (สินค้า บิล สรุป) และล้างตะกร้า
- หน้าจัดการสาขาในหน้าตั้งค่า: เพิ่ม แก้ ปิดสาขา
- ใบเสร็จแสดงชื่อและที่อยู่ของสาขา

## นอกขอบเขต

ราคาแยกตามสาขา, โอนสต็อกระหว่างสาขา, ผู้ใช้หลายสาขา, รายงานรวมทุกสาขา, ตั้งค่าแยกตามสาขา

## เสร็จเมื่อ

- ทดสอบเดิมทั้งหมดผ่าน (แก้เฉพาะรูปแบบเลขใบเสร็จและการตั้งต้นข้อมูล)
- ขายในสองสาขาแล้วสต็อก เลขใบเสร็จ และสรุปแยกกันจริง
- แคชเชียร์เข้าสาขาอื่นไม่ได้ ปิดสาขาสุดท้ายไม่ได้
- migration แปลงข้อมูลเดิมเข้าสาขา `MAIN` ได้ครบ (ยอดสต็อกรวมเท่าเดิม)
- `openapi:check` ผ่านหลังบันทึก baseline ใหม่
