# ชุดติดตั้ง

สถานะ: ร่างสำหรับลงมือทำ · roadmap ข้อ 14 · branch `ohmattpon/install-kit` (แตกจาก `main`)

## เป้าหมาย

เจ้าของร้านที่ไม่ใช่นักพัฒนาติดตั้ง EasyPOS บนเครื่องของร้านหรือ VPS ได้ด้วยคำสั่งเดียว ตั้งค่าเจ้าของและร้านครั้งแรกจากหน้าเว็บโดยไม่มีรหัสผ่านเริ่มต้นอยู่ใน repo สำรองและกู้คืนข้อมูลได้ และมีเอกสารกับใบอนุญาตครบ

## ขอบเขต

ข้อ 14 ทำเป็นสี่ส่วนตามลำดับ ในแผนเดียว: (1) หน้าตั้งค่าครั้งแรก (2) ชุดติดตั้ง Docker Compose (3) สำรองและกู้คืน (4) เอกสาร ใบอนุญาต และการตรวจความลับ ตัวติดตั้งสำหรับ Windows แบบดับเบิลคลิกอยู่นอกขอบเขตรอบนี้

## การตัดสินใจ

## 1) หน้าตั้งค่าครั้งแรก

- ตอนเริ่ม API ถ้าฐานไม่มีผู้ใช้เลย ระบบสร้างรหัสตั้งค่า (สุ่ม 12 ตัวอักษรจากชุดที่อ่านง่าย เก็บในหน่วยความจำ) และพิมพ์ลง log พร้อมวิธีดู (`docker compose logs app`) รีสตาร์ทได้รหัสใหม่ จนกว่าจะตั้งค่าเสร็จ
- API (v1 เพิ่มอย่างเดียว, ไม่ต้องล็อกอิน):
  - `GET /api/v1/setup` → `{ needsSetup: boolean }`
  - `POST /api/v1/setup` body `{ setupCode, shopName, branchName, username, displayName, password }` สร้างเจ้าของ ตั้งชื่อร้านและสาขาแรก (`MAIN`) แล้วล็อกอินให้ (ตั้งคุกกี้เซสชันเหมือน login)
- ผิดรหัสตั้งค่า 5 ครั้งล็อก 15 นาที (ในหน่วยความจำ) การเทียบรหัสใช้เวลาคงที่
- รหัสผ่านเจ้าของยาวอย่างน้อย 10 ตัวอักษร
- การสร้างผู้ใช้และตั้งค่าร้านอยู่ใน unit of work เดียวภายใต้ advisory lock: สองคำขอพร้อมกันได้เจ้าของคนเดียว อีกคำขอตอบ `SETUP_DONE` (409) และเมื่อมีผู้ใช้แล้ว `POST /setup` ตอบ `SETUP_DONE` เสมอ
- use case: `GetSetupStatus` (query), `CompleteSetup` (command), port `ISetupCode` (เจ้าของคือโมดูล `setup`)
- เว็บ: feature `setup` หน้า `/setup` และ `App` ตรวจ `needsSetup` ก่อนแสดงหน้าเข้าสู่ระบบ
- `db:seed` ยังอยู่เป็นเครื่องมือนักพัฒนา ชุดติดตั้งไม่รัน

## 2) ชุดติดตั้ง Docker Compose

- `Dockerfile` หลายขั้น: build เว็บเป็น `apps/web/dist` แล้วรวมกับ API ในคอนเทนเนอร์เดียว ตัวแปร `WEB_DIST` ชี้ไปที่โฟลเดอร์ที่ build แล้ว API บริการไฟล์ static และ fallback ไป `index.html` สำหรับเส้นทางที่ไม่ใช่ `/api`, `/openapi`
- `docker-compose.yml`: บริการ `db` (ไม่เปิดพอร์ตออกนอกเครื่อง), `app` (migrate อัตโนมัติตอนเริ่มแล้วรัน API เปิดพอร์ต `${PORT:-3000}`), `caddy` (profile `https` ใช้ตัวแปร `DOMAIN` และตั้ง `COOKIE_SECURE=true`) พอร์ต 5433 สำหรับนักพัฒนาย้ายไป `docker-compose.override.yml`
- `scripts/install.sh` และ `scripts/install.ps1`: สร้าง `.env` จาก `.env.example` พร้อม `JWT_SECRET` และรหัสฐานข้อมูลสุ่ม (ไม่เขียนทับ `.env` ที่มีอยู่) รัน `docker compose up -d --build` รอจนระบบพร้อม แล้วพิมพ์ URL และรหัสตั้งค่า
- `MEDIA_URL` และ `MEDIA_TOKEN` ไม่บังคับ: ถ้าไม่ตั้ง การอัปโหลดรูปตอบ `MEDIA_UNAVAILABLE` และ `GET /api/v2/capabilities` เพิ่ม `imageStorage: 'enabled' | 'disabled'` ให้หน้าสินค้าซ่อนส่วนอัปโหลดรูป

## 3) สำรองและกู้คืน

- `scripts/backup.sh|ps1`: `pg_dump` ผ่านคอนเทนเนอร์ `db` เป็น `backups/easypos-<วันเวลา>.sql.gz` (`backups/` ถูก ignore) ไม่ต้องมี Bun หรือเครื่องมือ Postgres บนเครื่อง
- `scripts/restore.sh|ps1 <ไฟล์>`: ถามยืนยัน หยุด `app` ชั่วคราว ล้างและโหลดข้อมูลกลับ แล้วเริ่ม `app` ใหม่
- ไฟล์รูปที่อยู่ที่ R2 ไม่ถูกรวมในการสำรอง (เอกสารระบุ)

## 4) เอกสาร ใบอนุญาต และการตรวจความลับ

- `docs/install.md` (ไทย): ข้อกำหนด ติดตั้ง ตั้งค่าครั้งแรก เปิด HTTPS ตั้ง SCB/R2 สำรอง กู้คืน อัปเดตเวอร์ชัน แก้ปัญหา และลิงก์จาก `README.md`
- `LICENSE` เป็นข้อความ AGPL-3.0 ฉบับทางการ และส่วนหัวลิขสิทธิ์ใน `README.md`
- การทดสอบอัตโนมัติสแกนไฟล์ที่ track หา `.env` ที่ถูก commit, คีย์ SCB ที่ไม่ใช่ placeholder (`your-…`), และสตริงเชื่อมต่อฐานข้อมูลที่มีรหัสผ่านจริง

## นอกขอบเขต

ตัวติดตั้ง Windows แบบดับเบิลคลิก, ตัวตั้งเวลาสำรองในระบบ, การสำรองรูปบน R2, การอัปเดตอัตโนมัติ, ที่เก็บรูปในเครื่อง (ข้อ 13), การรีเซ็ตรหัสผ่านเจ้าของที่ลืม (ทำด้วยคำสั่งจากเครื่องเซิร์ฟเวอร์ เป็นงานแยก)

## เสร็จเมื่อ

- บนเครื่องที่มี Docker เท่านั้น: รัน `scripts/install.sh` แล้วเปิดเว็บ ตั้งค่าเจ้าของด้วยรหัสตั้งค่าจาก log และขายได้
- คนที่ไม่มีรหัสตั้งค่าสร้างเจ้าของไม่ได้ และตั้งค่าซ้ำไม่ได้
- สำรองแล้วกู้คืนได้ข้อมูลกลับมาครบ (ทดสอบจริงด้วยข้อมูล demo)
- ไม่มีค่าลับใน repo และการทดสอบสแกนผ่าน
- `typecheck`, `test`, `lint`, `openapi:check` (หลังได้รับอนุมัติให้บันทึก baseline) และ `e2e` ผ่าน
