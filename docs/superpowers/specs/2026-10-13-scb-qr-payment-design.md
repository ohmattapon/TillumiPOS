# ชำระด้วย QR ของ SCB (Thai QR Tag 30)

สถานะ: ร่างสำหรับลงมือทำ · หัวข้อ "ชำระเงินอัตโนมัติ" ของ roadmap (ดึงขึ้นมาทำก่อน) · branch `ohmattpon/scb-qr-payment`

## เป้าหมาย

เลือก "พร้อมเพย์" ตอนชำระ แล้วระบบสร้าง QR ตามยอดบิล แสดงให้ลูกค้าสแกน ยืนยันยอดเข้าจากธนาคารเอง แล้วบันทึกการขายต่อให้ทันที ไม่ต้องให้พนักงานเช็กสลิป ร้านที่ไม่ได้ตั้งค่า SCB ใช้พร้อมเพย์แบบกดยืนยันเองเหมือนเดิม

อ้างอิงเอกสารของ SCB (developer.scb): QR Code Payment, `POST /v1/oauth/token`, `POST /v1/payment/qrcode/create`, payment confirmation, `GET /v1/payment/billpayment/inquiry`

## การตัดสินใจ

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| ลำดับ | สร้าง QR ก่อน รอเงินเข้า แล้วค่อยบันทึกการขายด้วย `qrPaymentId` | เงินเข้าก่อนจึงไม่มีบิลที่ "จ่ายแล้วแต่ไม่มีเงิน" |
| สถานะที่เชื่อได้ | ข้อมูลจาก SCB inquiry เท่านั้น ไม่เชื่อ body ของ callback | เอกสาร SCB ไม่มีลายเซ็นหรือการยืนยันตัวตนของ callback ใครก็ส่งปลอมได้ |
| callback | เป็นเพียงสัญญาณให้ไปตรวจด้วย inquiry ทันที และตอบ `resCode 00` เสมอ | ได้ผลเร็วเมื่อมี URL สาธารณะ และระบบที่ติดตั้งในร้านซึ่งไม่มี URL ก็ใช้ได้ด้วยการ poll |
| การ poll | เว็บถาม `GET /payments/qr/:id` ทุก 3 วินาที เซิร์ฟเวอร์เรียก inquiry ได้ไม่ถี่กว่าทุก 3 วินาทีต่อรายการ | ไม่ยิง SCB ถี่เกินจำเป็น |
| เงินที่เข้ามาหลังยกเลิก | ถ้า inquiry เจอเงิน ให้เปลี่ยนเป็น `paid` แม้ถูกยกเลิกหรือหมดเวลาแล้ว | เงินเข้าจริงต้องไม่หายจากบันทึก ให้พนักงานเลือกใช้ต่อหรือคืนเงิน |
| ใช้ซ้ำ | หนึ่ง QR ใช้กับบิลได้ครั้งเดียว ล็อกแถวตอนใช้ ยอดต้องเท่ากับยอดชำระพอดี | กันใช้สลิปเดียวจ่ายหลายบิล |
| บังคับใช้ | เมื่อตั้งค่า SCB ครบ การชำระ `promptpay` ต้องมี `qrPaymentId` ที่ยืนยันแล้ว | ไม่เช่นนั้นพนักงานข้ามการตรวจได้ ถ้าไม่ได้ตั้งค่าก็ใช้แบบเดิม |
| อ้างอิง | `ref1` สุ่มไม่ซ้ำ (A-Z0-9 ยาว 16), `ref3` = `SCB_REF3_PREFIX` + รหัสสาขา | ตามข้อกำหนดของ SCB และตรวจย้อนได้ว่ามาจากสาขาไหน |
| หมดเวลา | QR 30 ของ SCB ไม่มีเวลาหมดอายุ ระบบกำหนด 10 นาทีเพื่อแสดงนับถอยหลังและหยุด poll | ลูกค้าที่จ่ายช้ายังถูกจับได้ผ่านกฎ "เงินที่เข้ามาหลังยกเลิก" |
| ความลับ | คีย์อยู่ใน `.env` เท่านั้น (`SCB_API_KEY`, `SCB_API_SECRET`, `SCB_BILLER_ID`, `SCB_REF3_PREFIX`, `SCB_API_BASE_URL`) ไม่ถูกส่งไปเว็บ ไม่ลง log ค่า placeholder ที่ขึ้นต้นด้วย `your-` นับว่าไม่ได้ตั้งค่า | |

## ข้อมูล

`qr_payments`: `id`, `branch_id`, `reference` (ref1, ไม่ซ้ำ), `amount_satang`, `status` (`pending|paid|cancelled`), `qr_raw_data`, `expires_at`, `bank_transaction_id`, `payer_name`, `paid_at`, `last_checked_at`, `sale_id` (เมื่อถูกใช้), `created_by_id`, เวลา

## API

| เส้นทาง | ทำอะไร |
|---|---|
| `GET /payments/qr/config` | `{ enabled }` ว่าร้านนี้ตั้งค่า QR ของ SCB แล้วหรือยัง |
| `POST /payments/qr` | `{ amountSatang }` สร้าง QR คืน `id`, `reference`, `qrRawData`, `qrImage` (base64), `expiresAt` |
| `GET /payments/qr/:id` | สถานะ (ถ้ายังรอ จะถาม SCB ให้ ไม่ถี่กว่า 3 วินาที) |
| `POST /payments/qr/:id/cancel` | เลิกรอ (ใช้ได้เฉพาะที่ยังไม่จ่าย) |
| `POST /payments/qr/scb/confirmation` | callback ของ SCB (ไม่ต้องล็อกอิน) |
| `POST /sales`, `POST /orders/:id/pay` | รายการชำระรับ `qrPaymentId` เพิ่ม |

ข้อผิดพลาดใหม่: `QR_NOT_CONFIGURED` 409, `QR_GATEWAY_ERROR` 502, `QR_PAYMENT_NOT_FOUND` 404, `QR_NOT_PAID` 409, `QR_ALREADY_USED` 409, `QR_ALREADY_PAID` 409, `QR_AMOUNT_MISMATCH` 400, `QR_PAYMENT_REQUIRED` 400

## เว็บ

เลือก "พร้อมเพย์" ในหน้าชำระ (เมื่อ `enabled`): สร้าง QR ตามยอด แสดงรูป ยอด และเวลาที่เหลือ รอจนยืนยันแล้วบันทึกการขายอัตโนมัติ ยกเลิกหรือเปลี่ยนวิธีชำระได้ ถ้าบันทึกการขายไม่สำเร็จหลังเงินเข้าแล้ว (เช่นของไม่พอ) จะมีปุ่มลองบันทึกอีกครั้งโดยไม่ต้องให้ลูกค้าจ่ายใหม่

## นอกขอบเขต

คืนเงิน/void QR กับ SCB, QR CS (บัตร), B Scan C, ยอดที่ไม่ตรงกับ QR (ลูกค้าแก้ยอดเอง), รายการเงินเข้าที่ไม่มีบิลรองรับให้ตรวจสอบทั้งหมด (มีสถานะ `paid` ที่ไม่มี `sale_id` ให้ดูได้ในฐานข้อมูล)

## สิ่งที่ยืนยันไม่ได้จากเอกสาร (ต้องลองกับ sandbox)

- host ของ production และรูปแบบ `SCB_API_BASE_URL` ของ production
- วิธี HTTP ที่ถูกต้องของ inquiry (หัวข้อบอก GET แต่ตัวอย่าง curl ใช้ POST) และรหัสตอบกลับเมื่อ "ยังไม่พบรายการ"
- ว่าโปรไฟล์ร้านต้องส่ง `ref2` หรือไม่ (ตั้ง `SCB_TWO_REFERENCES=true` ถ้าต้องส่ง)

## เสร็จเมื่อ

- ทดสอบกับ SCB จำลองครอบคลุม สร้าง QR, ยืนยันด้วย poll, ยืนยันด้วย callback, callback ปลอมไม่ทำให้จ่ายสำเร็จ, ใช้ซ้ำไม่ได้, ยอดไม่ตรงไม่ได้, ข้ามสาขาไม่ได้
- ที่ไม่ตั้งค่า SCB ทุกอย่างทำงานเหมือนเดิม
- `openapi:check` ผ่านหลังบันทึก baseline
