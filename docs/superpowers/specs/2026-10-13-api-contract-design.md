# ปรับสัญญา API ก่อนเผยแพร่: เอกสารออกแบบ

- วันที่: 2026-10-13
- ชิ้นงานที่ 3 ใน `docs/superpowers/roadmap.md`
- branch: `ohmattpon/api-contract` (ซ้อนบน `ohmattpon/hexagonal-architecture`)

## เป้าหมาย

เปลี่ยนสัญญาของ API ในจุดที่แก้ทีหลังแล้วทำให้ผู้ใช้ API พัง ให้เสร็จก่อนมีผู้ใช้ภายนอก ชิ้นนี้ตั้งใจเปลี่ยนสัญญา จึงแก้ assertion ของการทดสอบ integration และบันทึก `test/openapi-baseline.json` ใหม่

## การเปลี่ยนแปลง

### 1. เส้นทางมีเลขรุ่น

ทุกเส้นทางย้ายจาก `/api/...` ไป `/api/v1/...` เอกสาร OpenAPI ยังอยู่ที่ `/openapi`

### 2. ข้อผิดพลาดเป็น RFC 9457 (Problem Details)

ทุกคำตอบที่เป็นข้อผิดพลาดมี `Content-Type: application/problem+json` และรูปร่าง:

| ช่อง | ค่า |
|---|---|
| `type` | `about:blank` |
| `title` | ชื่อมาตรฐานของสถานะ HTTP เป็นภาษาอังกฤษ เช่น `Conflict` |
| `status` | สถานะ HTTP เป็นตัวเลข เท่ากับสถานะของคำตอบ |
| `detail` | ข้อความสำหรับแสดงต่อผู้ใช้ (ข้อความเดิมในช่อง `message`) |
| `code` | รหัสคงที่สำหรับโปรแกรม ค่าเดิมทุกตัว |
| `errors` | มีเฉพาะข้อผิดพลาดการตรวจข้อมูล (422): รายการปัญหาของแต่ละช่อง |

ช่อง `message` เดิมถูกเอาออก ไม่คงไว้คู่กัน เพื่อไม่ให้มีสองช่องที่ความหมายเดียวกัน

### 3. รายการทุกชนิดคืนรูปร่างเดียวกัน

เส้นทางที่คืนรายการทั้งห้า (ผู้ใช้ หมวดหมู่ สินค้า รายการเคลื่อนไหวสต็อก บิลขาย) คืน `{ items, total }` แทนอาร์เรย์เปล่า

- `total` คือจำนวนทั้งหมดที่ตรงตัวกรอง ไม่ใช่จำนวนใน `items`
- สินค้า รายการเคลื่อนไหว และบิลขาย รับ `limit` และ `offset` (สองตัวหลังเพิ่ม `offset`)
- ผู้ใช้และหมวดหมู่คืนทั้งหมดเสมอ `total` จึงเท่ากับจำนวนใน `items` การเพิ่มการแบ่งหน้าภายหลังไม่เปลี่ยนรูปร่างคำตอบ

### 4. ยอดเงินที่เกินช่วงเป็นข้อผิดพลาดของผู้เรียก

บรรทัดขายหรือยอดรวมที่เกิน 2,147,483,647 สตางค์ ตอบ 400 `AMOUNT_TOO_LARGE` พร้อมข้อความ "ยอดเงินเกินกว่าที่ระบบรองรับ" แทน 500 กฎอยู่ใน `SaleEntity.complete` การทดสอบที่ปักด้วย `test.failing` เปลี่ยนเป็น `test`

## สิ่งที่อยู่นอกขอบเขต

- เปลี่ยนชื่อช่องของข้อมูลที่สำเร็จ หรือเปลี่ยนสถานะ HTTP ของกรณีใด
- cursor pagination, การเรียงลำดับที่เลือกได้
- การรองรับ `/api` แบบเดิมคู่กับ `/api/v1` (ยังไม่มีผู้ใช้ภายนอก)

## ผลกระทบ

- หน้าเว็บ: client ชี้ `/api/v1`, อ่านข้อความข้อผิดพลาดจาก `detail`, อ่านรายการจาก `items`
- โครงทดสอบ: client และการล็อกอินชี้ `/api/v1`
- port ของ repository ที่คืนรายการแบบแบ่งหน้าคืน `Page<T>` (`{ items, total }`) จาก `domains/page.ts`

## เกณฑ์ว่าเสร็จ

- การทดสอบทั้งหมดผ่าน โดย assertion ของข้อผิดพลาดตรวจช่อง `detail` และของรายการตรวจผ่าน `items`
- มีการทดสอบใหม่: หัว `Content-Type` และรูปร่างครบของ problem details, `total` ที่มากกว่าจำนวนใน `items` เมื่อใช้ `limit`, `offset` ของบิลขายและรายการเคลื่อนไหว, เส้นทาง `/api/...` แบบเดิมตอบ 404
- typecheck, lint, build ของหน้าเว็บผ่าน และกฎของชั้นยังผ่าน
- เปิดหน้าเว็บในเบราว์เซอร์แล้วใช้งานได้
