# จอลูกค้าที่เคาน์เตอร์

สถานะ: ร่างสำหรับตรวจ · งานเพิ่มเติม (ไม่อยู่ใน roadmap เดิม) · branch `ohmattpon/customer-display` (แตกจาก `main`)

## เป้าหมาย

ลูกค้าที่เคาน์เตอร์เห็นสิ่งที่กำลังขายและยอดที่ต้องจ่ายบนจอที่สองของเครื่องแคชเชียร์เครื่องเดียวกัน และสแกน QR ชำระ PromptPay จากจอนั้นได้ โดยไม่ต้องมองจอของแคชเชียร์

## ขอบเขต

อยู่ในงานนี้:

- หน้า `/customer` แบบอ่านอย่างเดียว แสดงสี่สถานะ: ว่าง, กำลังขาย, ชำระเงิน, ชำระแล้ว
- ส่งสถานะจากหน้าขายไปหน้า `/customer` ในเบราว์เซอร์เดียวกัน ไม่ผ่านเซิร์ฟเวอร์
- เมนู "จอลูกค้า" ในหน้าขายสำหรับเปิดหน้าต่าง

อยู่นอกงานนี้:

- อุปกรณ์แยกเครื่อง (แท็บเล็ต จอของเครื่องอื่น) ซึ่งต้องส่งผ่านเซิร์ฟเวอร์ มีการจับคู่และสิทธิ์
- ลูกค้าสั่งเองจากมือถือ
- ลูกค้ากดหรือกรอกอะไรบนจอ สไลด์โฆษณา เสียง รูปสินค้า สีแบรนด์ของร้าน
- การเปลี่ยนสัญญา API ฐานข้อมูล หรือ `calculateTotals`

## การตัดสินใจ

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| ชนิดของจอ | จอที่สองของเครื่องเดียวกับแคชเชียร์ | เจ้าของเลือก ทำได้เร็วและเสี่ยงน้อยที่สุด |
| การส่งข้อมูล | `BroadcastChannel` ชื่อ `easypos-customer-display` | ไม่ผ่านเซิร์ฟเวอร์ ไม่มีข้อมูลค้างในเครื่อง (ต่างจาก `localStorage`) และเปิดจอลูกค้าเองหรือหลังรีเฟรชได้ (ต่างจาก `postMessage` ผ่าน `window.open`) |
| ผู้ส่ง | หน้าขาย ส่ง "สถานะที่คำนวณแล้ว" ไม่ใช่ข้อมูลดิบ | ยอดที่ลูกค้าเห็นเป็นยอดเดียวกับที่แคชเชียร์เห็นเสมอ (`calculateTotals` ตัวเดียว) และจอลูกค้าไม่ต้องรู้จักสินค้า ราคา หรือภาษี |
| การล็อกอิน | `/customer` อยู่นอกประตูล็อกอินของ `App` ไม่เรียก API | ถ้า session แคชเชียร์หมดอายุ ลูกค้าไม่เห็นหน้าล็อกอิน และหน้านี้ไม่มีข้อมูลให้ดึงเกินที่หน้าขายส่งมา |
| ภาษาและสกุลเงิน | ตามที่ส่งมาในสถานะ (`locale`, `currency`) | จอลูกค้าไม่เรียกการตั้งค่าร้าน |

## 1) สิ่งที่ลูกค้าเห็น

| สถานะ | แสดง |
|---|---|
| ว่าง | ชื่อร้านตัวใหญ่ตรงกลางและข้อความต้อนรับ |
| กำลังขาย | รายการ (ชื่อ ตัวเลือก จำนวน ราคาต่อบรรทัด), รวม, ส่วนลด (ถ้ามี), ภาษีมูลค่าเพิ่ม (ถ้ามี), ยอดสุทธิตัวใหญ่ที่สุด รายการล่าสุดเลื่อนให้เห็นเสมอ |
| ชำระเงิน | ยอดที่ต้องจ่าย ถ้าเลือก PromptPay และมี QR แสดง QR พร้อม "สแกนเพื่อชำระ" และเวลาหมดอายุ ถ้าเป็นช่องทางอื่นแสดงเฉพาะยอด รายการด้านซ้ายยังเห็นอยู่ |
| ชำระแล้ว | เครื่องหมายถูกสีเขียว "ชำระแล้ว ขอบคุณ" และเงินทอนถ้าจ่ายเงินสด แสดง 5 วินาทีแล้วกลับเป็นว่าง |

ไม่แสดงต้นทุน กำไร ชื่อแคชเชียร์ ยอดสต็อก หรือข้อมูลภายใน ข้อมูลที่ส่งมีเท่าที่อยู่บนใบเสร็จเท่านั้น

## 2) สถานะและข้อความ

ซองข้อความ (`v` คือรุ่นของรูปแบบ เริ่มที่ 1):

```ts
interface DisplayEnvelope {
  v: 1
  /** สร้างใหม่ทุกครั้งที่หน้าขายโหลด */
  sessionId: string
  /** เพิ่มขึ้นทีละหนึ่งในแต่ละ session; จอลูกค้าทิ้งข้อความที่ seq ต่ำกว่าของ session เดียวกัน */
  seq: number
  /** เวลาที่ส่ง (ms) ใช้ตัดสินว่าเงียบเกินไป */
  at: number
  locale: 'th' | 'en'
  currency: string
  shopName: string
  state: DisplayState
}

type DisplayState =
  | { kind: 'idle' }
  | { kind: 'selling'; lines: DisplayLine[]; subtotalSatang: number; discountSatang: number; vatSatang: number; vatMode: 'inclusive' | 'exclusive' | 'none'; totalSatang: number }
  | { kind: 'paying'; lines: DisplayLine[]; totalSatang: number; qr: { image: string; expiresAt: string } | null }
  | { kind: 'paid'; totalSatang: number; changeSatang: number }

interface DisplayLine { name: string; options: string[]; quantity: number; lineTotalSatang: number }
```

- เงินเป็นจำนวนเต็มสตางค์เหมือนส่วนอื่นของระบบ จอลูกค้าจัดรูปแบบด้วย `createMoney(currency, locale)` ไม่ใส่ `฿` หรือหารเอง
- `image` คือ PNG แบบ base64 ที่ธนาคารตอบมา ใช้ตัวเดียวกับที่ `useQrPayment` ถืออยู่ ไม่สร้าง QR เพิ่ม
- จอลูกค้าตรวจทุกข้อความด้วยตัวตรวจที่เขียนเองใน `display-state.ts` (เว็บไม่มี `zod` เป็น dependency และไม่คุ้มที่จะเพิ่ม) ข้อความผิดรูปหรือเกินขนาดถูกทิ้งเงียบ ๆ และฟิลด์ที่ไม่รู้จักถูกตัดทิ้ง

กติกา:

1. หน้าขายส่งสถานะทุกครั้งที่ตะกร้า ส่วนลด หรือสถานะชำระเงินเปลี่ยน
2. จอลูกค้าเปิดขึ้นมาแล้วส่ง `hello` หน้าขายตอบด้วยสถานะล่าสุด
3. หน้าขายส่งซ้ำทุก 10 วินาที จอลูกค้าที่ไม่ได้รับอะไรเกิน 30 วินาทีกลับเป็นว่าง กันไม่ให้ตะกร้าของลูกค้าคนก่อนค้างอยู่เมื่อหน้าขายปิดหรือค้าง
4. หน้าขายส่ง `idle` ทันทีเมื่อ `pagehide` หรือออกจากระบบ (ตะกร้าถูกล้างอยู่แล้ว)
5. สถานะ `paid` หน้าขายเป็นผู้นับ 5 วินาทีแล้วส่ง `idle` เอง (ไม่ให้จอลูกค้านับ เพราะการส่งซ้ำทุก 10 วินาทีจะทำให้ "ชำระแล้ว" โผล่ซ้ำ)

## 3) โครงสร้างโค้ด (เว็บเท่านั้น)

feature ใหม่ `apps/web/src/features/customer-display`:

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/display-state.ts` | ชนิดข้อมูลข้างบน, ตัวตรวจข้อความ, `isStale(now, lastAt)` และการเลือกข้อความที่ใหม่กว่า (ฟังก์ชันล้วน) |
| `lib/channel.ts` | ตัวห่อ `BroadcastChannel`: `publish`, `subscribe`, `requestLatest` เป็น interface เพื่อสลับตัวจำลองในการทดสอบ |
| `hooks/use-customer-display-publisher.ts` | ฝั่งหน้าขาย: เก็บสถานะล่าสุด ส่งเมื่อเปลี่ยน ส่งซ้ำทุก 10 วินาที ตอบ `hello` และส่ง `idle` ตอน `pagehide` |
| `components/CustomerDisplayPage.tsx` | วาดสี่สถานะ |
| `locales.ts` | ข้อความของ feature (namespace `customerDisplay`, ไทยเป็นต้นแบบ) |
| `index.ts` | ส่งออก `CustomerDisplayPage`, `useCustomerDisplayPublisher`, `openCustomerDisplay` |

`pos` ใช้ `customer-display` ได้ แต่ `customer-display` ไม่ import จาก `pos` (ไม่วนกลับ ตามกฎของ feature)

ฝั่ง `pos` (แก้เล็กน้อย):

- `pos/lib/customer-display.ts`: ฟังก์ชันล้วนแปลง `PricedCart` เป็น `DisplayState` (ชื่อและตัวเลือกของบรรทัด ยอด ส่วนลด VAT) พร้อมไฟล์ทดสอบ
- `PosPage`: เรียก publisher ด้วยสถานะ "กำลังขาย" จาก `useCart()` ทั้งตะกร้าปกติและออเดอร์ค้าง
- `PaymentDialog`: ส่งสถานะ "ชำระเงิน" พร้อม QR จาก `useQrPayment` ที่มีอยู่
- ตอนขายสำเร็จ: ส่ง "ชำระแล้ว" พร้อมเงินทอนจากบิลที่ได้
- เมนูหน้าขายเพิ่ม "จอลูกค้า" เรียก `openCustomerDisplay()` ซึ่งเปิดหน้าต่างชื่อ `easypos-customer` ซ้ำหน้าต่างเดิมถ้ายังเปิดอยู่ ซ่อนเมนูถ้าเบราว์เซอร์ไม่มี `BroadcastChannel`

ฝั่ง `app`:

- `App`: ถ้าเส้นทางเป็น `/customer` ให้แสดง `CustomerDisplayPage` ก่อนการตรวจ `me` และ `setup` ไม่มี sidebar
- `i18n.ts`: เพิ่ม namespace `customerDisplay`
- ไม่แก้ API, OpenAPI baseline, ฐานข้อมูล หรือ `web.plugin` (ตัว fallback ของ SPA ตอบ `index.html` ให้เส้นทางที่ไม่ใช่ `/api` อยู่แล้ว)

## 4) หน้าตา

ออกแบบสำหรับจอแนวนอน 16:9 (1920×1080 ถึง 1366×768) ขนาดตัวอักษรปรับตามความสูงจอ จอแนวตั้งหรือแคบเรียงเป็นชั้นและยอดสุทธิอยู่ล่างสุด

- สองคอลัมน์ขณะขาย: รายการซ้าย (ประมาณ 60%) สรุปยอดขวา ตอนชำระ PromptPay คอลัมน์ขวาเปลี่ยนเป็น QR จัตุรัสบนพื้นขาว สูงประมาณครึ่งหนึ่งของจอ
- ตัวอักษรตาม `DESIGN.md` (Geist และ IBM Plex Sans Thai, น้ำหนัก 400/500/600, `tabular-nums`) ขนาดอ้างอิงที่ 1080p: แถวรายการ 36px, ยอดสุทธิ 96px, ข้อความกำกับ 24px
- พื้นหลัง `canvas` การ์ดสรุปสีขาว ยอดสุทธิสี `foreground` เขียวใช้กับ "ชำระแล้ว" เท่านั้น และมีเครื่องหมายถูกกับข้อความคู่เสมอ ไม่มีปุ่มสีส้มเพราะไม่มีปุ่ม
- ชื่อสินค้ายาวตัดที่สองบรรทัด รายการยาวเกินจอเลื่อนอัตโนมัติให้เห็นล่าสุดเสมอ ไม่แบ่งหน้า
- การเปลี่ยนสถานะเลือนเข้าเบา ๆ ปิดเมื่อผู้ใช้ตั้ง "ลดการเคลื่อนไหว"
- คลิกที่จอหนึ่งครั้งเพื่อเต็มจอ และซ่อนเคอร์เซอร์เมื่อไม่ขยับ 3 วินาที

## 5) ความปลอดภัย

- ช่องส่งใช้ได้เฉพาะ origin เดียวกันในเบราว์เซอร์เดียวกัน เว็บอื่นอ่านไม่ได้
- ข้อความมีเท่าที่อยู่บนใบเสร็จ ไม่มีข้อมูลภายใน ห้ามเพิ่มช่องข้อมูลภายในลง `DisplayState` (จะเขียนไว้ใน `DESIGN.md`)
- หน้า `/customer` ไม่เรียก API จึงไม่มีทางเป็นช่องทางเข้าถึงข้อมูลของร้าน
- รูป QR มาจากคำตอบที่หน้าขายถืออยู่แล้ว จอลูกค้าไม่ขอ QR เอง และไม่มีทางยกเลิกหรือสร้างซ้ำ

## 6) การทดสอบ

- หน่วย (`bun test`, ไม่ต้องมีฐานข้อมูล):
  - ตัวแปลง `PricedCart` → `DisplayState`: ตัวเลือก ส่วนลด VAT ทั้งสามโหมด ตะกร้าว่างเป็น `idle`
  - ตัวตรวจข้อความ: ปฏิเสธข้อความผิดรูป เกินขนาด ชนิดไม่รู้จัก และรุ่น `v` ที่ไม่ตรง และตัดฟิลด์ที่ไม่รู้จัก
  - `isStale`: เงียบเกิน 30 วินาทีเท่ากับว่าง
  - การเลือกข้อความ: ทิ้ง `seq` เก่าของ session เดียวกัน รับ session ใหม่ทันที
  - publisher กับ channel จำลอง: ส่งเมื่อเปลี่ยน ตอบ `hello` ส่ง `idle` ตอน `pagehide`
- เบราว์เซอร์จริง (`bun run e2e`): หน้า `/customer` ในแท็บที่สองของ context เดียวกัน เพิ่มสินค้าที่หน้าขายแล้วรายการและยอดขึ้น จ่ายเงินสดแล้วขึ้น "ชำระแล้ว" และหน้า `/customer` เปิดได้โดยไม่ล็อกอิน ต้องเปิด Docker (ฐานข้อมูล `pos_e2e`)
- ภาพหน้าจอ (`bun run screenshots`): สี่สถานะที่ 1366×768 และ 1920×1080 ตรวจด้วยตา
- เอกสาร: `DESIGN.md` เพิ่มหัวข้อ "จอลูกค้า" (สี่สถานะ ตัวอักษร และกฎห้ามข้อมูลภายใน) และ `docs/summary.md`
- ก่อนบอกว่าเสร็จ: `bun run typecheck` และ `bun run test` ผ่าน

## 7) ความเสี่ยงและข้อจำกัด

- ใช้ได้เฉพาะเบราว์เซอร์และโปรไฟล์เดียวกัน เปิดจอลูกค้าในเบราว์เซอร์อื่นหรือเครื่องอื่นจะเห็นแต่ "ว่าง"
- ถ้าหน้าขายถูกแช่แข็ง (แท็บถูกเบราว์เซอร์พักเมื่อไม่ได้โฟกัสนาน) การส่งซ้ำทุก 10 วินาทีอาจหยุด จอลูกค้าจะกลับเป็นว่างหลัง 30 วินาที ซึ่งปลอดภัยกว่าการค้างตะกร้าเก่า
- ค่า 5, 10, 30 วินาที และ 3 วินาทีของเคอร์เซอร์เป็นค่าคงที่ ยังไม่ให้ตั้งในหน้าตั้งค่า
- ทดสอบบนจอ 16:9 และเบราว์เซอร์ Chrome เท่านั้น ยังไม่ทดสอบกับจอสัมผัสหรือเบราว์เซอร์อื่น
