# ที่เก็บรูปสินค้าในเครื่อง

สถานะ: ร่างสำหรับให้เจ้าของโครงการตรวจ · roadmap ข้อ 13 · branch `ohmattpon/local-image-storage` (แตกจาก `ohmattpon/install-kit` เพราะต่อจากส่วน "ที่เก็บรูปเป็นของเลือกได้" ที่ทำไว้ในข้อ 14)

## เป้าหมาย

ร้านที่ติดตั้งด้วยชุดติดตั้งมีรูปสินค้าได้ทันทีโดยไม่ต้องมีบัญชี Cloudflare: รูปเก็บบนดิสก์ของเครื่องร้าน API เสิร์ฟให้เอง และเลือกใช้ R2 (Worker เดิม) หรือปิดรูปได้ด้วยการตั้งค่า

## สิ่งที่มีอยู่แล้ว

- port `IMediaStorage` (`isEnabled`, `urlFor`, `put`, `delete`) และ `WorkerMediaStorage` ที่ลงทะเบียนผ่าน factory ใน `shared.module.ts`
- use case `SetProductImageUseCase` ตั้งคีย์ `products/<id>/<uuid>.<jpg|png|webp>` ใหม่ทุกครั้งที่อัปโหลด (จึง cache ได้ตลอดไป) และ `RemoveProductImageUseCase`
- v2 `capabilities.imageStorage` (`enabled`/`disabled`) และเว็บซ่อนการอัปโหลดเมื่อปิด

ข้อ 13 จึงไม่แตะ use case หรือสัญญา API: เพิ่ม adapter ใหม่ เส้นทางเสิร์ฟรูป การเลือก adapter และการสำรอง

## การตัดสินใจ

| เรื่อง | ตัดสินใจ | เหตุผล |
|---|---|---|
| การเลือกที่เก็บ | ตัวแปร `MEDIA_STORAGE` = `local` \| `worker` \| `none` ถ้าไม่ตั้ง: มี `MEDIA_URL` และ `MEDIA_TOKEN` ครบ → `worker` ไม่งั้น → `local` | ร้านที่ใช้ R2 อยู่ไม่ต้องแก้อะไร ร้านใหม่ได้รูปเลยตามที่ roadmap กำหนด ("ค่าเริ่มต้นเก็บในเครื่อง") |
| ที่เก็บในเครื่อง | โฟลเดอร์ `MEDIA_DIR` (ค่าเริ่มต้น `./data/media` ตอนพัฒนา; ใน Docker คือ volume `pos-media` ที่ `/data/media`) | ข้อมูลอยู่นอก image จึงรอดการอัปเดต |
| URL ของรูป | `/media/<key>` แบบ relative บน origin เดียวกับแอป | ใช้ได้ทั้งหลัง Caddy, บน `localhost` และตอนพัฒนา ไม่ต้องรู้โดเมน |
| การเสิร์ฟ | `GET /media/*` สาธารณะ เหมือน Worker: ไม่ต้องล็อกอิน (รูปสินค้าไม่ใช่ความลับ และคีย์เดายาก) | `<img>` ส่ง cookie ได้อยู่แล้วแต่ไม่ควรผูกกับ session และ Worker ก็เปิดสาธารณะ |
| ความปลอดภัยของเส้นทางไฟล์ | คีย์ต้องตรงรูปแบบ `products/<เลข>/<uuid>.<jpg\|png\|webp>` ทั้งตอนเขียนและตอนอ่าน ไม่ตรงตอบ 404 / ปฏิเสธ | กัน `..` และการอ่านไฟล์นอกโฟลเดอร์ (ทดสอบแบบ mutation check เหมือน `web.plugin`) |
| ชนิดและขนาด | JPEG/PNG/WebP ไม่เกิน 5 MB เท่า Worker: adapter ปฏิเสธด้วย domain error (`INVALID_FILE_TYPE`, `IMAGE_TOO_LARGE`) | พฤติกรรมเหมือนกันทุกที่เก็บ |
| การเขียน | เขียนไฟล์ชั่วคราวแล้ว rename | ไม่เหลือไฟล์ครึ่งเดียวถ้าไฟฟ้าดับ |
| การลบ | ลบไฟล์ ถ้าไม่มีไฟล์ถือว่าสำเร็จ | use case ลบแบบ best effort อยู่แล้ว |
| การสำรอง | `backup` เพิ่มไฟล์ `easypos-<เวลา>.media.tar.gz` คู่กับ `.sql.gz` เมื่อใช้ที่เก็บในเครื่อง `restore` กู้รูปด้วยถ้าพบไฟล์คู่ | คู่มือเดิมบอกว่ารูปไม่อยู่ในไฟล์สำรอง ซึ่งไม่ควรเป็นจริงของที่เก็บในเครื่อง |
| ย้ายจาก R2 | ไม่ทำตัวย้ายรูปในรอบนี้ | ร้านที่เปลี่ยนที่เก็บต้องอัปโหลดรูปใหม่ ระบุในคู่มือ (รูปเก่าที่ URL หายจะแสดงเป็นไม่มีรูป ข้อมูลสินค้าไม่เสีย) |

## การทำงาน

- `LocalDiskMediaStorage` (`modules/shared/adapters`) implements `IMediaStorage`: `isEnabled()` เป็นจริงเสมอ, `urlFor(key)` คือ `/media/<key>`, `put` ตรวจชนิดกับขนาดแล้วเขียนแบบ atomic, `delete` ลบไฟล์
- ปลั๊กอิน `media.plugin.ts` (อ่านอย่างเดียว) เสิร์ฟ `GET`/`HEAD /media/*` จากโฟลเดอร์เดียวกัน พร้อม `Cache-Control: public, max-age=31536000, immutable`, `Content-Type` ตามนามสกุล, ETag และ 304 ลงทะเบียนก่อน `web.plugin` (ซึ่งต้องอยู่ท้ายสุด) และไม่ลงทะเบียนเมื่อที่เก็บไม่ใช่ `local`
- ปลั๊กอินนี้อยู่นอก `/api/v1` ตั้งใจ เพื่อให้ URL ของรูปสั้นและตรงกับรูปแบบของ Worker (`/<key>`) ไม่ถือเป็นสัญญา API จึงไม่เข้า OpenAPI baseline
- `shared.module.ts` เลือก adapter จาก `MEDIA_STORAGE` ตามตารางด้านบน ค่าที่ไม่รู้จักทำให้โปรแกรมไม่เริ่มพร้อมข้อความชัดเจน (กันพิมพ์ผิดแล้วรูปหายเงียบ ๆ)
- `docker-compose.yml`: volume `pos-media` ที่ `/data/media` (และ `MEDIA_DIR=/data/media`); `install.sh` ไม่ต้องเขียนอะไรเพิ่ม
- เว็บตอนพัฒนา: เพิ่ม `'/media': apiTarget` ใน proxy ของ Vite เพื่อให้ URL แบบ relative ใช้ได้

## ไม่ทำในรอบนี้

- ตัวย้ายรูประหว่าง R2 กับดิสก์
- ปรับขนาดรูปหรือทำ thumbnail (ยังเสิร์ฟไฟล์ตามที่อัปโหลด จำกัด 5 MB)
- S3 หรือที่เก็บอื่นนอกจาก R2 (เพิ่ม adapter ใหม่หลัง port เดิมได้ภายหลังโดยไม่แตะ use case)

## การทดสอบ

- `LocalDiskMediaStorage`: เขียนแล้วอ่านกลับได้, ชนิดผิด/ใหญ่เกินถูกปฏิเสธและไม่สร้างไฟล์, คีย์นอกรูปแบบ (`../x`, ตัดเป็นหลายชั้น) ถูกปฏิเสธ, ลบไฟล์ที่ไม่มีไม่ล้ม, ไม่มีไฟล์ `.tmp` ค้างเมื่อเขียนล้ม
- `media.plugin`: 200 พร้อม header ที่ถูก, 304 เมื่อ ETag ตรง, 404 ของไฟล์ที่ไม่มีและของคีย์ที่ไม่ตรงรูปแบบ (รวม `..` ที่เข้ารหัส) โดยตรวจว่า traversal guard ถูกจริงด้วย mutation check
- ตัวเลือก adapter: ตั้งไม่ครบ/ตั้งครบ/`none`/ค่าไม่รู้จัก
- integration: อัปโหลดรูปสินค้า แล้ว `GET imageUrl` ได้ไบต์เดิม, ลบรูปแล้ว 404, `capabilities.imageStorage` เป็น `enabled`
- e2e: อัปโหลดรูปจากฟอร์มสินค้า รูปแสดงในหน้าขาย และอยู่หลัง reload
- ลองจริงด้วย Docker: อัปโหลดรูป, `down` แล้ว `up` รูปยังอยู่, backup → ลบรูป → restore แล้วรูปกลับมา
