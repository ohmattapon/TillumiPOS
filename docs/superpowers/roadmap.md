# TillumiPOS Roadmap

ปรับปรุงล่าสุด: 2026-10-14 (เพิ่มงานรายงานย้อนหลังตามการใช้งานจริง)

## งานที่เพิ่มตามการใช้งานจริง

งานรายงานย้อนหลังบน branch `ohmattpon/sales-reports` มีช่วงวัน ยอดขายและกำไร สินค้าขายดี เปรียบเทียบสาขา และส่งออก Excel แล้ว รายละเอียดและนิยามตัวเลขอยู่ใน [รายงานย้อนหลัง](../sales-reports.md)

## เป้าหมาย

POS แบบ open source ที่ร้านอื่นนำไปติดตั้งใช้เองได้

- รองรับทั้งร้านค้าปลีกและร้านอาหารในรุ่นแรก
- ชุด Docker เดียวกันรันได้ทั้งบนเครื่องในร้านและบนคลาวด์
- ไทยก่อน แต่ข้อความ สกุลเงิน และอัตราภาษีแยกออกจากโค้ด เพื่อเพิ่มภาษาอื่นได้โดยไม่รื้อ

## วิธีทำงาน

แต่ละชิ้นงานผ่านหนึ่งรอบ: spec (`docs/superpowers/specs/`) → แผนลงมือทำ (`docs/superpowers/plans/`) → ลงมือทำ
ชิ้นถัดไปเริ่มเมื่อชิ้นก่อนหน้าใช้งานได้และทดสอบผ่าน กฎการทำงานอยู่ใน `AGENTS.md`

## ช่วงที่ 1: แกนที่แก้ทีหลังแพง

| # | ชิ้นงาน | เหตุผลของลำดับ | เสร็จเมื่อ | สถานะ |
|---|---|---|---|---|
| 1 | ชุดทดสอบอัตโนมัติของการขายและสต็อก พร้อม CI | ทุกชิ้นหลังจากนี้แก้โค้ดส่วนเงินและสต็อก | ทดสอบรันกับ PostgreSQL จริงด้วยคำสั่งเดียว และรันทุกครั้งที่ push | เสร็จในเครื่องบน branch `test-suite-ci` (70 กรณี) รอเจ้าของโครงการ push และ merge |
| 2 | ย้ายโครงสร้าง API เป็น Hexagonal | ยิ่งมีโค้ดมาก การย้ายยิ่งแพง และฟีเจอร์ถัดไปควรเขียนบนโครงใหม่ตั้งแต่ต้น | การทดสอบของชิ้นที่ 1 ผ่านครบโดยไม่แก้ assertion และไม่เหลือ `service.ts` | เสร็จในเครื่องบน branch `ohmattpon/hexagonal-architecture` (333 กรณีทดสอบ) รอเจ้าของโครงการ push และ merge |
| 3 | ปรับสัญญา API ก่อนเผยแพร่ | เปลี่ยนสัญญาหลังมีผู้ใช้คือการทำของคนอื่นพัง | ข้อผิดพลาดเป็น RFC 9457 โดยคงช่อง `code`, รายการคืนพร้อมข้อมูลแบ่งหน้า, เส้นทางอยู่ใต้ `/api/v1` | เสร็จในเครื่องบน branch `ohmattpon/api-contract` รอเจ้าของโครงการ push และ merge |
| 4 | การตั้งค่าร้านและโครงรองรับหลายภาษา | VAT เขตเวลา และข้อความไทยฝังอยู่ในโค้ด | ชื่อร้าน เลขผู้เสียภาษี สกุลเงิน อัตราและวิธีคิดภาษีตั้งได้จากหน้าเว็บ ข้อความทั้งหมดอยู่ในไฟล์ภาษา | เสร็จในเครื่องบน branch `ohmattpon/shop-settings` (ไทย/อังกฤษ, THB และสกุลอื่น, VAT รวม/แยก/ไม่คิด, เก็บกติกาภาษีไว้กับแต่ละบิล) รอเจ้าของโครงการ push และ merge |
| 5 | โครงสร้างสาขา | แก้ตารางตอนยังไม่มีข้อมูลจริงถูกที่สุด | สต็อก บิล เลขใบเสร็จ และผู้ใช้ผูกกับสาขา | เสร็จในเครื่องบน branch `ohmattpon/branches` (สต็อกแยกสาขา เลขใบเสร็จ `<รหัส>-วันที่-เลขที่` ตัวสลับสาขาและหน้าจัดการสาขา) หน้าจัดการผู้ใช้ทำในข้อ 11 รอเจ้าของโครงการ push และ merge |
| 6 | ออเดอร์ค้างและจ่ายทีหลัง | ร้านอาหารต้องเปิดออเดอร์ เพิ่มรายการ แล้วค่อยจ่าย ซึ่งเปลี่ยนโครงสร้างการขาย | เปิดออเดอร์ค้าง เพิ่มและลบรายการ แล้วชำระได้ โดยการขายแบบค้าปลีกยังทำได้ในขั้นตอนเดียว | เสร็จในเครื่องบน branch `ohmattpon/open-orders` (ออเดอร์เป็น aggregate แยก ชำระผ่านตัวคิดเงินเดียวกับการขายปกติ) รอเจ้าของโครงการ push และ merge |

## ช่วงที่ 2: ร้านอาหาร

| # | ชิ้นงาน | เสร็จเมื่อ |

## ช่วงที่ 3: พร้อมเผยแพร่

| # | ชิ้นงาน | เสร็จเมื่อ |
|---|---|---|
| 10 | กะและเงินสดในลิ้นชัก | เปิดกะ ปิดกะ นับเงิน และเห็นส่วนต่าง (เสร็จฝั่งโค้ดบน branch `ohmattpon/cash-shifts` รอทดสอบในเบราว์เซอร์และรอเจ้าของโครงการ push/merge; เปิดใช้ด้วย `CHECKOUT_MODE=shifts`) |
| 11 | ใบเสร็จ การพิมพ์ และหน้าจัดการที่ขาด | พิมพ์ใบกำกับภาษีอย่างย่อออกเครื่องพิมพ์ thermal ได้ มีหน้าผู้ใช้และหมวดหมู่ (เสร็จฝั่งโค้ดบน branch `ohmattpon/receipts-users-categories`: หน้าผู้ใช้ หน้าหมวดหมู่ หัวใบเสร็จเก็บลงบิล ใบกำกับภาษีอย่างย่อ ข้อความท้ายใบ และ CSS พิมพ์ 58/80 มม. ยังไม่ได้พิมพ์ออกเครื่อง thermal จริง และ) |
| 12 | สิทธิ์ละเอียดและบันทึกการกระทำ | กำหนดสิทธิ์รายฟังก์ชันได้ และดูประวัติการแก้ราคา ปรับสต็อก ยกเลิกบิลได้ |
| 13 | ที่เก็บรูปแบบเลือกได้ | ค่าเริ่มต้นเก็บในเครื่อง และเลือกใช้ R2 ได้ด้วยการตั้งค่า (เสร็จฝั่งโค้ดบน branch `ohmattpon/local-image-storage` ต่อจาก `ohmattpon/install-kit`: `MEDIA_STORAGE` = `local` | `worker` | `none` รูปในเครื่องเสิร์ฟที่ `/media` และอยู่ใน volume ของ Docker พร้อมสำรองและกู้คืนคู่กับฐานข้อมูล ไม่มีตัวย้ายรูประหว่างที่เก็บ และไม่ปรับขนาดรูป) |
| 14 | ชุดติดตั้ง | ติดตั้งด้วยคำสั่งเดียว มีหน้าตั้งค่าครั้งแรกแทนบัญชีเริ่มต้น สำรองและกู้คืนข้อมูลได้ มีเอกสารและใบอนุญาต ไม่มีความลับใน repo (เสร็จฝั่งโค้ดบน branch `ohmattpon/install-kit`: Docker Compose ติดตั้งด้วย `scripts/install.sh` หน้าตั้งค่าครั้งแรกด้วยรหัสที่พิมพ์ใน log สำรองและกู้คืน `docs/install.md` ใบอนุญาต AGPL-3.0 และชุดทดสอบตรวจความลับ ติดตั้งแล้วรันได้โดยไม่มีที่เก็บรูป จนกว่าจะทำข้อ 13 ยังไม่มีการรีเซ็ตรหัสผ่านเจ้าของร้านและไม่ได้ลองรัน `install.ps1` บน Windows จริง) |

## หลังรุ่นแรก

ลำดับกำหนดตามเสียงผู้ใช้: จัดซื้อและโอนสินค้าระหว่างสาขา, รายงานย้อนหลัง, โปรโมชัน, ชำระเงินอัตโนมัติ (QR ของ SCB ที่ยืนยันยอดเอง เครื่องรูดบัตร), สมาชิกและแต้ม, ขายได้เมื่อเน็ตหลุดพร้อมซิงก์, e-Tax Invoice และเชื่อมระบบบัญชี

การชำระด้วย QR ของ SCB (Thai QR Tag 30 พร้อมยืนยันยอดเอง) ทำแล้วบน branch `ohmattpon/scb-qr-payment` ส่วนเครื่องรูดบัตรและรายการอื่นยังไม่ทำ ค่า `SCB_*` อยู่ใน `.env` ของเจ้าของโครงการ ห้ามอยู่ใน `.env.example`

## ทางเลือกลดขอบเขต

ถ้าต้องการออกรุ่นแรกเร็วขึ้น ให้ออกรุ่นค้าปลีกก่อน (ข้ามชิ้นที่ 7–9) รุ่นแรกจะเหลือ 11 ชิ้น
ชิ้นที่ 6 ยังควรทำก่อนเผยแพร่ เพราะเปลี่ยนโครงสร้างข้อมูลการขาย
