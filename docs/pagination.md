# การแบ่งหน้ารายการ

รายการที่โตตามการขายโหลดทีละหน้าจาก API ส่วนแค็ตตาล็อกขนาดเล็กที่ใช้ประกอบตัวเลือกหลายหน้าจออ่านครบแล้วแบ่งเฉพาะการแสดงผล

| รายการ | ต่อหน้า | วิธีโหลด |
|---|---:|---|
| สินค้าและสต็อก | 20 | API: ค้นหาและกรองก่อนแบ่งหน้า |
| สินค้าบนหน้าขาย | 24 | API: ค้นหาและเลือกหมวดก่อนแบ่งหน้า |
| บิลวันนี้ | 20 | API: กรองสถานะก่อนแบ่งหน้า |
| สต็อกใกล้หมดบนหน้าวันนี้ | 8 | API: เรียงยอดสต็อกน้อยก่อน |
| ออเดอร์เปิดและออเดอร์ที่จะรวมบิล | 10 | API: เลือกเฉพาะออเดอร์ที่ใช้ได้ |
| ออเดอร์ของโต๊ะที่เลือก | 5 | API: กรองโต๊ะก่อนแบ่งหน้า |
| รายการเงินในกะ | 20 | API |
| ประวัติกะ | 10 | API: กรองเครื่องขายและสถานะ |
| QR ที่ยังไม่ทราบผล และเงินเข้าที่ยังไม่มีบิล | 10 | API: แบ่งหน้าแยกกัน |
| เงิน QR ที่นำมาใช้ชำระได้ | 5 | API: กรองยอดตรงกับยอดชำระก่อนแบ่งหน้า |
| หมวดหมู่ ผู้ใช้ สาขา และเครื่องขาย | 20 | แบ่งการแสดงผลจากแค็ตตาล็อกที่อ่านครบ |
| กลุ่มตัวเลือกเสริม | 5 | แบ่งการแสดงผล |
| ตัวเลือกในแต่ละกลุ่ม | 20 | แบ่งการแสดงผล |

ผังโต๊ะแสดงทั้งผังเพื่อรักษาความหมายของตำแหน่ง ตะกร้า รายการในใบเสร็จ และตัวเลือกในฟอร์มแสดงครบตามรายการที่กำลังทำงานอยู่

## การใช้งาน

- แถบแบ่งหน้ามีหน้าแรก ก่อนหน้า ถัดไป และหน้าสุดท้าย พร้อมช่วงรายการและจำนวนทั้งหมด ซ่อนเมื่อมีหน้าเดียว
- เปลี่ยนตัวกรอง คำค้น หรือสาขาแล้วเริ่มที่หน้าแรก หากรายการในหน้าสุดท้ายหมดหลังเปลี่ยนสถานะ ระบบถอยกลับไปหน้าที่มีอยู่
- ระหว่างโหลดปิดปุ่มเปลี่ยนหน้า ไม่ใช้ข้อมูลของหน้าก่อนหน้าแทนหน้าที่กำลังโหลด
- การพิมพ์ค้นหาสินค้ารอให้หยุดพิมพ์ 200 มิลลิวินาที การกด Enter จากเครื่องสแกนค้นหาได้ทันทีโดยไม่จำกัดหน้าหรือหมวดที่กำลังดู
- ตะกร้าอ่านรายละเอียดเฉพาะสินค้าที่เลือกผ่าน query แยกจากรายการสินค้า การเปลี่ยนหน้าจึงไม่เปลี่ยนสิ่งที่เลือกไว้ ปิดการชำระและพักออเดอร์เมื่อรายละเอียดสินค้าอ่านไม่ครบหรือสินค้าปิดการขาย
- ตัวนับบิล ออเดอร์ สินค้า และสต็อกใกล้หมดใช้ `total` จาก API ไม่ใช้จำนวนแถวในหน้าปัจจุบัน ยอดขายสรุปยังอ่านจาก summary ของทั้งวัน

## สัญญา API

ทุกเส้นทางยังคืน `{ items, total }` และใช้ `limit` กับ `offset` ตามเดิม เพิ่มเฉพาะตัวกรอง optional:

| เส้นทาง | ตัวกรองใหม่ |
|---|---|
| `GET /api/v1/catalog/products/` | `code` สำหรับบาร์โค้ดหรือ SKU ตรงตัว, `isActive`, `stockAtMost`, `sort=name\|stock` |
| `GET /api/v1/sales/` | `status=completed\|voided` |
| `GET /api/v1/orders/` | `tableId`, `excludeId` |
| `GET /api/v2/payments/qr/unclaimed` | `amountSatang` |

เมื่อไม่ส่งตัวกรองใหม่ พฤติกรรมเดิมยังคงอยู่ `isActive` ที่ระบุชัดเจนมีผลเหนือค่าเริ่มต้นของ `includeInactive` สต็อกและออเดอร์ทุกคำขอยังคงจำกัดตามสาขาที่ได้รับอนุญาต

สินค้าเรียงชื่อแล้วตาม id เพื่อให้ชื่อซ้ำไม่สลับหน้า การอ่านแบบ offset เป็นข้อมูลปัจจุบัน ไม่ใช่ snapshot: การเพิ่มหรือเปลี่ยนข้อมูลจากเครื่องอื่นระหว่างเปิดหน้าสามารถเปลี่ยนตำแหน่งรายการได้

OpenAPI v1 baseline ปรับให้ตรงกับเส้นทางโต๊ะและออเดอร์ที่มีอยู่บน main ก่อนงานนี้ด้วย v2 เปลี่ยนเฉพาะ query parameter ของรายการเงิน QR

แนวทาง SQL อ้างอิง [Drizzle: limit, offset และ order by](https://orm.drizzle.team/docs/select#limit--offset)

## การตรวจงาน

งานนี้ตรวจด้วย typecheck, lint, production build และ OpenAPI check ไม่มีการเปลี่ยน schema ฐานข้อมูลหรือข้อมูลร้าน ยังไม่ได้รันชุดทดสอบอัตโนมัติหรือทดลองการแบ่งหน้าในเบราว์เซอร์
