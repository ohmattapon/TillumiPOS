# โหมดโชว์หน้าตาโดยไม่รัน server (demo-static)

เปิดเว็บ TillumiPOS ดูได้ทุกจอโดยไม่ต้องรัน API และไม่มีฐานข้อมูลเลย
ข้อมูลทั้งหมดเป็นข้อมูลสมมติในเบราว์เซอร์ ตอบโดย Mock Service Worker (msw)

## วิธีรัน

```bash
bun run demo:static
```

แล้วเปิด URL ที่ Vite แสดง (ปกติ `http://localhost:5173`)

## เข้าใช้งาน + PIN

- หน้า login ใส่อะไรก็ได้ กดเข้าได้เลย (ล็อกอินเป็นเจ้าของร้านเสมอ)
- สลับผู้ขายด้วย PIN (เมนูบัญชี → สลับผู้ขาย):
  - เจ้าของร้าน (`owner`) PIN `1111`
  - พนักงานขาย (`cashier`) PIN `1234`
- เปลี่ยนภาษาได้ที่ตั้งค่าร้าน (ไทย/English) มีผลทันทีโดยไม่ต้องรีโหลด

## ทำอะไรได้บ้าง

- ดูได้ทุกจอ: ขาย, บิลวันนี้, รายงาน, สินค้า, ใบรับของ, หมวด, ตัวเลือก, โต๊ะ, ทีมงาน, ตั้งค่า, ประวัติการใช้งาน, สมาชิก, โปรโมชัน, สไลด์จอลูกค้า, กะ
- กดบันทึก/ขาย/void/รับของ/ปรับสต็อก ตอบสำเร็จเหมือนจริง
  - สต็อกเปลี่ยนตามจริงใน session (รับของแล้วตัวเลขเพิ่ม เปิดดูหน้าสินค้าได้)
  - ประวัติการใช้งาน (audit) เพิ่มรายการตามที่กดจริง
  - รายงานคำนวณจากบิลเดียวกับที่หน้า "บิลวันนี้" แสดง
  - ปุ่ม export รายงานดาวน์โหลดไฟล์ Excel จริง (สร้างในเบราว์เซอร์)
- กฎสำคัญยังตอบเหมือน server:
  - สร้างสาขาเพิ่มไม่ได้ (`SINGLE_BRANCH_ONLY`) ปิดสาขา MAIN ไม่ได้
  - ลบบทบาทระบบ (เจ้าของร้าน/พนักงานขาย) ไม่ได้ ลบบทบาทที่มีคนใช้อยู่ไม่ได้
  - ถอดบทบาทเจ้าของออกจากเจ้าของคนสุดท้ายไม่ได้ (`LAST_OWNER`)
  - PIN ผิดตอบ `PIN_INVALID` (ไม่หลุดล็อกอิน)
- จอลูกค้า (`/customer`): เปิดอีกแท็บในเบราว์เซอร์เดียวกันแล้วขายของ
  ยอดจะตามไปโชว์ผ่าน BroadcastChannel เดิม (ไม่ต้องทำอะไรเพิ่ม)

## อะไรไม่จริงบ้าง (ปลอมเพื่อโชว์)

- รีเฟรช = เริ่มใหม่ทั้งหมด (รวมล็อกอินและภาษา) เพราะข้อมูลอยู่ใน memory ของหน้าเว็บ
- QR พร้อมเพย์จากธนาคาร: กดขอแล้วตอบ "จ่ายแล้ว" สมมติเสมอ ไม่ได้คุยกับธนาคารจริง
- อัปโหลดรูป: ตอบสำเร็จพร้อมรูปตัวอย่างในเครื่อง (`public/demo/`) ไม่ได้เก็บไฟล์ที่เลือกจริง
- จอลูกค้าข้ามเครื่องไม่ได้ (ใช้ได้เฉพาะแท็บในเบราว์เซอร์เดียวกัน)
  รหัสจับคู่/สตรีมของ server ใช้ไม่ได้ในโหมดนี้ (EventSource ผ่าน MSW ไม่ได้)
- ตัวเลขรายงานคำนวณแบบง่ายจากบิลสมมติ ไม่ใช่สูตรบัญชีจริง
- ข้อมูลทั้งหมดเป็นเรื่องแต่ง (ร้านกาแฟบ้านสวน) ห้ามเข้าใจว่าเป็นยอดจริง

## อยากได้ logic จริง

ใช้ demo-memory mode (รัน API ด้วยฐานข้อมูลในหน่วยความจำ) ซึ่งใช้ use case
ของจริง ดูวิธีรันใน `docs/` ของโหมดนั้น

## หมายเหตุสำหรับคนทำต่อ

- `src/main.tsx` รอ worker พร้อมก่อน render เฉพาะโหมดนี้ เพื่อไม่ให้ query
  แรกหลุดไปโดน API จริง (เช่นตอนมี dev server รันอยู่ที่ `:3000`)
- `vite.config.ts` ไม่ตั้ง proxy เลยเฉพาะโหมดนี้ ด้วยเหตุผลเดียวกัน
  (EventSource ของจอลูกค้าไม่ผ่าน MSW เลยตอบสตรีมตัวอย่างเงียบ ๆ
  จาก dev server เองผ่านปลั๊กอิน `demo-static-customer-stream`
  ซึ่งทำงานเฉพาะ `serve` ในโหมดนี้เท่านั้น)
- เจอ race ในแอปจริง (ไม่ได้แก้ เพราะ `src/` ห้ามเปลี่ยนในงานนี้):
  `downloadReportWorkbook` revoke object URL หลัง 1 วินาที ไฟล์อาจโหลดไม่ทัน
  บนเครื่องช้า/เน็ตช้า ถ้าจะแก้ให้ revoke หลัง `link.click()` นานกว่านี้
  หรือเมื่อ download เสร็จ
