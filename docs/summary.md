# สรุปงานที่ทำ: TillumiPOS

สรุป ณ วันที่ 19 ตุลาคม 2026 · เขียนจากสถานะของ repo จริง (`main` ถึง #74 กับงานพิมพ์ LAN บน PR #75 ที่ยังไม่ merge) ดูรายละเอียดเชิงลึกของแต่ละเรื่องในโฟลเดอร์ `docs/superpowers/specs` (เอกสารมีวันที่คือบันทึกประวัติ ไม่แก้ย้อนหลัง)

## ภาพรวม

TillumiPOS คือ POS แบบโอเพนซอร์สที่ติดตั้งใช้เองได้ รองรับทั้งร้านค้าปลีกและร้านอาหาร เริ่มที่ประเทศไทย (ภาษาไทยเป็นหลัก มีอังกฤษด้วย) ติดตั้งในเครื่องร้านด้วย Podman และรันบนคลาวด์ได้

| ส่วน | เทคโนโลยี |
|---|---|
| API (`server/`) | Bun, Elysia, Drizzle, PostgreSQL, tsyringe, zod สถาปัตยกรรม Hexagonal + CQRS |
| เว็บ (`src/`) | React 19, Vite, Tailwind, shadcn/ui, TanStack Query, zustand, react-router, i18next |
| รูป (`workers/media`) | Cloudflare Worker + R2 เก็บรูปสินค้า |

## ความสามารถที่มีตอนนี้

**การขาย**
- ขายขั้นตอนเดียว: เลือกสินค้า ใส่ส่วนลด ชำระ (เงินสด/พร้อมเพย์/บัตร) พร้อมคำนวณเงินทอน
- เลขใบเสร็จไม่มีช่องว่าง รูปแบบ `MAIN-yyyymmdd-nnnnn` นับแยกตามวัน ร้านมีสาขาเดียว
- ยกเลิกบิล (เจ้าของร้าน) คืนสต็อกเข้าสาขาของบิลนั้น บิลแก้/ลบไม่ได้
- VAT 3 แบบ: รวมในราคา, บวกเพิ่ม, ไม่คิด เก็บกติกาภาษีไว้กับแต่ละบิล แก้ตั้งค่าทีหลังไม่กระทบบิลเก่า
- จำนวนเงินเก็บเป็นจำนวนเต็มหน่วยเล็กสุด (สตางค์) เสมอ

**รายงานย้อนหลัง (เจ้าของร้าน)**
- เลือกช่วงวันรวมวันเริ่มและวันสิ้นสุดได้สูงสุด 366 วัน ครอบคลุมสาขาเดียวของร้าน (`MAIN`) ตารางเปรียบเทียบสาขาแสดงสาขาที่ขายในช่วงนั้น
- สรุปยอดขาย กำไรขั้นต้นหลังหัก VAT และต้นทุน ณ ตอนขาย ช่องทางชำระเงิน กราฟรายวัน และสินค้าขายดี
- ส่งออก Excel ครบทุกหน้าของตาราง 5 ชีต: สรุป รายวัน สินค้า สาขา การชำระเงิน
- รายงานใช้สถานะบิลปัจจุบัน ไม่ใช่ snapshot ปิดกะ ดูนิยามตัวเลขใน `docs/sales-reports.md`

**ออเดอร์ค้าง (ร้านอาหาร)**
- เก็บตะกร้าเป็นออเดอร์ เพิ่ม/ลด/ลบรายการ ทำต่อจากรายการ แล้วชำระทีหลัง
- ราคา ณ ตอนสั่งถูกเก็บไว้ ชำระตามราคานั้น สต็อกตัดตอนชำระ
- ชำระผ่านตัวคิดเงินเดียวกับการขายปกติ จึงได้บิลธรรมดา

**สินค้าและสต็อก**
- สินค้า หมวดหมู่ รูปสินค้า (เก็บในเครื่อง หรือ R2 ตามที่ตั้ง) รับสินค้าเข้า ปรับยอดนับจริง ประวัติการเคลื่อนไหวแบบ append-only
- สต็อกแยกตามสาขา

**สาขาเดียว**
- ร้านมีสาขา `MAIN` สาขาเดียว ทุกคำขอทำงานในสาขานี้ ไม่มีหน้าจอสลับสาขาหรือจัดการสาขาในเว็บ (เส้นทาง API เดิมยังอยู่เพื่อไม่ให้ไคลเอนต์เก่าพัง แต่สร้างเพิ่มไม่ได้และปิด `MAIN` ไม่ได้)
- เลขใบเสร็จขึ้นต้นด้วย `MAIN`

**หน้าจอทุกขนาด (มือถือ แท็บเล็ต คอม)**
- มือถือ: แถบเมนูล่าง 4 ช่อง แถบตะกร้าล่างที่แตะเพื่อเปิดตะกร้าเต็ม ปุ่มการทำงานอื่นรวมในเมนูเดียว ตารางเป็นรายการ ผังโต๊ะเป็นรายการ
- แท็บเล็ตแนวตั้ง: sidebar เป็นแถบไอคอน ตารางแสดงคอลัมน์ที่จำเป็นเท่านั้น
- จอใหญ่: เหมือนเดิม sidebar กาง แผงตะกร้าขวา ผังโต๊ะลากได้

**การตั้งค่าร้านและภาษา**
- ชื่อร้าน เลขผู้เสียภาษี ที่อยู่ เบอร์โทร สกุลเงิน VAT เขตเวลา ภาษา
- เครื่องพิมพ์ใบเสร็จผ่านแลน: IP/พอร์ต เปิดพิมพ์ เปิดลิ้นชัก (ดู `docs/thermal-printer-setup.md`)
- ทุกข้อความอยู่ในไฟล์ภาษา ข้อผิดพลาดจาก API แปลตามรหัส

**ชำระด้วย QR ของ SCB**
- สร้าง QR ตามยอด รอธนาคารยืนยัน แล้วบันทึกบิลอัตโนมัติ
- ธนาคารเป็นแหล่งความจริงเดียว: callback ของ SCB ไม่มีลายเซ็น จึงใช้เป็นแค่สัญญาณให้ไปถาม SCB เอง
- หนึ่ง QR ใช้ได้หนึ่งบิล ยอดต้องตรงพอดี ต้องอยู่สาขาเดียวกัน
- ถ้าจ่ายแล้วแต่บันทึกบิลไม่สำเร็จ จะกดบันทึกใหม่ได้โดยไม่ต้องจ่ายซ้ำ
- ถ้าไม่ได้ตั้งค่า SCB พร้อมเพย์ใช้แบบกดยืนยันเองเหมือนเดิม

**ติดตั้งและตั้งค่าครั้งแรก**
- `scripts/install.sh` (Windows: `install.ps1`) สร้าง `.env` พร้อมรหัสลับสุ่ม แล้วเริ่มระบบด้วย Docker Compose: ฐานข้อมูล และแอปที่ API เสิร์ฟเว็บเอง เปิด HTTPS ด้วย `--domain` (Caddy)
- ระบบที่ยังไม่มีผู้ใช้แสดงหน้าตั้งค่าครั้งแรก เจ้าของร้านกรอกรหัสตั้งค่าที่พิมพ์ใน log แล้วสร้างบัญชีและตั้งชื่อร้านกับสาขา ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
- `scripts/backup.sh` / `restore.sh` สำรองและกู้คืนฐานข้อมูลเป็นไฟล์เดียว
- รูปสินค้าเก็บบนดิสก์ของเครื่องร้านเป็นค่าเริ่มต้น (volume `pos-media`) เลือก R2 ผ่าน Worker หรือปิดรูปได้ด้วย `MEDIA_STORAGE` (ปิดแล้วหน้าสินค้าซ่อนการอัปโหลด)
- ชุดทดสอบตรวจว่าไม่มี `.env` หรือรหัสผ่านฐานข้อมูลจริงอยู่ในไฟล์ที่ commit

## API (`/api/v1`)

| กลุ่ม | เส้นทางหลัก |
|---|---|
| ตั้งค่าครั้งแรก | `GET,POST /setup` (ไม่ต้องล็อกอิน ใช้ได้เฉพาะตอนยังไม่มีผู้ใช้) |
| ระบบ/ผู้ใช้ | `GET /health`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `GET,POST /users`, `PATCH /users/{id}` |
| สาขา | `GET,POST /branches`, `PATCH /branches/{id}` |
| รายการสินค้า | `GET,POST /catalog/categories`, `PATCH /catalog/categories/{id}`, `GET,POST /catalog/products`, `GET,PATCH /catalog/products/{id}`, `PUT,DELETE /catalog/products/{id}/image` |
| สต็อก | `GET /inventory/movements`, `POST /inventory/receive`, `POST /inventory/adjust` |
| การขาย | `GET,POST /sales`, `GET /sales/summary`, `GET /sales/{id}`, `POST /sales/{id}/void` |
| ออเดอร์ | `GET,POST /orders`, `GET,PATCH /orders/{id}`, `POST /orders/{id}/items`, `PATCH,DELETE /orders/{id}/items/{productId}`, `POST /orders/{id}/cancel`, `POST /orders/{id}/pay` |
| QR | `GET /payments/qr/config`, `POST /payments/qr`, `GET /payments/qr/{id}`, `POST /payments/qr/{id}/cancel`, `POST /payments/qr/scb/confirmation` (ไม่ต้องล็อกอิน) |
| พิมพ์ใบเสร็จผ่านแลน | `POST /receipt-printer/print` (พร้อม `Idempotency-Key`), `POST /receipt-printer/drawer/open`, `POST /receipt-printer/test-connection` |
| ตั้งค่า | `GET,PATCH /settings` |

หลักการ: ข้อผิดพลาดเป็น RFC 9457 (`application/problem+json` มี `code` คงที่), ทุก list คืน `{ items, total }`, ทุกคำขอทำงานในสาขา `MAIN` สาขาเดียว (header `X-Branch-Id` เก่าถูกเพิกเฉย), สัญญาถูกตรวจด้วย `bun run openapi:check`

## หน้าเว็บ

| หน้า | ใคร | ทำอะไร |
|---|---|---|
| ตั้งค่าครั้งแรก | ใครก็ได้ ตอนยังไม่มีบัญชี | กรอกรหัสตั้งค่า สร้างบัญชีเจ้าของ ตั้งชื่อร้าน แล้วเข้าสู่ระบบ |
| ขายสินค้า | ทุกคน | ค้นหา/สแกน แตะสินค้า ตะกร้า ชำระ ใบเสร็จ ออเดอร์ค้าง |
| วันนี้ | ทุกคน (เจ้าของเห็นสรุปเพิ่ม) | บิลวันนี้ ยอดขาย กำไรขั้นต้น สินค้าใกล้หมด รับชำระ |
| สินค้าและสต็อก | เจ้าของ | จัดการสินค้า รับเข้า ปรับยอด รูป |
| หมวดหมู่ | เจ้าของ | เพิ่ม เปลี่ยนชื่อ จัดลำดับ ปิดใช้งาน |
| ผู้ใช้ | เจ้าของ | เพิ่ม แก้ชื่อ/บทบาท/สาขา ปิดใช้งาน ตั้งรหัสผ่านใหม่ ตั้ง PIN สลับคนขายเร็ว |
| ตั้งค่าร้าน | เจ้าของ | ข้อมูลร้าน สกุลเงิน VAT ภาษา เขตเวลา ขนาดกระดาษและข้อความท้ายใบเสร็จ เครื่องพิมพ์แลน (IP/พอร์ต/ลิ้นชัก) |

- API: `domains/` (กฎธุรกิจ ไม่พึ่ง framework) → `applications/` (use case แบบ command/query, port) → `adapters/` (Elysia, Drizzle, SCB)

- เว็บแบ่งตาม feature, ข้อมูลจากเซิร์ฟเวอร์อยู่ใน TanStack Query, สถานะฝั่งเครื่องอยู่ใน zustand
- ข้อความที่ผู้ใช้อ่านทุกตัวมาจาก `t()`; เงินและวันที่จัดรูปแบบผ่าน `useFormat()`
- ความลับอยู่ใน `.env` เท่านั้น `.env.example` ต้องเป็น placeholder

## ข้อจำกัดที่รู้อยู่

- ชื่อฟิลด์ API ยังเป็น `*Satang` แม้ใช้สกุลเงินอื่น
- ภาษาตั้งระดับร้าน ไม่ใช่ต่อผู้ใช้
- ไม่มีโอนสต็อกระหว่างสาขาหรือราคาแยกสาขา
- มี component test ฝั่งเว็บแล้ว (ตาราง รายงาน และตรรกะ lib) ส่วน e2e ยังรันเฉพาะ flow หลัก
- รายการออเดอร์ค้างรีเฟรชเองทุก 15 วินาที ยังไม่มีการแจ้งแบบ real-time
- บิลที่ขายก่อนงานข้อ 11 ไม่มีหัวใบเสร็จเก็บไว้ ใบเสร็จของบิลเหล่านั้นยังอ้างชื่อร้านและข้อมูลสาขาปัจจุบัน
- การพิมพ์มีสองทาง: พิมพ์ตรงผ่านแลนแบบ raster ไทย (`GS v 0` + ตัด + ลิ้นชัก โค้ดผ่านเทสต์กับเครื่องพิมพ์จำลองแล้ว) กับพิมพ์ผ่านเบราว์เซอร์/PDF ที่ยังอยู่ ทั้งสองทางยังไม่เคยพิมพ์ออกเครื่อง thermal จริง และยังไม่มีโลโก้บนใบเสร็จ
- ข้อความท้ายใบเสร็จและขนาดกระดาษใช้ค่าปัจจุบันของร้าน ไม่ได้เก็บลงบิล
- ยังไม่มีการรีเซ็ตรหัสผ่านของเจ้าของร้านเมื่อลืม (ต้องแก้ในฐานข้อมูลเอง) และยังไม่มีการสำรองอัตโนมัติ: คู่มือแนะนำให้ตั้ง cron หรือ Task Scheduler เอง
- ไฟล์สำรองรวมรูปที่เก็บในเครื่อง (ไฟล์ `.media.tar.gz` คู่กัน) แต่ไม่รวมรูปบน R2 ไม่มีตัวย้ายรูประหว่างที่เก็บ เปลี่ยนที่เก็บแล้วต้องอัปโหลดรูปใหม่ และรูปที่อัปโหลดไม่ถูกปรับขนาด (จำกัด 5 MB)
- ชุดติดตั้งยังไม่มีตัวติดตั้งแบบกดสำหรับ Windows ต้องมี Docker Desktop
- ปุ่มยืนยันของฟอร์มยาว (เช่น ฟอร์มสินค้า) บนมือถือไม่ติดล่างเสมอ ต้องเลื่อนลงไปถึง dialog ที่ไม่มี form (ตัวเลือกสินค้า เลือกโต๊ะ) ติดล่างได้
- ผังโต๊ะบนมือถือไม่ลากตำแหน่ง ต้องใช้จอที่ใหญ่กว่า
- ตัวสำรอง/กู้คืนรูปของ `.ps1` ตรวจไวยากรณ์เท่านั้น ยังไม่เคยรันจริงบน Windows
