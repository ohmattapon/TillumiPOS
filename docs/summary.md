# ภาพรวม TillumiPOS

สรุปโค้ดใน main ที่ตรวจเมื่อ 20 ตุลาคม 2026 ไม่ใช่การรับรองว่าทดสอบกับอุปกรณ์หรือธนาคารจริงครบแล้ว ดูเอกสารทั้งหมดที่ [คู่มือ TillumiPOS](README.md)

## ความสามารถปัจจุบัน

TillumiPOS เป็นระบบขายหน้าร้านสำหรับร้านค้าปลีก คาเฟ่ และร้านอาหาร ใช้ผ่านเว็บ มีภาษาไทยและอังกฤษ ร้านหนึ่งใช้สาขา `MAIN` เพียงสาขาเดียว แต่มีหลายจุดขายได้

| งาน | ขอบเขตที่มี |
|---|---|
| ขาย | ค้นหาและสแกนสินค้า ส่วนลด VAT เงินสด พร้อมเพย์ และบันทึกการชำระบัตร |
| ออเดอร์และโต๊ะ | เก็บออเดอร์ไว้จ่ายทีหลัง ย้ายโต๊ะ รวมออเดอร์ และแยกตามรายการ |
| สินค้า | หมวดหมู่ รูปภาพ SKU อัตโนมัติ ตัวเลือกสินค้า และเมนูคาเฟ่เริ่มต้น |
| สต็อก | ใบรับสินค้าเข้าหลายรายการ ปรับยอด และตัดสต็อกเมื่อชำระ |
| ลูกค้า | สมาชิก ประวัติซื้อ และโปรโมชั่นตามเงื่อนไข |
| กะ | จุดขาย เงินตั้งต้น เงินเข้าออก นับเงิน และรายงานปิดกะ ในโหมด `shifts` |
| ใบเสร็จ | พิมพ์ผ่านเบราว์เซอร์ บันทึก PDF และส่งภาพใบเสร็จไปเครื่องพิมพ์ ESC/POS ผ่าน LAN |
| จอลูกค้า | จออ่านอย่างเดียว จับคู่ข้ามอุปกรณ์ผ่านเซิร์ฟเวอร์ หรือส่งในเบราว์เซอร์เดียวกัน |
| ดูแลร้าน | ผู้ใช้ บทบาท สิทธิ์ ประวัติการกระทำ รายงานย้อนหลัง และส่งออก Excel |

ระบบครัวถูกถอดออกแล้ว ไม่มีปุ่มส่งครัว จอครัว หรือสถานะใบสั่งครัว หมายเหตุในรายการออเดอร์ยังใช้ได้

## การรับเงิน

- เงินสด: บันทึกยอดรับและคำนวณเงินทอน
- พร้อมเพย์แบบกำหนดผู้รับ: แสดง QR พร้อมยอดบิล พนักงานตรวจเงินเข้าในธนาคารเองก่อนยืนยัน ระบบไม่ได้ตรวจยอดให้อัตโนมัติ
- SCB QR: สร้าง QR และตรวจสถานะกับธนาคาร ต้องมีข้อมูลร้านค้าของ SCB และทดสอบกับธนาคารจริงก่อนใช้ ชุดทดสอบอัตโนมัติใช้ธนาคารจำลอง
- บัตร: บันทึกช่องทางชำระเงิน ยังไม่ได้เชื่อมเครื่องรูดบัตร

## ติดตั้งและเก็บข้อมูล

main ใช้ Podman Compose รัน PostgreSQL และแอปบนเครื่องหลัก ผู้ใช้เปิดเว็บที่พอร์ต 3000 เครื่องอื่นในร้านเชื่อมต่อเครื่องหลักผ่านเครือข่ายเดียวกัน ดู [ติดตั้ง](install.md) และ [ตั้งอุปกรณ์](devices.md)

ฐานข้อมูลอยู่ใน volume `pos-db` รูปในเครื่องอยู่ใน `pos-media` การสำรองด้วยสคริปต์ได้ฐานข้อมูล `.sql.gz` และไฟล์รูป `.media.tar.gz` เมื่อมีรูป ควรเก็บไฟล์คู่กันและคัดลอกออกนอกเครื่องหลัก รูปที่เก็บผ่าน Worker/R2 ต้องสำรองแยก

Tauri และตัวติดตั้ง Windows แบบ native เป็นงานแยกจาก main ที่ตรวจครั้งนี้ คู่มือปัจจุบันจึงอิงการติดตั้งผ่าน Podman

## โครงสร้างโค้ด

| ที่อยู่ | หน้าที่ |
|---|---|
| `src/` | เว็บ React แบ่งตามฟีเจอร์ |
| `server/src/` | API Bun/Elysia แบบ Hexagonal Architecture และ CQRS |
| `drizzle/` | Migration และประวัติโครงสร้าง PostgreSQL |
| `workers/media/` | ตัวเลือกเก็บรูปบน Cloudflare R2 |
| `workers/cloud/` | การติดตั้งผ่าน Cloudflare Container |
| `scripts/` | ติดตั้ง สำรอง กู้คืน และเครื่องมือดูแลระบบ |
| `e2e/` | ทดสอบผ่านเบราว์เซอร์และเก็บภาพหน้าจอ |

API ใช้ `/api/v1` และ `/api/v2` สำหรับงาน checkout/กะรุ่นใหม่ เว็บและ API ใช้กฎคำนวณยอดร่วมกัน เงินเก็บเป็นจำนวนเต็มหน่วยสตางค์

## ข้อจำกัด

- ไม่มีระบบหลายสาขา ระบบครัว ผู้จำหน่าย ล็อตสินค้า หรือวันหมดอายุ
- ตัวเลือกสินค้าเพิ่มราคาและต้นทุนได้ แต่ไม่มีสต็อกวัตถุดิบแยกตามตัวเลือก
- จอลูกค้าที่จับคู่และตัวนับการลอง PIN เก็บในหน่วยความจำ API จึงรองรับ API หนึ่ง instance; รีสตาร์ตแล้วต้องจับคู่จอใหม่
- การพิมพ์และเปิดลิ้นชักต้องตรวจความเข้ากันได้กับอุปกรณ์จริง การส่งข้อมูลสำเร็จไม่ได้ยืนยันว่ากระดาษออกครบ
- ชุดทดสอบอัตโนมัติไม่แทนการทดลองติดตั้ง รีสตาร์ต ขาย สำรอง และกู้คืนบนเครื่องร้าน

แผนและบันทึกงานที่ลงวันที่ใน `superpowers/` และ `work-log-*` เป็นประวัติการพัฒนา อาจกล่าวถึงฟีเจอร์หรือโครงสร้างที่เปลี่ยนไปแล้ว
