# สรุปงานที่ทำ: EasyPOS

สรุป ณ วันที่ 14 ตุลาคม 2026 · เขียนจากสถานะของ repo จริง (ดูรายละเอียดเชิงลึกของแต่ละเรื่องในโฟลเดอร์ `docs/superpowers/specs`)

## ภาพรวม

EasyPOS คือ POS แบบโอเพนซอร์สที่ติดตั้งใช้เองได้ รองรับทั้งร้านค้าปลีกและร้านอาหาร เริ่มที่ประเทศไทย (ภาษาไทยเป็นหลัก มีอังกฤษด้วย) ติดตั้งได้ทั้งในเครื่องร้านด้วย Docker และบนคลาวด์

| ส่วน | เทคโนโลยี |
|---|---|
| `apps/api` | Bun, Elysia, Drizzle, PostgreSQL, tsyringe, zod สถาปัตยกรรม Hexagonal + CQRS |
| `apps/web` | React 19, Vite, Tailwind, shadcn/ui, TanStack Query, zustand, react-router, i18next |
| `apps/media` | Cloudflare Worker + R2 เก็บรูปสินค้า |

## ความสามารถที่มีตอนนี้

**การขาย**
- ขายขั้นตอนเดียว: เลือกสินค้า ใส่ส่วนลด ชำระ (เงินสด/พร้อมเพย์/บัตร) พร้อมคำนวณเงินทอน
- เลขใบเสร็จไม่มีช่องว่าง รูปแบบ `<รหัสสาขา>-yyyymmdd-nnnnn` นับแยกตามสาขาและวัน
- ยกเลิกบิล (เจ้าของร้าน) คืนสต็อกเข้าสาขาของบิลนั้น บิลแก้/ลบไม่ได้
- VAT 3 แบบ: รวมในราคา, บวกเพิ่ม, ไม่คิด เก็บกติกาภาษีไว้กับแต่ละบิล แก้ตั้งค่าทีหลังไม่กระทบบิลเก่า
- จำนวนเงินเก็บเป็นจำนวนเต็มหน่วยเล็กสุด (สตางค์) เสมอ

**ออเดอร์ค้าง (ร้านอาหาร)**
- เก็บตะกร้าเป็นออเดอร์ เพิ่ม/ลด/ลบรายการ ทำต่อจากรายการ แล้วชำระทีหลัง
- ราคา ณ ตอนสั่งถูกเก็บไว้ ชำระตามราคานั้น สต็อกตัดตอนชำระ
- ชำระผ่านตัวคิดเงินเดียวกับการขายปกติ จึงได้บิลธรรมดา

**สินค้าและสต็อก**
- สินค้า หมวดหมู่ รูปสินค้า (R2) รับสินค้าเข้า ปรับยอดนับจริง ประวัติการเคลื่อนไหวแบบ append-only
- สต็อกแยกตามสาขา

**หลายสาขา**
- เจ้าของร้านสลับสาขาที่ทำงาน แคชเชียร์ทำงานได้เฉพาะสาขาตน
- เพิ่ม/แก้/ปิดสาขา (ลบไม่ได้ รหัสสาขาแก้ไม่ได้)

**การตั้งค่าร้านและภาษา**
- ชื่อร้าน เลขผู้เสียภาษี ที่อยู่ เบอร์โทร สกุลเงิน VAT เขตเวลา ภาษา
- ทุกข้อความอยู่ในไฟล์ภาษา ข้อผิดพลาดจาก API แปลตามรหัส

**ชำระด้วย QR ของ SCB**
- สร้าง QR ตามยอด รอธนาคารยืนยัน แล้วบันทึกบิลอัตโนมัติ
- ธนาคารเป็นแหล่งความจริงเดียว: callback ของ SCB ไม่มีลายเซ็น จึงใช้เป็นแค่สัญญาณให้ไปถาม SCB เอง
- หนึ่ง QR ใช้ได้หนึ่งบิล ยอดต้องตรงพอดี ต้องอยู่สาขาเดียวกัน
- ถ้าจ่ายแล้วแต่บันทึกบิลไม่สำเร็จ จะกดบันทึกใหม่ได้โดยไม่ต้องจ่ายซ้ำ
- ถ้าไม่ได้ตั้งค่า SCB พร้อมเพย์ใช้แบบกดยืนยันเองเหมือนเดิม

**ติดตั้งและตั้งค่าครั้งแรก**
- `scripts/install.sh` (Windows: `install.ps1`) สร้าง `.env` พร้อมรหัสลับสุ่ม แล้วเริ่มระบบด้วย Docker Compose: ฐานข้อมูล และแอปที่ API เสิร์ฟเว็บเอง เปิด HTTPS ด้วย `--domain` (Caddy)
- ระบบที่ยังไม่มีผู้ใช้แสดงหน้าตั้งค่าครั้งแรก เจ้าของร้านกรอกรหัสตั้งค่าที่พิมพ์ใน log แล้วสร้างบัญชีและตั้งชื่อร้านกับสาขา ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
- `scripts/backup.sh` / `restore.sh` สำรองและกู้คืนฐานข้อมูลเป็นไฟล์เดียว
- ทำงานได้โดยไม่มีที่เก็บรูปสินค้า (หน้าสินค้าซ่อนการอัปโหลด)
- ชุดทดสอบตรวจว่าไม่มี `.env` หรือรหัสผ่านฐานข้อมูลจริงอยู่ในไฟล์ที่ commit

## API (`/api/v1`)

| กลุ่ม | เส้นทางหลัก |
|---|---|
| ตั้งค่าครั้งแรก | `GET,POST /setup` (ไม่ต้องล็อกอิน ใช้ได้เฉพาะตอนยังไม่มีผู้ใช้) |
| ระบบ/ผู้ใช้ | `GET /health`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, `GET,POST /users`, `PATCH /users/{id}` |
| สาขา | `GET,POST /branches`, `PATCH /branches/{id}` |
| รายการสินค้า | `GET,POST /catalog/categories`, `PATCH /catalog/categories/{id}`, `GET,POST /catalog/products`, `GET,PATCH /catalog/products/{id}`, `PUT,DELETE /catalog/products/{id}/image` |
| สต็อก | `GET /inventory/movements`, `POST /inventory/receive`, `POST /inventory/adjust` |
| การขาย | `GET,POST /sales`, `GET /sales/summary`, `GET /sales/{id}`, `POST /sales/{id}/void` |
| ออเดอร์ | `GET,POST /orders`, `GET,PATCH /orders/{id}`, `POST /orders/{id}/items`, `PATCH,DELETE /orders/{id}/items/{productId}`, `POST /orders/{id}/cancel`, `POST /orders/{id}/pay` |
| QR | `GET /payments/qr/config`, `POST /payments/qr`, `GET /payments/qr/{id}`, `POST /payments/qr/{id}/cancel`, `POST /payments/qr/scb/confirmation` (ไม่ต้องล็อกอิน) |
| ตั้งค่า | `GET,PATCH /settings` |

หลักการ: ข้อผิดพลาดเป็น RFC 9457 (`application/problem+json` มี `code` คงที่), ทุก list คืน `{ items, total }`, สาขาที่ทำงานอยู่ส่งด้วย header `X-Branch-Id`, สัญญาถูกตรวจด้วย `bun run openapi:check`

## โครงสร้างและกฎของโค้ด (สรุปจาก `AGENTS.md`)

- API: `domains/` (กฎธุรกิจ ไม่พึ่ง framework) → `applications/` (use case แบบ command/query, port) → `adapters/` (Elysia, Drizzle, SCB)
- ทุกการสร้างบิลขายผ่าน port `ISaleCheckout` ตัวเดียว
- สต็อกเปลี่ยนผ่าน `IStockLedger` เท่านั้น และทุกการเปลี่ยนมีรายการเคลื่อนไหวพร้อมสาขา
- เว็บแบ่งตาม feature, ข้อมูลจากเซิร์ฟเวอร์อยู่ใน TanStack Query, สถานะฝั่งเครื่องอยู่ใน zustand
- ข้อความที่ผู้ใช้อ่านทุกตัวมาจาก `t()`; เงินและวันที่จัดรูปแบบผ่าน `useFormat()`
- ความลับอยู่ใน `.env` เท่านั้น `.env.example` ต้องเป็น placeholder

## สถานะ git

- `main` (และ `origin/main`) อยู่ที่ `d721cb3` รวมข้อ 1–8, 10 และ 11 แล้ว แต่ commit baseline ของ OpenAPI สำหรับโต๊ะ (`8da92de`) อยู่บน `ohmattpon/tables` เท่านั้น
- `ohmattpon/install-kit` แตกจาก `main`: งานข้อ 14 (ชุดติดตั้ง) ยังไม่ได้ push มี commit baseline ที่เนื้อหาเหมือน `8da92de` ติดมาด้วย เพื่อให้ `openapi:check` ผ่านบน branch นี้ ถ้า merge `ohmattpon/tables` ทีหลังไฟล์ baseline ควรไม่ชนเพราะเนื้อหาส่วนนั้นเหมือนกัน
- `ohmattpon/demo-data` (ต่อจาก `ohmattpon/tables`): ตัวสร้างข้อมูลตัวอย่าง `bun run db:seed:demo`
- branch เก่าทั้งหมดยังอยู่ ยังไม่ได้ลบ

## เรื่องที่ต้องทำต่อ (เป็นของเจ้าของโครงการ)

1. **ออกคีย์ SCB ใหม่** คีย์เดิมเคยถูก commit และ push ใน `.env.example` (commit `c428e8d`) ถือว่ารั่ว การแก้ประวัติ git ไม่พอแทนการเปลี่ยนคีย์
2. **push และ merge ตามลำดับ:** `ohmattpon/tables` → `ohmattpon/demo-data` → `ohmattpon/install-kit` ฉันไม่ push เองตามกฎเหล็ก
3. **ทดสอบการจ่าย QR จริงให้เห็น "จ่ายแล้ว" 1 ครั้ง** (sandbox ไม่มีเอกสารวิธีจำลอง ทางที่ชัวร์คือ production ยอด 1 บาท) แล้วรัน `bun run scb:inquiry <รหัส>`
4. **ลองทั้งระบบในเบราว์เซอร์:** สลับสาขา, สลับภาษา, สร้างออเดอร์ค้าง, ตั้งค่า VAT แบบบวกเพิ่ม
5. ถ้าจะลงทะเบียน callback ของ SCB ต้องมี URL HTTPS สาธารณะ (ไม่บังคับ ระบบ poll ได้เองทุก 3 วินาที)
6. **เพิ่มหัวข้อใบอนุญาตใน `README.md`** (AGPL-3.0, `Copyright (C) 2026 ohmattapon` ลิงก์ไป `LICENSE` และ `docs/install.md`) ฉันไม่ได้แตะ README เพราะมีการแก้ของคุณที่ยังไม่ได้ commit
7. **ลอง `scripts/install.ps1` บน Windows จริงหนึ่งครั้ง** ฉันตรวจได้แค่ไวยากรณ์ ลองรันจริงเฉพาะ `install.sh` กับ `backup.sh`/`restore.sh`
8. ถ้าเคยเปิดฐานข้อมูลสาธิตสู่สาธารณะ ให้เปลี่ยนรหัสผ่านของบัญชีตัวอย่างที่ `db:seed:demo` สร้าง

## ข้อจำกัดที่รู้อยู่

- ชื่อฟิลด์ API ยังเป็น `*Satang` แม้ใช้สกุลเงินอื่น
- ภาษาตั้งระดับร้าน ไม่ใช่ต่อผู้ใช้
- ไม่มีโอนสต็อกระหว่างสาขา ราคาแยกสาขา หรือรายงานย้อนหลัง
- ยังไม่มีทดสอบคอมโพเนนต์/E2E ฝั่งเว็บ (ทดสอบเฉพาะตรรกะล้วนและ store)
- รายการออเดอร์ค้างรีเฟรชเองทุก 15 วินาที ยังไม่มีการแจ้งแบบ real-time
- บิลที่ขายก่อนงานข้อ 11 ไม่มีหัวใบเสร็จเก็บไว้ ใบเสร็จของบิลเหล่านั้นยังอ้างชื่อร้านและข้อมูลสาขาปัจจุบัน
- การพิมพ์ใช้หน้าต่างพิมพ์ของเบราว์เซอร์: ตรวจความกว้างด้วย CSS ในเบราว์เซอร์แล้ว แต่ยังไม่เคยพิมพ์ออกเครื่อง thermal จริง ขนาดหน้ากระดาษและขอบขึ้นกับ driver ของเครื่องพิมพ์ ยังไม่มี ESC/POS เปิดลิ้นชัก หรือโลโก้
- ข้อความท้ายใบเสร็จและขนาดกระดาษใช้ค่าปัจจุบันของร้าน ไม่ได้เก็บลงบิล
- ยังไม่มีการรีเซ็ตรหัสผ่านของเจ้าของร้านเมื่อลืม (ต้องแก้ในฐานข้อมูลเอง) และยังไม่มีการสำรองอัตโนมัติ: คู่มือแนะนำให้ตั้ง cron หรือ Task Scheduler เอง
- ไฟล์สำรองมีเฉพาะฐานข้อมูล ไม่รวมรูปสินค้าบน R2
- ชุดติดตั้งยังไม่มีตัวติดตั้งแบบกดสำหรับ Windows ต้องมี Docker Desktop
- ติดตั้งเสร็จแล้วยังไม่มีที่เก็บรูป จนกว่าจะตั้ง `MEDIA_URL` และ `MEDIA_TOKEN` (ข้อ 13 จะทำให้เลือกที่เก็บในเครื่องได้)
