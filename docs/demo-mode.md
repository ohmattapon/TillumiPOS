# โหมดสาธิต (demo mode, ไม่ใช้ฐานข้อมูล)

โหมดสาธิตเปิด TillumiPOS ทั้งแอปโดยไม่ต้องมี PostgreSQL เลย ข้อมูลทั้งหมดอยู่ในหน่วยความจำ
(memory adapters ชุดเดียวกับที่ use case ตัวจริงใช้ พฤติกรรมจึงเหมือนของจริง) มีไว้โชว์ให้คนอื่นดู
หรือลองกดเล่นเท่านั้น

## วิธีรัน

```bash
bun run demo:memory
```

คำสั่งนี้ตั้งค่าให้เอง (`DEMO_MODE=memory`, `MEDIA_STORAGE=none`, `DATABASE_URL` ปลอมที่ชี้ไปพอร์ตที่ไม่มีอะไรฟัง)
แล้วรันสแต็ก dev ปกติ (API + เว็บ) ทุกครั้งที่รีสตาร์ท ข้อมูลจะกลับมาเป็นชุดสาธิตชุดเดิมเสมอ
ไม่มีการบันทึกลงไฟล์หรือฐานข้อมูล

## รหัสเข้าสาธิต (ใช้ได้เฉพาะในโหมดนี้เท่านั้น)

| ผู้ใช้ | รหัสผ่าน | PIN (สลับคนขายหน้าเครื่อง) |
|---|---|---|
| `admin` (เจ้าของร้าน) | `demo-owner-1234` | `1234` |
| `somying` (แคชเชียร์) | `demo-cashier-1234` | `1111` |
| `wichai` (แคชเชียร์) | `demo-cashier-1234` | `2222` |

คำเตือน: รหัสเหล่านี้อยู่ใน seeder ของโหมดสาธิตเท่านั้น ห้ามเอาไปใช้กับระบบจริงเด็ดขาด
และห้ามคัดลอกไปใส่ใน seed/migration ของระบบจริง

## สิ่งที่ใช้ไม่ได้ในโหมดสาธิต

- QR ธนาคารจริง (SCB): ไม่มีการตั้งค่า SCB การชำระด้วยพร้อมเพย์ใช้แบบ static (พนักงานยืนยันยอดเอง)
- รูปสินค้า (`MEDIA_STORAGE=none` ไม่มีรูป)
- รันหลาย instance: ข้อมูลอยู่ในหน่วยความจำของ API ตัวเดียว (เหมือนจอลูกค้าและตัวกันกด PIN รัว)
- เครื่องพิมพ์ USB/Bluetooth และเครื่อง thermal จริง (พิมพ์ได้แค่ตัวอย่างบนจอ/PDF)
- ข้อมูลรีเซ็ตทุกครั้งที่รีสตาร์ท

## ห้ามใช้กับข้อมูลจริง

โหมดสาธิตไม่มีฐานข้อมูล ไม่มีสำรองข้อมูล และรหัสผ่านเป็นรหัสสาธิตที่รู้กันทั่วไป
ห้ามรันโหมดนี้กับข้อมูลร้านจริงเด็ดขาด
