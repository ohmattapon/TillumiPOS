# รายงานย้อนหลัง

หน้า `/reports` สำหรับเจ้าของร้าน เลือกวันเริ่มและวันสิ้นสุดได้ รวมวันทั้งสองด้านและไม่เกิน 366 วัน มีช่วงสำเร็จรูป: วันนี้, 7 วันล่าสุด, เดือนนี้ และเดือนก่อน เลือกรายงานสาขาที่ทำงานอยู่หรือทุกสาขาได้

## ตัวเลขที่แสดง

- **ยอดขายรวม:** ยอดที่เรียกเก็บหลังส่วนลด รวม VAT เฉพาะบิลที่ยังมีสถานะสำเร็จ
- **ยอดขายไม่รวม VAT:** ยอดขายรวมลบ VAT ที่เก็บไว้กับบิล
- **กำไรขั้นต้น:** ยอดขายไม่รวม VAT ลบต้นทุนรายการสินค้าและตัวเลือก ณ ตอนขาย ยังไม่หักค่าใช้จ่ายร้าน
- **ยอดเฉลี่ยต่อบิล:** ยอดขายรวมหารจำนวนบิลสำเร็จ
- **ช่องทางชำระเงิน:** เงินสดหักเงินทอนแล้ว บัตรและพร้อมเพย์นับตามยอดชำระ
- **สินค้าขายดี:** เรียงตามจำนวนขาย รวมรายการของสินค้าเดียวกัน ใช้ชื่อและ SKU จากรายการขายล่าสุดในช่วงนั้น ยอดสินค้าเป็นยอดบรรทัดก่อนส่วนลดท้ายบิลและ VAT ที่บวกเพิ่ม จึงอาจไม่เท่ากับยอดรวมบิล
- **เปรียบเทียบสาขา:** รวมสาขาที่ปิดแล้วหากมีบิลในช่วงนั้น รายงานทุกสาขาเปิดให้เจ้าของร้านเท่านั้น

วันถูกแปลงเป็นช่วงเวลาใน PostgreSQL ด้วยเขตเวลาปัจจุบันของร้าน รวมถึงวันที่มีการเปลี่ยนเวลา DST ไม่ใช้เขตเวลาของเครื่องผู้เปิดเว็บ วันที่ไม่มียอดขายแสดงเป็นศูนย์

รายงานใช้สถานะบิลปัจจุบัน: ยกเลิกบิลทีหลังแล้วรายงานช่วงวันขายเดิมจะเปลี่ยนตาม รายงานนี้ไม่ใช่ snapshot รายงานปิดกะ และไม่มีการเขียนทับ `shift_summaries`

## API ที่เพิ่ม

| เส้นทาง | ผลลัพธ์ |
|---|---|
| `GET /api/v1/sales/reports` | สรุป, รายวัน `{items,total}`, ช่องทางชำระเงิน |
| `GET /api/v1/sales/reports/products` | สินค้าขายดี `{items,total}` |
| `GET /api/v1/sales/reports/branches` | เปรียบเทียบสาขา `{items,total}` |

ทุกเส้นทางใช้ `from`, `to` แบบ YYYY-MM-DD และ `scope` เป็น `branch` หรือ `all` (ค่าเริ่มต้น branch) สาขาที่เลือกมาจาก `X-Branch-Id` ผ่านตัวตรวจสิทธิ์เดิม รายการสินค้าและสาขารับ `limit` (1–500) กับ `offset`

การเพิ่มนี้ไม่เปลี่ยนสัญญาเส้นทางเดิม เจ้าของร้านเท่านั้นที่อ่านรายงานได้ ทั้งใน HTTP และใน use case เว็บเรียกผ่าน Elysia Treaty และเก็บข้อมูลเซิร์ฟเวอร์ใน TanStack Query ภายใต้ sales query keys เพื่อ invalidate เมื่อขายหรือยกเลิกบิล

## ส่งออก Excel

ไฟล์ .xlsx มี 5 ชีต: สรุป, รายวัน, สินค้า, สาขา และการชำระเงิน รวมสินค้าทุกหน้าและสาขาทุกหน้า เก็บจำนวนเงินเป็นตัวเลขในหน่วยสกุลเงินที่แสดง ไม่ใช่ข้อความหรือสตางค์ ชื่อสินค้าและ SKU เป็นข้อความ รวมถึงชื่อที่ขึ้นต้นเหมือนสูตร Excel

ใช้ข้อมูลใหม่ขณะส่งออกและตรึงสาขาตลอดคำขอ หากจำนวนแถวเปลี่ยนหรือพบรายการซ้ำระหว่างอ่านหลายหน้า จะหยุดและให้ลองใหม่ ข้อมูลอาจเปลี่ยนตามการขายระหว่างคำขอรายงานแต่ละส่วน จึงไม่ใช่ snapshot ทางบัญชี ณ เวลาเดียวกันทั้งไฟล์

ExcelJS โหลดเฉพาะตอนส่งออก ตาม [เอกสารการใช้งานในเบราว์เซอร์](https://github.com/exceljs/exceljs#browser) และสร้าง workbook แบบ document พร้อม `writeBuffer()` ส่วนช่วงวันอ้างอิง [PostgreSQL AT TIME ZONE](https://www.postgresql.org/docs/current/functions-datetime.html#FUNCTIONS-DATETIME-ZONECONVERT)

## การตรวจสอบ

- การคำนวณกำไร, การตรวจวัน, สิทธิ์ และ scope ทดสอบกับ port จำลอง
- HTTP ทดสอบกับ pos_test ที่ localhost:5433 โดยตรวจชื่อฐานจริงก่อน reset: ยอดหลายบรรทัด, ส่วนลด, VAT, เงินทอน, บิลยกเลิก, ราคา/ต้นทุนที่เปลี่ยนภายหลัง, pagination, หลายสาขา, สาขาปิด และ DST
- ฝั่งเว็บทดสอบช่วงสำเร็จรูปข้ามปี/ปีอธิกสุรทิน, การรวมทุกหน้า และอ่านไฟล์ XLSX กลับเพื่อตรวจชนิดตัวเลข ข้อความไทยและข้อความคล้ายสูตร
