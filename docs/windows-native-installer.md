# ติดตั้ง TillumiPOS บน Windows ด้วยไฟล์เดียว (ไม่ต้องใช้คำสั่ง)

> **ไฟล์นี้สำหรับ:** เจ้าของร้านที่ไม่อยากแตะ PowerShell — อ่านแค่ครึ่งแรกก็ติดตั้งได้
> ครึ่งหลัง ("สำหรับช่าง") เป็นข้อมูลทางเทคนิคสำหรับคนดูแลเครื่อง
> ถ้าร้านติดตั้งแบบ Podman อยู่แล้ว ให้อ่าน `install.md` แทน วิธีนี้เป็นอีกทางเลือกหนึ่ง ไม่ต้องย้ายถ้าของเดิมใช้ดีอยู่

## ไฟล์ติดตั้งคืออะไร

ไฟล์ติดตั้งชื่อประมาณ `TillumiPOS-Setup-1.0.0.exe` เป็นไฟล์เดียวจบ ดับเบิลคลิกแล้วตอบคำถามบนหน้าจอภาษาไทย โปรแกรมจะจัดการให้ทั้งหมดโดยไม่ต้องพิมพ์คำสั่งใด ๆ:

- วางตัวโปรแกรมและฐานข้อมูล (PostgreSQL) ไว้ในเครื่องร้านเอง ข้อมูลไม่ออกไปข้างนอก
- ตั้งให้โปรแกรมเปิดเองทุกครั้งที่เปิดเครื่อง ไม่ต้องล็อกอินเข้าวินโดวส์ก่อนก็ขายได้
- สร้างไอคอน **"เปิดหน้าร้าน"** บนหน้าจอและใน Start menu กดแล้วเปิดหน้าต่างแอป TillumiPOS เข้าหน้าขายเลยแบบเต็มจอ (ถ้าไฟล์ติดตั้งไม่มีแอปนี้ตอนติดตั้ง ไอคอนจะเปิดหน้าขายด้วยเบราว์เซอร์แทน ถ้าแอปติดตั้งแล้วแต่เปิดไม่ขึ้นภายหลัง ไอคอนจะไม่สลับเป็นเบราว์เซอร์เอง ให้ใช้ที่อยู่เบราว์เซอร์ในหัวข้อแก้ปัญหาเบื้องต้นด้านล่าง)
- ตั้งงานสำรองข้อมูลอัตโนมัติทุกคืนตอนตีสอง
- ตอนถอนการติดตั้ง โปรแกรมจะถามก่อนเสมอว่าจะลบข้อมูลร้านด้วยหรือไม่ **ค่าเริ่มต้นคือเก็บข้อมูลไว้** ติดตั้งใหม่ทับ ยอดขายเดิมกลับมาเหมือนเดิม

## เครื่องแบบไหนใช้ได้

- **ใช้ได้:** คอมพิวเตอร์ Windows 10 หรือ Windows 11 รุ่น 64 บิต (x64) ตัวที่ร้านใช้อยู่ทั่วไป
- **ใช้ไม่ได้ / ยังไม่รองรับ:** เครื่องชิป ARM (เช่น Surface รุ่น ARM, Snapdragon) — ยังไม่เคยทดสอบ ห้ามใช้กับเครื่องขายจริง
- เนื้อที่ว่างอย่างน้อย 2 GB, RAM อย่างน้อย 2 GB
- ต้องมีเน็ตตอนติดตั้งครั้งแรก (โหลดไฟล์ติดตั้ง) หลังติดตั้งแล้วขายแบบไม่มีเน็ตได้ ยกเว้นรับเงิน QR ผ่านธนาคารที่ต้องใช้เน็ต
- ต้องมีสิทธิ์แอดมินของเครื่องตอนติดตั้ง (เครื่องร้านของตัวเองปกติมีอยู่แล้ว)

## ขั้นตอนติดตั้ง (สำหรับเจ้าของร้าน)

1. **ดับเบิลคลิก**ไฟล์ `TillumiPOS-Setup-*.exe`
   - ถ้าวินโดวส์ขึ้นจอเตือนสีฟ้า/แดงว่า "Windows protected your PC" (SmartScreen) ให้กด `More info` แล้วกด `Run anyway`
     นี่เกิดเพราะโปรแกรมยังไม่มีใบรับรองลายเซ็นดิจิทัล (ดูหมายเหตุด้านล่าง) ไฟล์ที่โหลดจากเพจทางการของร้านปลอดภัย
2. **ตอบตามหน้าจอภาษาไทย:** กด Next ไปเรื่อย ๆ
   - หน้า "การเชื่อมต่อในร้าน" มีช่องติ๊ก **"ให้เครื่องอื่นในร้านเปิดหน้าขายได้ด้วย (เช่น iPad ผ่านวายฟายร้าน)"**
     - ติ๊กช่องนี้ถ้าจะให้ iPad / มือถือ / เครื่องที่สองเปิดหน้าขายผ่านวายฟายร้าน
     - ไม่ติ๊ก = เปิดได้เฉพาะเครื่องหลักเครื่องเดียว (ปลอดภัยที่สุด)
3. ติ๊ก **"ดูรหัสสำหรับตั้งค่าร้านครั้งแรก"** และ **"เปิดหน้าร้านเลย"** แล้วกด Finish — โปรแกรมจะแสดงรหัสตั้งค่าและเปิดหน้าร้าน
4. **ตั้งค่าร้านครั้งแรก:** กรอกชื่อร้าน สร้างบัญชีเจ้าของ ตามหน้าจอ (เหมือนหัวข้อ "ตั้งค่าร้านครั้งแรก" ใน `install.md`)
   - **รหัสตั้งค่า** ดูจากหน้าต่างที่เปิดหลังติดตั้ง หากปิดไปแล้วให้เปิด **Start → TillumiPOS → รหัสตั้งค่าร้าน** Windows จะขอสิทธิ์ผู้ดูแลก่อน (log ของระบบอ่านได้เฉพาะผู้ดูแล) รหัสจะอ่านจาก log โดยไม่สร้างไฟล์รหัสเพิ่ม ร้านที่ตั้งค่าแล้วจะไม่แสดงรหัส
   - กรอกผิด 5 ครั้งจะถูกล็อก 15 นาที ต้องสลับแป้นพิมพ์เป็นภาษาอังกฤษก่อนกรอก

## ใช้งานทุกวัน (ไม่ต้องทำอะไร)

- เปิดเครื่อง โปรแกรมติดเอง ขายได้เลย ไม่ต้องล็อกอินวินโดวส์ ไม่ต้องเปิดโปรแกรมอะไรก่อน
- กดไอคอน **"เปิดหน้าร้าน"** บนหน้าจอเพื่อขาย ถ้าปิดหน้าขายไป เปิดไอคอนใหม่ได้ตลอด ข้อมูลไม่หาย
- ถ้าเปิดแอปตอนที่ระบบหน้าร้านยังไม่พร้อม (เช่นเพิ่งเปิดเครื่อง) หน้าต่างจะขึ้นว่ากำลังเตรียมระบบและเปิดหน้าขายให้เองเมื่อพร้อม ไม่ต้องกดซ้ำ
- แอปเปิดเป็นเต็มจอและไม่มีแถบเมนู ถ้าจะออกจากเต็มจอ กด **F11** หรือ **Alt + Enter** ได้เลย (กดซ้ำกลับเข้าเต็มจอ) หรือถ้าจะโหลดหน้าใหม่หรือปิดแอป ให้กด **Ctrl + Shift + Alt + O** พร้อมกัน จะมีเมนูเจ้าของร้าน (ออกจากโหมดเต็มจอ / โหลดหน้าใหม่ / ปิดแอป)
- แอปไม่มีหน้าตั้งค่าเครื่องพิมพ์ การพิมพ์ใบเสร็จยังไปทางเครื่องพิมพ์ LAN เหมือนเดิม (ดู `thermal-printer-setup.md`)
- iPad มือถือ และเครื่องอื่นในร้านยังใช้เบราว์เซอร์เปิดหน้าขายเหมือนเดิม แอปนี้มีเฉพาะบนเครื่องหลักที่ลงโปรแกรม
- ไฟดับ / เครื่องรีสตาร์ทเอง: เปิดเครื่องขึ้นมาใหม่ รอสักครู่แล้วกดไอคอนเปิดหน้าร้าน ขายต่อได้เลย
- ไฟล์สำรองข้อมูลถูกสร้างให้ทุกคืนตอนตีสอง อยู่ใน `C:\ProgramData\TillumiPOS\backups`
  **ควรคัดลอกไฟล์สำรองไว้ที่อื่นด้วย** (ดิสก์อีกลูก หรือ cloud drive) อย่างน้อยสัปดาห์ละครั้ง
  โฟลเดอร์ข้อมูลร้านเปิดได้เฉพาะบัญชีผู้ดูแลของเครื่อง (บัญชีพนักงานทั่วไปเปิดไม่ได้ เพราะมีข้อมูลลูกค้าและรหัสลับของร้าน)
  ถ้า Windows ถามสิทธิ์ตอนเปิดโฟลเดอร์ ให้ใช้บัญชีผู้ดูแล

## อัปเดตเวอร์ชันใหม่ (สำหรับเจ้าของร้าน)

ไม่ต้องโหลดไฟล์ติดตั้งใหม่เองทั้งหมด ทำ 2 ขั้น:

1. ในหน้าขาย ไปที่ **ตั้งค่าร้าน → อัปเดตโปรแกรม** กด **"ตรวจอัปเดต"**
   - ถ้าเป็นรุ่นล่าสุดแล้ว จบตรงนี้ ไม่ต้องทำอะไร
   - ถ้ามีรุ่นใหม่ กด **"โหลดรุ่นใหม่"** โปรแกรมจะโหลดมาตรวจความถูกต้องให้เอง (ขั้นนี้ยังขายต่อได้ตามปกติ)
2. พอโหลดเสร็จ หน้าจอจะบอกว่าให้รันสคริปต์ติดตั้งบนเครื่องหลัก
   ให้ช่าง (หรือเจ้าของที่กล้าทำตาม) คลิกขวาที่ไฟล์ `apply-update.ps1` ในโฟลเดอร์โปรแกรมแล้วเลือก
   **Run with PowerShell แบบผู้ดูแล (Run as administrator)** รอจนขึ้นว่า "อัปเดตสำเร็จ" แล้วเปิดร้านตามปกติ
   - ระหว่างรันสคริปต์ หน้าร้านจะหยุดชั่วครู่ ควรทำตอนปิดร้านหรือตอนไม่มีลูกค้า
   - ถ้าอัปเดตพังกลางทาง สคริปต์จะ**ย้อนกลับไปรุ่นเดิมให้เอง** แล้วเปิดร้านต่อได้ ข้อมูลการขายไม่โดนแตะเลย
   - ระบบเก็บรุ่นเก่าไว้ 1 รุ่นเสมอไว้ย้อนกลับ รุ่นที่เก่ากว่านั้นลบออกให้เอง


เมื่อเปิดโปรแกรมหรือรัน `tillumi-migrate.exe` ระบบจะเติมส่วนแบ่งต่อรายการของบิลเก่าให้เองโดยอัตโนมัติ ไม่ต้องทำขั้นตอนเพิ่ม

## กู้คืนข้อมูลจากไฟล์สำรอง

ถ้าเครื่องพังแล้วลงใหม่ หรือต้องการย้อนข้อมูลกลับ ให้ช่างรันสคริปต์กู้คืนแบบผู้ดูแล:

```powershell
restore-native.ps1 -File "C:\ProgramData\TillumiPOS\backups\easypos-วันที่-เวลา.sql.gz" -PgsqlBinDir "C:\Program Files\TillumiPOS\pgsql\bin" -DataDir "C:\ProgramData\TillumiPOS"
```

- คำสั่งนี้**แทนที่ข้อมูลทั้งหมด**ด้วยข้อมูลในไฟล์สำรอง จะถามให้พิมพ์ `YES` ก่อนเสมอ
- ก่อนกู้ควรลองกับเครื่องทดสอบก่อนถ้าทำได้ และตรวจว่ายอดขายกับสต็อกครบหลังกู้

## แก้ปัญหาเบื้องต้น

| อาการ | ทางแก้ |
|---|---|
| เปิดหน้าร้านไม่ติดหลังติดตั้ง | รอสัก 1 นาทีแล้วลองใหม่ ถ้ายังไม่ได้ ให้รีสตาร์ทเครื่อง 1 รอบแล้วลองอีกครั้ง ถ้ายังไม่ได้ให้เรียกช่าง |
| แอปหน้าต่างเปิดไม่ขึ้น หรือขึ้นกล่องผิดพลาด | ให้ช่างเปิดหน้าขายด้วยเบราว์เซอร์ที่ `http://127.0.0.1:3000` แทนได้ทันที (ระบบหน้าร้านเป็นตัวเดียวกัน ข้อมูลเหมือนกัน) แล้วเรียกช่างมาดูแอป |
| ขึ้นว่าพอร์ตถูกใช้อยู่ตอนติดตั้ง | มีโปรแกรมอื่นใช้พอร์ต 3000 หรือ 5435 อยู่ ให้ช่างปิดโปรแกรมนั้นก่อนแล้วติดตั้งใหม่ |
| วินโดวส์เตือน SmartScreen ตอนดับเบิลคลิก | กด `More info` → `Run anyway` (เกิดเพราะยังไม่มีใบรับรองลายเซ็น — ดูหมายเหตุด้านล่าง) |
| iPad / เครื่องอื่นเปิดหน้าขายไม่ได้ | 1) ต้องต่อวายฟายเดียวกับเครื่องหลัก 2) ตอนติดตั้งต้องติ๊กช่อง "ให้เครื่องอื่นในร้านเปิดหน้าขายได้ด้วย" ถ้าลืมติ๊ก ให้ช่างรันไฟล์ติดตั้งซ้ำทับของเดิม (ข้อมูลไม่หาย) แล้วติ๊กช่องนั้น 3) ถ้าเราเตอร์แจก IP ใหม่ให้เครื่องหลัก ที่อยู่จะเปลี่ยน ควรให้ช่างตั้งจอง IP (DHCP reservation) ไว้ |
| ถอนการติดตั้งแล้วกลัวข้อมูลหาย | ตอนถอนจะมีคำถาม "เก็บข้อมูลของร้านไว้หรือไม่" กด **"ใช่"** (แนะนำ) ข้อมูลจะอยู่ครบ ติดตั้งใหม่ทับได้เลย กด "ไม่ใช่" = ลบทั้งหมด กู้ไม่ได้ |
| ตรวจอัปเดตไม่ได้ | ตรวจเน็ตของเครื่องหลักแล้วกดตรวจใหม่ ถ้ายังไม่ได้ให้เรียกช่าง |

## ขอบเขตที่วิธีนี้ยังไม่รองรับ (อ่านก่อนตัดสินใจ)

- **เครื่องพิมพ์ที่ต่อผ่าน USB / Bluetooth:** ยังไม่รองรับ ใช้ได้เฉพาะเครื่องพิมพ์ใบเสร็จที่ต่อผ่าน**สายแลน (LAN)** เท่านั้น (ดู `thermal-printer-setup.md`)
- **เครื่องชิป ARM:** ทดสอบแล้วเฉพาะ x64 ห้ามใช้เครื่อง ARM เป็นเครื่องขายจริง
- **ใบรับรองลายเซ็น (code signing):** ไฟล์ติดตั้งรุ่นนี้ยังไม่มีลายเซ็นดิจิทัล วินโดวส์จึงขึ้นเตือน SmartScreen ทุกครั้งที่ติดตั้ง
  ใบรับรองมีค่าใช้จ่ายรายปี (หลักหมื่นบาท) เจ้าของร้านเป็นคนตัดสินใจซื้อเมื่อพร้อมใช้กับร้านจริง ไม่เกี่ยวกับการทำงานของโปรแกรม
- **อัปเดตเงียบตอนกลางคืน:** รุ่นนี้ต้องกดตรวจและกดโหลดเอง ยังไม่มีแบบอัปเดตให้เองตอนดึก

## สำหรับช่าง (technician notes)

### ตรวจการแก้ไขตัวติดตั้ง (20 ตุลาคม 2026)

- Migration ใช้ `migrate-native.ps1` แทน `cmd /c set ...` เพื่อรักษาพาธที่มีช่องว่าง และคืน environment/working directory หลังรัน
- ติดตั้งทับจะหยุด service ก่อนคัดไฟล์ ใช้ registration เดิม และเก็บ XML เดิมไว้สำหรับกู้คืนเมื่อขั้นตอนติดตั้งล้มเหลว
- อัปเดตที่ล้มก่อนสลับรุ่นจะพยายามเปิดรุ่นเดิมกลับ ตรวจสุขภาพ และล้างโฟลเดอร์รุ่นที่ติดตั้งไม่สำเร็จเพื่อให้ลองใหม่ได้
- Restore ตรวจ archive รูปก่อนเปลี่ยนฐานข้อมูล แตกไว้แยก และเปิด API หลังสลับรูปเสร็จ รูปเดิมเก็บใน `media-before-restore-*` หากคืนรูปหลังฐานข้อมูลสำเร็จไม่ได้ ระบบจะคง API ไว้ในสถานะหยุดเพื่อให้ผู้ดูแลแก้ไข
- การ rollback อัปเดตเป็นการคืนตัวโปรแกรมและ XML ไม่ได้ย้อน schema ฐานข้อมูล ต้องสำรองข้อมูลและใช้ migration ที่เข้ากันได้กับรุ่นก่อนหน้า

ทดสอบ regression บน Windows โดยไม่ติดตั้ง service และไม่แตะข้อมูลร้าน:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installer/tests/regressions.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File installer/tests/native-runners.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File installer/tests/service-account.ps1
```

เพิ่มเติมจาก log ติดตั้งจริงเวลา 06:08 วันที่ 20 ตุลาคม: PostgreSQL ปฏิเสธการเริ่มด้วย LocalSystem (`Execution of PostgreSQL by a user with administrative permissions is not permitted`). ปรับ XML ให้ใช้ LocalService ตาม [WinSW v2.12.0](https://github.com/winsw/winsw/blob/v2.12.0/doc/xmlConfigFile.md#localservice-account) และเพิ่ม `configure-postgres-service.ps1` ซึ่งกำหนดสิทธิ์อ่าน/รันที่โปรแกรม สิทธิ์แก้ไขที่ pgdata/logs และเปลี่ยน registration เดิมก่อนเริ่มฐานข้อมูล การทดสอบจำลองยืนยันกรณีลงครั้งแรก/ลงซ้ำ และการหยุดเมื่อ ACL/SCM/บัญชีที่ตรวจกลับไม่ถูกต้อง ยังไม่ได้ยืนยัน service จริงในรอบแก้นี้ เพราะ shell ของผู้พัฒนาไม่ได้ยกระดับสิทธิ์

ทดสอบแล้ว: ปัญหาเดิมทั้งห้าจุดมี regression checks, พาธที่มีช่องว่าง, migration ล้มแล้วคืน environment, อัปเดตสำเร็จ/ย้อนรุ่น/ไฟล์ไม่ครบ, ลำดับ restore ฐานข้อมูลและรูป รวมถึง archive เสียและแตกไฟล์ไม่สำเร็จ นอกจากนี้ compiled migrator รันกับฐานข้อมูลชั่วคราวได้ และ compiled API ตอบ `/api/v1/setup` กับหน้าเว็บได้ ทดสอบ backup → เปลี่ยนข้อมูล/รูป → restore กับ PostgreSQL จริงใน cluster ชั่วคราวแล้ว ทั้งข้อมูลและรูปกลับมาตรงต้นฉบับ (จำลองการควบคุม service เพื่อไม่แตะ service ของเครื่อง)

ยังต้องทดสอบบน Windows VM ที่ยกระดับสิทธิ์: wizard เต็มขั้นตอน, ติดตั้งซ้ำกับ service จริง, กล่องรหัสตั้งค่า, Task Scheduler, firewall, ถอนติดตั้ง และรีบูต ข้อความข้างต้นไม่ใช่หลักฐานว่ารอบทดสอบเหล่านี้ผ่านแล้ว

ผลตรวจรอบนี้: typecheck/build ผ่าน, web 510 ผ่าน, ชุด update/migrations-folder/repo-secrets 44 ผ่าน และ regression scripts ข้างต้นผ่าน ชุด API เต็มบน Windows กับ PostgreSQL ชั่วคราวผ่าน 1,924 ข้อ แต่ไม่ผ่าน 27 ข้อ (สคริปต์ Unix บน Windows และ Redis integration ที่ไม่ได้เปิด Redis) จึงยังไม่ผ่านเงื่อนไขชุดทดสอบทั้งหมด ห้ามใช้ผลนี้ยืนยันว่า production-ready

### องค์ประกอบ

- **ตัวติดตั้ง:** Inno Setup 6 (สคริปต์ `installer/tillumi.iss`, wizard ภาษาไทย `Thai.isl`)
  ต้องรันด้วยสิทธิ์แอดมิน (`PrivilegesRequired=admin`) ไฟล์ `.exe` ที่บิลด์แล้วออกที่
  `installer/output/` ซึ่งอยู่ใน `.gitignore` **ห้าม commit ไฟล์ติดตั้งลง git**
- **เพย์โหลด:** API ที่ compile แล้ว (`tillumi-pos.exe` + `tillumi-migrate.exe`),
  หน้าเว็บ (`web/` จาก `vite build`), `drizzle/` (migrations), PostgreSQL Windows binaries
  (เฉพาะ `pgsql/bin lib share` ไม่เอา pgAdmin/StackBuilder), WinSW v2 (`WinSW-x64.exe` คัดเป็น 2 ชื่อ)
- **2 Windows services** (รันเป็น LocalSystem, `startmode` Automatic, restart on failure ดีเลย์ 10 วินาที):
  | Service | ทำอะไร | ฟังที่ |
  |---|---|---|
  | `tillumi-postgres` | PostgreSQL เฉพาะข้อมูลร้านนี้ | `127.0.0.1:5435` (ไม่ใช่ 5432/5433/5434 เพื่อไม่ชน DB ของ dev) |
  | `tillumi-pos` | API + เสิร์ฟหน้าเว็บ | `127.0.0.1:3000`, มี `<depend>tillumi-postgres</depend>` (ฐานข้อมูลสตาร์ทก่อนเสมอ) |
- **ผังโฟลเดอร์:**
  - `C:\Program Files\TillumiPOS\app-<รุ่น>\` — โปรแกรมแยกตามรุ่น (ย้าย pointer ตอนอัปเดต)
  - `C:\Program Files\TillumiPOS\pgsql\` — ไบนารี PostgreSQL
  - `C:\Program Files\TillumiPOS\scripts\` — `first-install.ps1`, `backup-native.ps1`, `restore-native.ps1`, `apply-update.ps1`
  - `C:\ProgramData\TillumiPOS\` — **ข้อมูลร้านทั้งหมด** (อัปเดต/ลงทับไม่มีวันแตะ): `.env`, `pgdata\` (cluster),
    `data\media\` (รูปสินค้า), `backups\`, `logs\`, `updates\` (staging อัปเดต + `pending.json`)
- **สิทธิ์โฟลเดอร์ข้อมูล:** `protect-data-dir.ps1` (เรียกจาก `first-install.ps1` ทุกครั้งที่ติดตั้ง/ลงทับ ก่อนเขียน secret)
  ตัดสิทธิ์ที่รับมาจาก ProgramData ออก เหลือแค่ SYSTEM (service หน้าร้าน + งานสำรองตีสอง) และ Administrators
  แล้ว `configure-postgres-service.ps1` เพิ่ม LocalService ให้ `pgdata\` กับ `logs\` เพราะ ProgramData ปกติให้ผู้ใช้ทุกคน
  อ่านได้และสร้างไฟล์ได้ ถ้าไม่ล็อก พนักงานในเครื่องจะอ่าน `.env` ไฟล์สำรอง และรหัสตั้งค่าใน log ได้
- **Secrets:** `.env` เขียนครั้งเดียวตอนติดตั้ง (`first-install.ps1` สุ่ม `JWT_SECRET` 64 ตัวอักษร) รันซ้ำไม่เขียนทับ
  ฐานข้อมูลต้องใช้รหัสผ่าน (scram-sha-256) และรับเฉพาะ loopback (`pg_hba.conf` reject ทุก non-loopback) รหัสผ่านสุ่มตอนติดตั้ง
  เก็บไว้ที่ `DATABASE_URL` ใน `.env` ที่เดียว สคริปต์อื่นอ่านจากตรงนั้น (`shop-database.ps1`) ร้านที่ติดตั้งก่อนหน้านี้
  แบบ trust จะถูกเปลี่ยนเป็นรหัสผ่านตอนลงทับรุ่นใหม่ **ถ้า `.env` หาย รหัสผ่านฐานข้อมูลจะหายด้วย** ให้กู้ `.env` จากสำเนา
  ไฟล์ xml ของ service ห้ามมี secret ใด ๆ (จึงไม่มี `DATABASE_URL` ใน xml)
- **หน้าอัปเดตโปรแกรม:** แสดงเฉพาะการติดตั้งแบบนี้ (service ตั้ง `NATIVE_UPDATES=1`) ร้านที่ติดตั้งด้วย Podman หรือ cloud
  ไม่เห็นหน้านี้ และ API ไม่ไปถาม feed
- **แอปเดสก์ท็อป (Electron):** บิลด์ด้วย `bun run desktop:build` ได้โฟลเดอร์ `apps/desktop/release/win-unpacked/`
  (มี `TillumiPOS.exe`) ส่งให้ตัวติดตั้งด้วย `iscc /DDesktopDir="<path>\win-unpacked" ...` ตัวติดตั้งคัดทั้งโฟลเดอร์ไปที่
  `C:\Program Files\TillumiPOS\desktop\` ไม่ส่ง `/DDesktopDir` = ไฟล์ติดตั้งไม่มีแอป (ส่งโฟลเดอร์ที่ไม่มี `TillumiPOS.exe` คอมไพล์ไม่ผ่าน)
  แอปโหลดเฉพาะ origin ของร้าน (`http://127.0.0.1:3000`) ลิงก์ภายนอกเปิดในเบราว์เซอร์ของเครื่อง และไม่เก็บรหัสลับใด ๆ
  การอัปเดตผ่าน `apply-update.ps1` เปลี่ยนเฉพาะ `app-<รุ่น>\` **ไม่แตะโฟลเดอร์ `desktop\`** แอปเปลี่ยนได้ด้วยการติดตั้ง setup .exe ใหม่ทับเท่านั้น
- **ทางลัด "เปิดหน้าร้าน":** ถ้ามี `{app}\desktop\TillumiPOS.exe` ตอนติดตั้ง (ตรวจตอนรัน ไม่ใช่ตอนคอมไพล์) ทางลัดบนหน้าจอและใน Start menu เปิดแอปนั้น
  ถ้าไม่มี ใช้ทางเดิม: Chrome kiosk (`--kiosk http://127.0.0.1:3000`) ก่อน ถ้าไม่มีใช้ Edge kiosk
  ถ้าไม่มีทั้งคู่เปิด URL ด้วยเบราว์เซอร์เริ่มต้น ใช้ `127.0.0.1` ตรง ๆ ไม่ใช้ `localhost` (บางเครื่องแปลงชื่อแล้วค้าง)
  แต่ละที่ได้ทางลัดเดียวเสมอ (ทางเลือกเบราว์เซอร์ถูกข้ามเมื่อมีแอป) ขั้น "เปิดหน้าร้านเลย" หลังติดตั้งเปิดแอปเมื่อมี มิฉะนั้นเปิดทางลัดเดิม
- **พอร์ตไม่ใช่ 3000:** ทางลัดไม่ส่งอะไรทางบรรทัดคำสั่ง แอปใช้ `http://127.0.0.1:3000` เมื่อไม่ตั้งตัวแปร `TILLUMI_SHOP_URL`
  (พอร์ตในตัวติดตั้ง `PortApi` ตายตัว 3000) ถ้าร้านใช้พอร์ตอื่น ช่างต้องตั้งตัวแปรสภาพแวดล้อม `TILLUMI_SHOP_URL=http://127.0.0.1:<พอร์ต>`
  ให้บัญชีที่เปิดแอปเอง รูปแบบต้องเป็น `http://127.0.0.1:<พอร์ต>` หรือ `http://localhost:<พอร์ต>` เท่านั้น ค่าอื่นแอปไม่ยอมเปิดและขึ้นกล่องแจ้งผิดพลาด
  อย่าใส่รหัสผ่านหรือรหัสลับในตัวแปรนี้
- **งานสำรองข้อมูล:** Task Scheduler ชื่อ `TillumiPOS nightly backup` รัน `backup-native.ps1` ทุกวัน 02:00
  สิทธิ์ SYSTEM ได้ไฟล์ `backups\easypos-<วัน>-<เวลา>.sql.gz` (+ `.media.tar.gz` คู่กันถ้ามีรูป)
  สคริปต์ตรวจความครบของ dump ก่อนเก็บ ไฟล์ไม่ครบทิ้งทันที
- **Firewall (เฉพาะตอนติ๊กช่อง LAN):** กฎขาเข้า `TillumiPOS (TCP 3000)` เปิดเฉพาะโปรไฟล์ Private+Domain
  และเฉพาะ `localsubnet` วายฟายที่มาร์กเป็น Public ยังถูกกันเหมือนเดิม
- **ถอนการติดตั้ง:** หยุด+ลบทั้ง 2 services ลบงาน backup ลบกฎ firewall แล้วถามเก็บ/ลบข้อมูล
  (ค่าเริ่มต้นเก็บ — ปุ่ม "ใช่" = เก็บไว้)

### อัปเดต (owner UI + สคริปต์)

- ตรวจเวอร์ชัน: `GET /api/v1/update/status` (ล็อกอินก็เรียกได้) เทียบ `APP_VERSION`
  (`server/src/domains/update-version.ts`) กับ feed
- โหลดรุ่นใหม่: `POST /api/v1/update/apply` (ต้องสิทธิ์ `settings.write` = เจ้าของร้าน, audit `update.applied`)
  API ตรวจ **ลายเซ็นผู้เผยแพร่** ของรายการใน feed ก่อน แล้วโหลด zip ตรวจ SHA-256 แล้ววางที่
  `<DataDir>\updates\<รุ่น>\` + `pending.json` (มี url กับลายเซ็นติดไปด้วย)
- feed URL ตายตัวในโค้ด (`UPDATE_FEED_URL` ใน `update-feed.adapter.ts` ชี้ `.../releases/latest/download/feed.json`
  ตามแม่แบบ `installer/feed.json`) ต้อง HTTPS เท่านั้น **ห้ามให้ client ส่ง URL มาเอง**
- ติดตั้ง: `apply-update.ps1` แบบยกระดับสิทธิ์ — **ตรวจลายเซ็นเองด้วยกุญแจใน Program Files** (ไม่เชื่อแฮชใน
  `pending.json` เพราะโฟลเดอร์นั้น service เขียนได้) → ตรวจแฮชซ้ำ → หยุด `tillumi-pos` → แตกเป็น `app-<รุ่นใหม่>` →
  รัน `tillumi-migrate.exe` ก่อนสตาร์ทเสมอ → ชี้ `tillumi-pos.xml` ไปรุ่นใหม่ → สตาร์ท → ตรวจสุขภาพ
  `GET /api/v1/setup` (ต้อง 200 = ต่อ DB ที่อัปแล้วได้จริง) → เก็บรุ่นเก่าไว้ 1 รุ่น ลบรุ่นที่เก่ากว่านั้น
  พังขั้นไหน = ชี้ xml กลับรุ่นเดิม + สตาร์ท (rollback) แล้วจบด้วยรหัสผิดพลาดเสมอ
- **ลายเซ็นรุ่นอัปเดต:** ลายเซ็น RSA-3072 (SHA-256, PKCS#1 v1.5) ครอบข้อความ `tillumi-update:v1` + รุ่น + แฮช + url
  (`updateSignedMessage` ใน `server/src/domains/update-release.ts`) จึงสลับรุ่น แฮช หรือ url ไม่ได้ และ url ต้องอยู่ใต้
  `https://github.com/ohmattapon/TillumiPOS/releases/download/` กุญแจสาธารณะอยู่ที่
  `server/src/modules/update/update-public-key.json` ตัวติดตั้งวางไว้ที่ `C:\Program Files\TillumiPOS\update-public-key.json`
  (แก้ได้เฉพาะแอดมิน และไม่เคยมาจากแพ็กเกจอัปเดต) ถ้ายังไม่มีกุญแจ (ค่าว่างใน repo) ทั้ง API และสคริปต์ **ปฏิเสธการอัปเดตทุกครั้ง**
  - ครั้งแรก: `bun scripts/sign-update.ts keygen --out <ที่เก็บกุญแจส่วนตัว.pem>` แล้ว commit ไฟล์กุญแจสาธารณะ และ build setup .exe ใหม่
    **เก็บกุญแจส่วนตัวนอก repo และสำรองไว้** ถ้าหายหรือเปลี่ยนกุญแจ ทุกร้านต้องติดตั้ง setup .exe ใหม่ถึงจะอัปเดตต่อได้
  - ทุกรุ่น: `bun scripts/sign-update.ts sign --key <.pem> --package <zip> --version x.y.z --url <url> --out feed.json`
    แล้วอัปโหลด zip กับ feed.json ที่ได้ไว้ใน GitHub Release
- **กฎเหล็กตอน release:** `APP_VERSION` ใน `server/src/domains/update-version.ts` กับ `AppVersion`
  (`#define` ใน `installer/tillumi.iss`) ต้องเลขเดียวกันทุกครั้ง มีเทสต์อัตโนมัติคุม
  (`update-version.test.ts` หัวข้อ version parity) — ถ้าเทสต์แดงห้าม release
