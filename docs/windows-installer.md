# ตัวติดตั้ง Windows สำหรับร้าน

สถานะ: มีตัวสร้าง EXE และหน้าควบคุมภาษาไทยแล้ว ยังต้องทดสอบบน Windows ใหม่ที่ไม่มี WSL/Podman รวมถึงการรีสตาร์ท UAC และอุปกรณ์อีกเครื่อง ก่อนเผยแพร่ให้ร้านทั่วไป ไฟล์ที่สร้างในเครื่องนักพัฒนายังไม่ได้ลงลายเซ็นผู้เผยแพร่

## สำหรับผู้ใช้ร้าน

1. รับไฟล์ `TillumiPOS-Setup-<รุ่น>.exe` จากผู้ดูแล เปิดตามปกติ ไม่ต้องเลือก Run as administrator
2. กดติดตั้ง แล้วเปิด TillumiPOS จากไอคอนบน Desktop ใช้บัญชี Windows เดิมทุกครั้ง
3. ครั้งแรกต้องต่ออินเทอร์เน็ตเพื่อดาวน์โหลดโปรแกรมที่จำเป็น หากต้องเตรียม WSL ระบบจะขอสิทธิ์ผู้ดูแล และแจ้งให้รีสตาร์ท ให้บันทึกงานก่อนรีสตาร์ท หลังเข้าสู่ Windows ระบบจะทำต่อ
4. เมื่อพร้อมใช้งาน ระบบเปิดเบราว์เซอร์ แสดงรหัสตั้งค่าร้านในหน้าควบคุม สร้างบัญชีเจ้าของร้านด้วยรหัสนั้น ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
5. ต้องการใช้ iPad ให้กด **เชื่อมต่อเครื่องอื่น** ยืนยันว่าต่อเครือข่ายร้านที่ไว้ใจ แล้วอนุญาตสิทธิ์ Windows เปิดที่อยู่ที่แสดง หรือดู QR ในหน้าตั้งค่าร้าน

รองรับ Windows 11 x64 เท่านั้น ต้องเปิด Virtualization ได้ มี App Installer/winget และอินเทอร์เน็ตสำหรับเตรียม WSL/Podman/Compose และฐานข้อมูลครั้งแรก ควรเผื่อพื้นที่อย่างน้อย 10 GB สำหรับเครื่องเสมือน ตัวติดตั้ง และไฟล์สำรอง เครื่องเสมือนของระบบใช้ RAM เริ่มต้นประมาณ 2 GB นอกเหนือจาก Windows

ตัวติดตั้งสร้าง **ร้านใหม่แยกจากระบบที่ติดตั้งด้วยสคริปต์** ถ้าพอร์ต 3000 มีระบบเดิมอยู่ จะหยุดและแจ้งให้ปิดระบบเดิมก่อน ไม่คัดลอกหรือเลือกฐานข้อมูลเดิมเอง การย้ายร้านต้องให้ผู้ดูแลสำรองและกู้คืนข้อมูลตามขั้นตอนด้านล่าง

ตั้งแต่ 0.1.2 ขั้นตอนสร้าง Podman machine จะลองซ้ำให้อัตโนมัติสูงสุด 3 ครั้งเฉพาะเมื่อพบปัญหาเครือข่ายชั่วคราว หากการสร้างรอบก่อนลงทะเบียน machine แล้ว จะอ่านสถานะและเปิดต่อแทนการสร้างซ้ำ ไม่มีการลบ machine เพื่อแก้ข้อผิดพลาดเอง ปัญหาสิทธิ์/พื้นที่/WSL จะไม่ถูกลองซ้ำแบบเดาสาเหตุ บันทึกจะแยก init/start/inspect พร้อม exit code และเหตุผลที่กรองข้อมูลลับแล้ว ผู้ใช้กดลองใหม่จากหน้าควบคุมได้

## การใช้งานประจำวัน

- ระบบเริ่มเมื่อเข้าสู่บัญชี Windows เดิม ไม่ใช่ก่อนเข้าสู่ Windows
- ปิดหน้าควบคุมได้เมื่อเริ่มระบบเสร็จแล้ว ระบบร้านยังทำงานอยู่ ถ้าต้องการหยุดให้กด **หยุดระบบร้าน**
- กด **สำรองข้อมูล** เมื่อหยุดขายชั่วคราว ระบบพักแอประหว่างสำรองฐานข้อมูลและรูปสินค้า แล้วเปิดกลับให้
- **เปิดโฟลเดอร์สำรอง** แล้วคัดลอกสำรองไปเก็บอีกอุปกรณ์หนึ่งด้วย
- ถ้า IP เปลี่ยน ระบบพยายามซ่อมการส่งต่อพอร์ตตอนเปิดร้านบนเครือข่าย Private/Domain ที่เคยยืนยันไว้ อาจมีหน้าต่างขอสิทธิ์ Windows ถ้าเปลี่ยน Wi-Fi ต้องยืนยันเครือข่ายใหม่ด้วยปุ่มเชื่อมต่อเครื่องอื่น
- การตรวจจากเครื่องหลักยืนยันได้ว่าที่อยู่ตอบ แต่ยังยืนยัน Firewall หรือการแยกอุปกรณ์ของเราเตอร์แทน iPad จริงไม่ได้

## อัปเดตและถอนการติดตั้ง

หยุดขายและปิดหน้าควบคุมก่อนเปิด setup รุ่นใหม่ โปรแกรมจะไม่บังคับปิดงานสำรองที่ทำอยู่ ติดตั้งทับที่เดิม แล้วเปิด TillumiPOS ระบบสำรองฐานข้อมูลและรูปสินค้าก่อนเปิดรุ่นใหม่ หากสำรองไม่ได้จะไม่เริ่มอัปเดต

หากรุ่นใหม่เริ่มไม่สำเร็จ ข้อมูลสำรองยังอยู่และระบบไม่กู้คืนหรือเปิดรุ่นเก่าเอง เพราะฐานข้อมูลอาจเปลี่ยนแล้ว ให้ผู้ดูแลตรวจบันทึกก่อนกู้คืน ห้ามเปลี่ยนกลับไปใช้ setup รุ่นเก่าโดยเดาเอง

ถอนการติดตั้งจาก Settings > Apps หลังปิดหน้าควบคุมแล้ว ตัวถอนจะขอหยุดระบบร้านก่อนลบโปรแกรม ถ้าหยุดไม่ได้จะยังไม่ถอน ข้อมูลร้าน `.env` ไฟล์สำรอง Podman machine และ volumes ยังอยู่ โปรแกรม Podman/WSL ที่แชร์กับงานอื่นจะไม่ถูกถอน และกฎเครือข่ายจะไม่ถูกลบเอง

## โครงสร้างสำหรับผู้ดูแล

- โปรแกรม: `%LOCALAPPDATA%\TillumiPOS\program`
- ข้อมูลตั้งค่าและสำรอง: `%LOCALAPPDATA%\TillumiPOS\shop`
- Podman machine: `tillumipos` (rootful), connection `tillumipos-root`
- Compose project: `tillumipos`; ใช้ `shop\docker-compose.yml` และ `.env` ในโฟลเดอร์เดียวกัน
- บันทึก: `shop\launcher.log` มีเฉพาะขั้นตอนและรหัสข้อผิดพลาด ไม่รวมรหัสตั้งค่า รหัสผ่าน หรือ URL ฐานข้อมูล
- ชุดสำรอง: `shop\backups\tillumipos-<วันเวลา>-<รหัส>\shop.sql.gz`, `shop.media.tar.gz`, สำเนา compose/version และสำเนารูปแบบไม่บีบอัดใน `media`
- `docker-compose.previous.yml` คือ compose ก่อนอัปเดตล่าสุดที่เริ่มทำ ไม่ใช่หลักฐานว่าฐานข้อมูลยังเข้ากับรุ่นเก่า

กู้คืนเป็นงานผู้ดูแลที่ต้องได้รับการยืนยันว่าจะเขียนทับทั้งร้าน ต้องสำรองสถานะปัจจุบันอีกชุดและหยุดแอปก่อน ใช้ connection `tillumipos-root` และ compose project `tillumipos` โดยชี้ไปที่ active compose และ `.env` ในโฟลเดอร์ shop อย่างชัดเจน กู้ SQL แบบ transaction เดียวและตรวจรูปสินค้าจากไฟล์คู่กัน ก่อนเปิดแอปและตรวจข้อมูล ห้ามเรียกสคริปต์ restore เดิมโดยปล่อยโฟลเดอร์หรือ project เป็นค่าเริ่มต้น เพราะจะเลือกอีกฐานข้อมูลหนึ่ง ตัวติดตั้งรุ่นนี้มีปุ่มสำรอง แต่ยังไม่มีปุ่มกู้คืนหรือย้ายฐานข้อมูลอัตโนมัติ

สร้างตัวติดตั้ง

ใช้ Inno Setup 6 บน Windows และ app image Linux amd64 แบบ docker-archive ที่มี tag รุ่นเดียวกับ setup:

```powershell
podman build --platform linux/amd64 -t localhost/tillumipos:1.0.0 .
podman save --format docker-archive -o app-image.tar localhost/tillumipos:1.0.0
.\scripts\build-windows-installer.ps1 -Version 1.0.0 -ImageArchive .\app-image.tar -IsccPath 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

ผลอยู่ใน `dist-installer\TillumiPOS-Setup-1.0.0.exe` builder ตรวจ tag/platform ของ archive ก่อนแพ็ก ใช้ allowlist ชัดเจนและบันทึก SHA256 ของ image/compose ไม่คัดลอก checkout ทั้งหมดเข้า installer แต่ app image มี source ของแอปตาม Dockerfile และ LICENSE ที่มากับโปรแกรม รุ่นต้องเป็น x.y.z และห้ามใช้รุ่นเดิมกับเนื้อหา app/compose ที่เปลี่ยนแล้ว

Workflow `Windows installer artifact` เรียกด้วย workflow_dispatch เท่านั้น สร้าง image บน Linux แล้วคอมไพล์ setup บน Windows ดาวน์โหลด EXE จาก artifact ได้ ไม่มีการสร้าง GitHub release หรือ push โค้ดโดย workflow นี้

## ตรวจสอบก่อนเผยแพร่

```powershell
powershell -NoProfile -File installer/windows/runtime.tests.ps1
powershell -NoProfile -File installer/windows/packaging.tests.ps1
```

`smoke.tests.ps1` ใช้ได้เฉพาะ connection `tillumipos-installer-test-root` ที่แยกจากร้านจริง และต้องชี้ ProgramDirectory ไปยัง program ที่ builder แพ็กไว้ มันทดสอบเปิด image จริง สำรอง/เปิดซ้ำและขั้นตอนอัปเดตด้วยแอป build เดิม ไม่ใช่การยืนยัน schema migration ระหว่างคนละรุ่น

ทดสอบเส้นทางสร้างเครื่องเสมือนครั้งแรกจริงด้วย Windows PowerShell 5.1:

```powershell
powershell -NoProfile -File installer/windows/bootstrap.tests.ps1 -ProgramDirectory '<โฟลเดอร์ program ที่ builder แพ็กไว้>'
```

สคริปต์นี้สร้างชื่อ `tillumipos-boot-test-<รหัส>` ที่ยังไม่มีอยู่ ตรวจว่าไม่มี machine นั้นก่อนเริ่ม แล้วเรียก worker ของแพ็กเกจให้สร้าง/เปิด machine เอง โหลด image เปิดฐานข้อมูล/แอป และตรวจ HTTP บนพอร์ต 13073 จากนั้นให้ Stop worker ปิดเฉพาะ machine ทดสอบ ใช้ `-EngineOnly` เมื่อต้องการตรวจเฉพาะ engine ทดสอบนี้ไม่ mock bootstrap และไม่สั่ง machine init/start เตรียมให้ก่อน แต่ยังไม่แทนการทดสอบติดตั้ง WSL/Podman บน Windows ใหม่

ก่อนแจกจริงต้องทดสอบ Windows ใหม่ไม่มี prerequisites, reboot/resume, UAC ที่ใช้บัญชี admin อีกคน, เน็ตหลุด/พื้นที่เต็ม, IP เปลี่ยน, เครื่องอื่นเข้าใช้จริง, อัปเดตจากรุ่นก่อนและกู้คืน, ถอนแล้วติดตั้งใหม่โดยข้อมูลยังอยู่ รวมถึงลงลายเซ็นผู้เผยแพร่ EXE เพื่อให้ผู้ใช้ตรวจแหล่งที่มาได้
