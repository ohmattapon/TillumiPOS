## 1. ภาพรวมและสถานะ branch

ห่วงโซ่ branch (แต่ละอันแตกจากอันก่อนหน้า) และยังไม่มีอันไหนถูก push:

```
main (d721cb3)
 ├─ ohmattpon/tables            งานข้อ 8 โต๊ะ (+ baseline OpenAPI ของโต๊ะ 8da92de)
 ├─ ohmattpon/demo-data         ตัวสร้างข้อมูลตัวอย่าง (db:seed:demo) แตกจาก main
 └─ ohmattpon/install-kit       งานข้อ 14 ชุดติดตั้ง (15 commit)
     └─ ohmattpon/local-image-storage     งานข้อ 13 รูปสินค้าในเครื่อง (8 commit)
         └─ ohmattpon/responsive-layout   ปรับ design รอบที่ 1: หน้าจอทุกขนาด (17 commit)
```

- `main` ยังไม่มีงานชุดนี้ (มีแค่โต๊ะบางส่วน)
- branch เก่าทั้งหมดยังอยู่ ยังไม่ได้ลบ
- `D:\POS` (working tree ของเจ้าของ) ตอนนี้อยู่บน `ohmattpon/sales-reports` และมีงานค้างของเจ้าของที่ยังไม่ commit (`apps/web/src/features/reports/`, `docs/sales-reports.md`, ฯลฯ) ฉันไม่ได้แตะ

### ลำดับ push และ merge ที่แนะนำ (เจ้าของโครงการเป็นผู้ทำ)

```bash
git push -u origin ohmattpon/tables
git push -u origin ohmattpon/demo-data
git push -u origin ohmattpon/install-kit
git push -u origin ohmattpon/local-image-storage
git push -u origin ohmattpon/responsive-layout
```

ลำดับ merge: `tables` → `demo-data` → `install-kit` → `local-image-storage` → `responsive-layout` ถ้า `install-kit` ยังไม่ merge ให้ตั้ง base ของ PR ของ `local-image-storage` และ `responsive-layout` เป็น branch ก่อนหน้า

## 4. ข้อ 13: รูปสินค้าในเครื่อง (`ohmattpon/local-image-storage`)

**เอกสาร:** spec `2026-10-14-local-image-storage-design.md` (`0f85930`), plan `2026-10-14-local-image-storage.md` (`e9fdf5e`) เจ้าของอนุมัติทั้งคู่ และเลือก Native

**การตัดสินใจหลัก**
- เลือกที่เก็บด้วย `MEDIA_STORAGE` = `local` | `worker` | `none` ถ้าไม่ตั้ง: มี `MEDIA_URL` และ `MEDIA_TOKEN` ครบ → `worker` (ร้านเดิมไม่ต้องแก้) ไม่งั้น → `local`
- ไม่แตะ use case หรือสัญญา `/api/v1` ทำเป็น adapter ใหม่หลัง port `IMediaStorage` เดิม
- รูปเสิร์ฟที่ `GET /media/<key>` นอก `/api/v1` ตั้งใจ จึงไม่อยู่ใน OpenAPI baseline
- คีย์รูปต้องตรงรูปแบบ `products/<เลข>/<uuid>.<jpg|png|webp>` ทั้งตอนเขียนและตอนอ่าน (กัน path traversal)
- เขียนไฟล์แบบ atomic (เขียนชั่วคราวแล้ว rename)

### 5.7 การตัดสินใจที่เบี่ยงจากแผนหรือตัดสินเอง (rulings)
1. **ปุ่มยืนยันของฟอร์มยาวยังไม่ติดล่างเสมอ:** `sticky` ใน `<form>` ทำให้ footer ลอยกลาง dialog จึงให้ `DialogFooter` เป็น opt-in (`sticky`) ใช้กับ `OptionsDialog` และ `OrderTools` เท่านั้น ฟอร์มสินค้า/ผู้ใช้/สาขา/โต๊ะ ปุ่มอยู่ท้ายฟอร์มและต้องเลื่อนลงไปกด การทำให้ติดล่างจริงต้องแก้โครงฟอร์มประมาณ 9 ตัว (เป็นงานรอบ 2)
2. **คอลัมน์ `wide-only` ซ่อนต่ำกว่า 1024px** ไม่ใช่ 640px ตามที่สเปกเขียน เพราะตารางแปดคอลัมน์ล้นบนแท็บเล็ต
3. **แถบหมวดสินค้า (`SegmentedTabs` แบบ touch)** สูงขึ้น 8px ทุกขนาดจอที่ใช้ตัวนี้ (ให้ปุ่มย่อยสูง 44px)
4. **ใช้ key ใหม่ `list.openReceipt`** ให้ชื่อที่เข้าถึงได้ของแถวบิลบนมือถือ

### 5.8 ความเสี่ยงที่ยังเปิด
- **e2e ภาษาอังกฤษล้มเป็นช่วง** (2 ใน 4 รอบ ก่อนแก้) หลังจากลำดับการทดสอบเปลี่ยน สาเหตุ: เพิ่มการนำทางในบริบทเดียวกันจนเบราว์เซอร์หมดซ็อกเก็ต (`ERR_INSUFFICIENT_RESOURCES`) และไม่มีการรอ network idle ก่อน assert การแก้: แยกบริบทของ layout check และรอ network idle หลังทุกการนำทาง ผ่าน 3 รอบติดกัน แต่ไม่ได้พิสูจน์รากเหตุของการ timing ทั้งหมด ถ้าเห็นอีกให้เปิดดู
- **ทดสอบบนเบราว์เซอร์จำลองเท่านั้น** ยังไม่มีการทดสอบบนมือถือ/แท็บเล็ตจริง
