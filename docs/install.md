# คู่มือติดตั้ง TillumiPOS สำหรับร้านค้า (Windows)

คู่มือนี้ติดตั้ง TillumiPOS ด้วย **Podman** บนเครื่อง Windows ของร้าน ด้วยคำสั่งเดียว ข้อมูลทั้งหมดอยู่ในเครื่องของคุณเอง

> **แพลตฟอร์มที่ทดสอบแล้ว:** Windows เท่านั้น เครื่อง Mac มีสคริปต์ให้ (ดู [ติดตั้งบน Mac](#ติดตั้งบน-mac)) แต่ยังไม่ได้ลองบนเครื่อง Mac จริง Linux ยังไม่ได้ทดสอบ ไม่ต้องใช้ Docker อีกแล้ว ถ้าร้านเคยใช้ Docker ให้ดูหัวข้อ [ย้ายจาก Docker](#ย้ายจาก-docker)

## สิ่งที่ต้องมี

- **Windows 11** ที่เปิด WSL2 ได้ (ทดสอบแล้วบน Windows 11 Home) สคริปต์ใช้ WSL2 เป็นเครื่องเสมือนของ Podman Windows 10 ยังไม่ได้ทดสอบ
- **Podman** เวอร์ชัน 5.8.3 ขึ้นไป สคริปต์จะติดตั้งให้ด้วย winget (`RedHat.Podman`) ถ้ายังไม่มี หรือดาวน์โหลดเองได้จาก https://podman.io/getting-started/installation
- **Docker Compose** แบบ standalone เวอร์ชัน 5.6.0 ขึ้นไป สคริปต์จะติดตั้งให้ด้วย winget (`Docker.DockerCompose`) ถ้ายังไม่มี
  - ไม่ต้องติดตั้ง Docker Desktop และสคริปต์ไม่ใช้ Docker Desktop
- เน็ตตอนติดตั้งครั้งแรก เพราะต้องดาวน์โหลดอิมเมจเครื่องเสมือนประมาณ 1 GB และ image ของระบบ
- พื้นที่ว่างอย่างน้อย 2 GB และ RAM อย่างน้อย 2 GB (ค่าเริ่มต้นของเครื่องเสมือนที่สคริปต์สร้าง)
- ถ้าต้องการใช้ผ่านอินเทอร์เน็ตด้วย HTTPS: โดเมนที่ชี้มาที่เครื่องนี้ และพอร์ต 80 กับ 443 ที่เข้าถึงได้ `[ยืนยันก่อนใช้]` การออกใบรับรองจริงยังไม่ได้ทดสอบ

โฟลเดอร์ที่ติดตั้งโปรแกรมอยู่ที่ไหนก็ได้บนไดรฟ์ (ทดสอบแล้วจาก `D:\`) แต่ไม่ควรอยู่ในไดรฟ์ที่ Windows ไม่แชร์กับ WSL

## ติดตั้ง

ดาวน์โหลดหรือ clone โปรเจกต์ แล้วเปิด PowerShell ในโฟลเดอร์หลักของโปรเจกต์:

```powershell
.\scripts\install.ps1
```

สคริปต์จะ

1. ตรวจและติดตั้ง Podman และ Docker Compose ถ้ายังไม่มี
2. สร้างและเปิดเครื่องเสมือนของ Podman (ครั้งแรกใช้เวลาหลายนาที) ตั้งเป็นโหมด rootful เพื่อให้เปิดพอร์ต 80 และ 443 ได้
3. สร้างไฟล์ `.env` พร้อมรหัสลับที่สุ่มให้ (เก็บไฟล์นี้เป็นความลับ ห้ามส่งให้ใคร)
4. สร้างและเริ่มระบบด้วย `podman compose` (ครั้งแรกใช้เวลาหลายนาที)
5. พิมพ์ที่อยู่เว็บและ **รหัสตั้งค่า** ให้ พร้อมที่อยู่สำหรับ iPad และเครื่องอื่นในร้าน (ดู "เชื่อมต่อเครื่องอื่น")

ถ้ามีไฟล์ `.env` อยู่แล้ว สคริปต์จะเก็บไว้และไม่เขียนทับ

## ติดตั้งบน Mac

`[ยังไม่ได้ทดสอบบนเครื่อง Mac จริง]` สคริปต์เขียนและทดสอบตรรกะด้วยตัวจำลองแล้ว แต่ยังไม่เคยรันบน macOS จริง ถ้าติดขัดที่ขั้นไหน แจ้งผู้พัฒนาพร้อมข้อความที่สคริปต์พิมพ์

ต้องมี [Homebrew](https://brew.sh) ก่อน เปิด Terminal ในโฟลเดอร์หลักของโปรเจกต์แล้วรัน

```bash
scripts/install.sh
```

สคริปต์จะติดตั้ง Podman และ Docker Compose ผ่าน Homebrew ถ้ายังไม่มี สร้างเครื่องเสมือนของ Podman (ครั้งแรกดาวน์โหลดประมาณ 1 GB) ตั้งเป็น rootful แล้วเปิดให้ จากนั้นทำเหมือน Windows: สร้าง `.env` สร้างและเริ่มระบบ พิมพ์ที่อยู่เว็บ ที่อยู่สำหรับเครื่องอื่นในร้าน และรหัสตั้งค่า บน Mac ไม่ต้องใช้ `sudo` และไม่ต้องใส่รหัสผ่านของเครื่อง

สำรองและกู้คืนใช้ `scripts/backup.sh` และ `scripts/restore.sh <ไฟล์>` เหมือนกัน หลังรีสตาร์ทเครื่อง Mac ให้รัน `podman machine start` หรือรัน `scripts/install.sh` อีกครั้ง (ไม่เขียนทับ `.env`) เพื่อเปิดเครื่องเสมือนของ Podman

## ตั้งค่าร้านครั้งแรก

1. เปิดที่อยู่ที่สคริปต์พิมพ์ (ปกติ `http://localhost:3000`)
2. กรอก **รหัสตั้งค่า** ที่สคริปต์พิมพ์ให้ (ตัวอักษรอังกฤษกับตัวเลข ต้องสลับแป้นพิมพ์เป็นภาษาอังกฤษก่อน) ชื่อร้าน ประเภทร้าน และบัญชีเจ้าของ (รหัสผ่านอย่างน้อย 10 ตัวอักษร) ร้านมีสาขาเดียว ระบบใช้ชื่อร้านเป็นชื่อสาขา ถ้าเลือก **คาเฟ่** ระบบสร้างกลุ่มตัวเลือก "ความหวาน" (หวานปกติ หวานน้อย หวานมาก ไม่ใส่น้ำตาล) และ "ท็อปปิ้ง" (วิปครีม ช็อตเอสเพรสโซ่เพิ่ม ไซรัปคาราเมล) ให้ทันที นำไปผูกกับเครื่องดื่มได้ที่หน้าสินค้า หรือกด "เมนูคาเฟ่" เพื่อเพิ่มเครื่องดื่มที่ผูกกลุ่มเหล่านี้ไว้แล้ว ร้านประเภทอื่นไม่มีกลุ่มตัวเลือกเริ่มต้น
3. (ไม่บังคับ) กรอก **พร้อมเพย์สำหรับรับเงิน** เป็นเบอร์มือถือ 10 หลักหรือเลขบัตร 13 หลัก ระบบจะตั้งให้รับพร้อมเพย์ด้วย QR แบบ static ที่ใส่ยอดบิลให้ ลูกค้าสแกนจ่ายเข้าบัญชีนี้ ถ้าเว้นไว้ ตั้งทีหลังได้ในหน้า "ตั้งค่าร้าน" (ระบบรับเฉพาะเบอร์พร้อมเพย์หรือเลขบัตร ไม่รับเลขบัญชีธนาคารตรงๆ ให้ผูกพร้อมเพย์กับบัญชีที่ธนาคารก่อน)
4. กด "ตั้งค่าและเข้าสู่ระบบ" ระบบจะพาเข้าหน้าขาย

QR แบบ static ระบบไม่รู้ว่าเงินเข้าแล้วหรือยัง แคชเชียร์ต้องดูยอดในแอปธนาคารแล้วกดยืนยันการชำระเอง และควรเทียบยอดพร้อมเพย์ในรายงานกับ statement ธนาคารตอนปิดวัน

ถ้าลืมรหัสตั้งค่า (ก่อนตั้งค่าเสร็จ) ดูรหัสได้จาก log หรือรีสตาร์ทเพื่อรับรหัสใหม่:

```powershell
podman compose logs app
podman compose restart app
```

รหัสตั้งค่าใช้ได้ครั้งเดียว กรอกผิด 5 ครั้งจะถูกล็อก 15 นาที หลังตั้งค่าเสร็จหน้านี้ใช้อีกไม่ได้

## เชื่อมต่อเครื่องอื่น (iPad มือถือ เครื่องขายเครื่องที่สอง)

เครื่องหลักที่ติดตั้งเป็นตัวเก็บข้อมูลทั้งร้าน เครื่องอื่นไม่ต้องติดตั้งอะไร เปิดผ่านเบราว์เซอร์ได้เลย ขอแค่ต่อ Wi-Fi หรือสายแลนเดียวกับเครื่องหลัก

1. ตอนติดตั้งเสร็จ สคริปต์จะพิมพ์บรรทัด `Other devices on the same Wi-Fi (iPad, phone): http://192.168.x.x:3000` ให้ ที่อยู่นี้คือที่อยู่ที่เครื่องอื่นพิมพ์ใน Safari หรือ Chrome
2. ถ้าหาบรรทัดนั้นไม่เจอ เปิดระบบในเครื่องหลัก ไปที่ "ตั้งค่าร้าน" เลื่อนลงไปที่ "เชื่อมต่อ iPad และเครื่องอื่น" กรอก IP ของเครื่องหลักแล้วระบบจะสร้าง QR ให้สแกน (ดู IP ได้จาก `ipconfig` บน Windows หรือการตั้งค่าเครือข่ายบน Mac)
3. ที่อยู่เป็นเลข IP ของเครื่องหลักในเครือข่ายร้าน ถ้าเราเตอร์แจก IP ใหม่ให้เครื่องหลัก (เช่น หลังไฟดับ) ที่อยู่จะเปลี่ยน ควรตั้งให้เราเตอร์จอง IP ให้เครื่องหลัก (DHCP reservation) ไว้

สคริปต์ลองเรียกระบบผ่านที่อยู่นี้เองหนึ่งครั้ง ถ้าขึ้นคำเตือนว่าระบบไม่ตอบ แปลว่าระบบรับเฉพาะในเครื่องหลัก สคริปต์ตรวจไม่ได้ว่า firewall ของเครื่องหลักกันเครื่องอื่นอยู่หรือไม่ ถ้าเครื่องอื่นเปิดไม่ได้ทั้งที่ไม่มีคำเตือน ให้ตรวจดังนี้

- **Windows**: สคริปต์เปิด firewall พอร์ตของระบบให้เฉพาะเครือข่ายแบบ Private และ Domain เมื่อรันด้วยสิทธิ์ผู้ดูแล (Run as administrator) ถ้าไม่ได้รันด้วยสิทธิ์นั้น สคริปต์จะพิมพ์คำสั่ง `New-NetFirewallRule` ให้ไปรันเอง และถ้า Wi-Fi ร้านถูกตั้งเป็น Public ให้เปลี่ยนเป็น Private ในการตั้งค่า Wi-Fi
- **Mac**: ถ้าเปิด Firewall ไว้ ให้ตรวจที่ System Settings → Network → Firewall ว่าอนุญาตการเชื่อมต่อขาเข้าของ Podman

Podman อาจเปิดพอร์ตให้เฉพาะในเครื่องหลักเอง บน Windows ทดสอบแล้วว่าระบบตอบผ่านที่อยู่ LAN ของเครื่องหลักได้ ส่วน Mac ยังไม่ได้ทดสอบบนเครื่องจริง ถ้าเจอคำเตือนว่าระบบไม่ตอบ ให้แจ้งผู้พัฒนาพร้อมข้อความที่สคริปต์พิมพ์

บน iPad เปิดที่อยู่ใน Safari แล้วกดปุ่มแชร์ → เพิ่มลงในหน้าจอโฮม จะได้ไอคอน TillumiPOS ที่เปิดเต็มจอเหมือนแอป

## ใช้ผ่านอินเทอร์เน็ตด้วย HTTPS

```powershell
.\scripts\install.ps1 -Domain pos.ร้านของคุณ.com
```

ระบบจะขอและต่ออายุใบรับรองให้เอง ถ้าติดตั้งไปแล้ว ให้ใส่ `DOMAIN=` และ `COOKIE_SECURE=true` ใน `.env` แล้วรัน `podman compose --profile https up -d` `[ยืนยันก่อนใช้]`

## สำรองข้อมูล

```powershell
.\scripts\backup.ps1
```

ได้ไฟล์ `backups\easypos-วันที่-เวลา.sql.gz` **เก็บสำเนาไว้นอกเครื่องนี้ด้วย** เช่นดิสก์อีกลูกหรือ cloud drive

สคริปต์ตรวจก่อนว่าไฟล์ที่ได้ครบทั้งไฟล์ (บรรทัดปิดท้ายของ pg_dump) ถ้าดิสก์เต็มหรือการเชื่อมต่อหลุดกลางทาง จะแจ้งว่าสำรองไม่สำเร็จและไม่เก็บไฟล์ที่ไม่ครบไว้ ไฟล์แบบนั้นดูเหมือนปกติ แต่ถ้ากู้คืนจะทำให้ข้อมูลหายหมด สคริปต์ยังไม่ลบไฟล์สำรองเก่าให้ ถ้าสำรองทุกคืน ควรลบไฟล์เก่าเองเป็นระยะ

ควรตั้งให้สำรองทุกคืนด้วย Task Scheduler ให้เรียก `backup.ps1` (ทดสอบแล้ว: งานที่ตั้งให้รันเองสร้างไฟล์สำรองทั้งสองไฟล์ได้) ให้เครื่องเสมือนของ Podman เปิดอยู่ตอนที่งานทำงาน และห้ามเปิด Docker Desktop พร้อมกันเพราะชนกันดังที่อธิบายด้านล่าง

ถ้าเก็บรูปสินค้าในเครื่อง (ค่าเริ่มต้น) สคริปต์จะสำรองรูปเป็นไฟล์ที่สองชื่อเดียวกัน `backups\easypos-วันที่-เวลา.media.tar.gz` เก็บและคัดลอกคู่กับไฟล์ `.sql.gz` ตอนกู้คืนให้ระบุไฟล์ `.sql.gz` ระบบจะกู้รูปจากไฟล์คู่ให้เองถ้ามี ส่วนรูปที่เก็บบน Cloudflare R2 ไม่อยู่ในไฟล์สำรองนี้

## กู้คืนข้อมูล

```powershell
.\scripts\restore.ps1 backups\easypos-20261014-210000.sql.gz
```

**คำสั่งนี้แทนที่ข้อมูลทั้งหมด** จะถามให้พิมพ์ `YES` ก่อน (ใส่ `-Yes` เพื่อข้ามคำถามเมื่อรันเอง)

ก่อนแตะข้อมูล สคริปต์ตรวจว่าไฟล์ครบ ถ้าไม่ครบ (เสียหรือถูกตัด) จะปฏิเสธโดยไม่เปลี่ยนอะไร และการกู้คืนทำในธุรกรรมเดียว ถ้ามีคำสั่งไหนในไฟล์ล้มเหลว ฐานข้อมูลจะกลับไปเป็นเหมือนเดิมทั้งหมดและเปิดแอปให้ใช้ต่อ (ไม่เหลือข้อมูลครึ่งๆ กลางๆ)

**ควรลองกู้คืนอย่างน้อยหนึ่งครั้งก่อนใช้จริง** บนเครื่องอื่นหรือเครื่องทดสอบ ด้วยไฟล์สำรองจริงของร้าน แล้วเปิดดูว่ายอดขายและสต็อกครบ ไฟล์สำรองที่ไม่เคยลองกู้คืนยังพิสูจน์ไม่ได้ว่าใช้ได้ ไฟล์สำรองจากเวอร์ชันเก่ากู้คืนได้ ระบบจะปรับโครงสร้างฐานข้อมูลให้เองตอนเปิดแอป

## อัปเดตเวอร์ชัน

```powershell
.\scripts\backup.ps1
git pull
podman compose up -d --build
```

ระบบปรับโครงสร้างฐานข้อมูลให้เองตอนเริ่ม

## ตั้งค่าเพิ่มเติม (ไฟล์ `.env`)

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `PORT` | พอร์ตของเว็บ (ค่าเริ่มต้น 3000) ถ้าพอร์ตนั้นถูกโปรแกรมอื่นใช้อยู่ ให้เปลี่ยนเลข |
| `DOMAIN`, `COOKIE_SECURE` | เปิด HTTPS (ดูหัวข้อด้านบน) |
| `MEDIA_STORAGE` | ที่เก็บรูปสินค้า: `local` เก็บในเครื่อง (ค่าเริ่มต้นเมื่อไม่ได้ตั้ง `MEDIA_URL` และ `MEDIA_TOKEN` ครบ), `worker` ใช้ Cloudflare R2 ผ่าน Worker ของ `workers/media` (ค่าเริ่มต้นเมื่อตั้งสองตัวนั้นครบ), `none` ไม่ใช้รูป เปลี่ยนที่เก็บแล้วต้องอัปโหลดรูปใหม่ (รูปเดิมไม่ถูกย้าย) |
| `MEDIA_URL`, `MEDIA_TOKEN` | ใช้เมื่อเลือก `worker` |
| `MEDIA_DIR` | โฟลเดอร์เก็บรูปเมื่อรันนอก container (ใน container คือ volume `pos-media` ไม่ต้องตั้ง) |
| `SCB_API_KEY`, `SCB_API_SECRET`, `SCB_BILLER_ID`, `SCB_REF3_PREFIX` | เปิดการชำระ QR ของ SCB ตั้งค่าและทดสอบกับธนาคารก่อนใช้จริง |
| `SCB_API_BASE_URL` | ที่อยู่ API ของ SCB ค่าเริ่มต้นเป็น sandbox: ตอนใช้จริงต้องเปลี่ยนเป็นที่อยู่ production ที่ SCB ให้มาพร้อมกุญแจ |

แก้ `.env` แล้วรัน `podman compose up -d` เพื่อให้มีผล

## แก้ปัญหา

| อาการ | ทางแก้ |
|---|---|
| เปิดเว็บไม่ได้ | `podman compose ps` ดูว่า `app` และ `db` ทำงานอยู่ และ `podman compose logs app` ดูข้อความผิดพลาด |
| พอร์ต 3000 ถูกใช้อยู่ | ตั้ง `PORT=` ใน `.env` เป็นเลขอื่นแล้วรัน `podman compose up -d` |
| ไม่เห็นรหัสตั้งค่า | `podman compose logs app` แล้วหา `SETUP CODE` หรือ `podman compose restart app` |
| คำสั่ง `podman` บอกว่าเชื่อมต่อ machine ไม่ได้ | `podman machine start` แล้วลองใหม่ |
| ต้องการเริ่มใหม่หมด (ลบข้อมูลทั้งหมด) | `podman compose down -v` แล้วลบ `.env` แล้วรันติดตั้งใหม่ ข้อมูลทั้งหมดจะหายถาวร |

## ย้ายจาก Docker

ใช้ตอนร้านเคยรันด้วย Docker และต้องการย้ายข้อมูลมา Podman ไม่ต้องเริ่มตั้งค่าร้านใหม่ ข้อมูลการขาย สต็อก ผู้ใช้ และรูปสินค้าจะติดไปด้วย ขั้นตอนนี้ทดสอบแล้วบน Windows: สำรองจากโค้ดเวอร์ชัน Docker (`b847f97`) ติดตั้ง Podman ใหม่ทั้งชุด แล้วกู้คืน ข้อมูล canary และรูปที่กู้คืนได้ตรงกับต้นฉบับทุกไบต์

1. **สำรองด้วยสคริปต์เวอร์ชัน Docker** เช็กเอาต์คอมมิตสุดท้ายที่ยังใช้ Docker แล้วรัน `scripts\backup.ps1` ได้ไฟล์ `.sql.gz` และ `.media.tar.gz` คู่กัน จดชื่อคอมมิตนี้ไว้
2. **หยุดระบบ Docker** ด้วย `docker compose down` **ห้ามใช้ `-v`** เพราะจะลบ volume ของข้อมูลและรูป
3. **ปิด Docker Desktop ทั้งหมด** ก่อนเปิด Podman machine เพราะ Podman จองชื่อ pipe `docker_engine` ตอนเริ่มทำงาน ถ้า Docker Desktop ยังเปิดอยู่ Docker จะเปิดไม่ได้ (ทดสอบแล้ว: ปิด Podman แล้ว Docker เปิดได้ทันที)
4. **ติดตั้ง Podman** ตามหัวข้อ "ติดตั้ง" ข้างต้น (ตั้ง `PORT` ใน `.env` ให้ไม่ชนกับโปรแกรมอื่น)
5. **ใช้โค้ดที่มี migration ชุดเดียวกับตอนสำรอง** ตรวจก่อนด้วย `git diff <คอมมิตที่สำรอง> <คอมมิตที่จะติดตั้ง> -- drizzle` ต้องไม่มีผลลัพธ์ ถ้ามีต้องใช้คอมมิตที่ migration ตรงกัน ไม่งั้นการกู้คืนอาจล้มเหลว
6. **กู้คืน** ด้วย `.\scripts\restore.ps1 backups\<ไฟล์>.sql.gz` แล้วพิมพ์ `YES`
7. **ตรวจ** เข้าสู่ระบบ ดูยอดขายย้อนหลัง และตรวจว่ารูปสินค้าแสดงได้
8. **เก็บ Docker ไว้จนกว่าจะมั่นใจ** เมื่อยืนยันแล้ว จึงลบ container และ volume ของ Docker ได้ แต่ต้องเก็บไฟล์สำรองไว้เสมอ
